ଗାର୍ଡରେଲ୍ସଗୁଡ଼ିକ OmniRoute ଏବଂ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରୋଭାଇଡର୍ମାନଙ୍କ ମଧ୍ୟରେ ସୀମାରେ ସୁରକ୍ଷା, ନୀତି ଏବଂ କଣ୍ଟେଣ୍ଟ୍ ପରିବର୍ତ୍ତନଗୁଡ଼ିକୁ କାର୍ଯ୍ୟକାରୀ କରେ। ପ୍ରତ୍ୟେକ ଗାର୍ଡରେଲ୍ ଅନୁରୋଧ ପେଲୋଡ୍ (`preCall`) ଏବଂ ଅପଷ୍ଟ୍ରିମ୍ ରେସ୍ପନ୍ସ (`postCall`) କୁ ଯାଞ୍ଚ (ଏବଂ ଇଚ୍ଛାଧୀନ ଭାବରେ ପ୍ରତ୍ୟାଖ୍ୟାନ, ପରିବର୍ତ୍ତନ, ବା ଆନୋଟେଟ୍) କରିପାରିବ।

ସିଷ୍ଟମ୍ ହେଉଛି **ଫେଲ୍-ଓପନ୍**: ଯଦି ଏକ ଗାର୍ଡରେଲ୍ ଏକଜିକିଉଟ୍ ହେବା ସମୟରେ ତ୍ରୁଟି ସୃଷ୍ଟି କରେ, ତେବେ ରେଜିଷ୍ଟ୍ରି ଏହି ତ୍ରୁଟିକୁ ରେକର୍ଡ କରେ ଏବଂ ଅନୁରୋଧକୁ ବିଫଳ ନକରି ପରବର୍ତ୍ତୀ ଗାର୍ଡରେଲ୍ ସହିତ ଜାରି ରଖେ। ବ୍ଲକ୍ କରିବା ହେଉଛି ଏକ ସ୍ପଷ୍ଟ ନିଷ୍ପତ୍ତି (`block: true`), କୌଣସି ଦୁର୍ଘଟଣା ନୁହେଁ। ଏହାର ଏକମାତ୍ର ବ୍ୟତିକ୍ରମ ହେଉଛି ଏକ ବାତିଲ ହୋଇଥିବା ଅନୁରୋଧ: ଯେତେବେଳେ କଲର୍ସର `signal` ବାତିଲ ହୁଏ, ସେତେବେଳେ ଏକ ତ୍ରୁଟିପୂର୍ଣ୍ଣ ଗାର୍ଡରେଲ୍ ହୁକ୍ ରନ୍ କୁ ଏଡ଼ାଇବା ପରିବର୍ତ୍ତେ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ।

ହୁକ୍ଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ ରୁଟ୍ କିମ୍ବା ପ୍ରତ୍ୟେକ ରେସ୍ପନ୍ସରେ ଚାଲେ **ନାହିଁ**। ଏକ ସୁରକ୍ଷା ନିୟନ୍ତ୍ରଣ ଭାବରେ ଗାର୍ଡରେଲ୍ ଉପରେ ନିର୍ଭର କରିବା ପୂର୍ବରୁ [Coverage and limits](#coverage-and-limits) ପଢ଼ନ୍ତୁ।

### ଭିଜନ ବ୍ରିଜ୍ (`visionBridge.ts`) — ମୋଡାଲିଟି ବ୍ରିଜ୍ PR-1

GLM 5.3 ବେସ୍ ମଡେଲ୍ ଏବଂ `glm-5.3-{low,high,max}` ର ସ୍ପଷ୍ଟ `supportsVision:false` ରେଜିଷ୍ଟ୍ରି/ସ୍ପେକ୍ ମେଟାଡାଟା ଅଛି। GLM 5.3 Flash ଭାରିଏଣ୍ଟଗୁଡ଼ିକ ନେଟିଭ୍-ଭିଜନ ମଡେଲ୍ ଭାବରେ ରହିଥାଏ। Claude Code ର `/v1/messages` ରୁଟ୍ Claude-to-OpenAI ଅନୁବାଦ **ପୂର୍ବରୁ** ସେୟାର୍ ହୋଇଥିବା `handleChat` ପ୍ରି-କଲ୍ ଗାର୍ଡରେଲ୍ ଚେନ୍ରେ ପ୍ରବେଶ କରେ; ନେଷ୍ଟେଡ୍ `Read` ଟୁଲ୍-ଫଳାଫଳ ଛବିଗୁଡ଼ିକୁ ସେହି ଅନୁବାଦ ସେଗୁଡ଼ିକୁ OpenAI `image_url` କଣ୍ଟେଣ୍ଟ୍ (#17069) କୁ ନେବା ପୂର୍ବରୁ ବର୍ଣ୍ଣନା କରାଯିବା କିମ୍ବା ପରିଚାଳନା କରାଯିବା ଆବଶ୍ୟକ।

**ନନ-ଭିଜନ ମଡେଲ୍ଗୁଡ଼ିକ** କୁ ଲକ୍ଷ୍ୟ କରି କରାଯାଇଥିବା ଛବି-ଯୁକ୍ତ ଅନୁରୋଧଗୁଡ଼ିକୁ ଇଣ୍ଟରସେପ୍ଟ କରେ ଏବଂ ସମଗ୍ର ଅନୁରୋଧକୁ ଏକ ଭିଜନ-ସକ୍ଷମ ମଡେଲ୍ କୁ ପୁନଃପଥ କରେ (reroutes) କିମ୍ବା ଅପଷ୍ଟ୍ରିମ୍ କଲ୍ ପୂର୍ବରୁ ଏକ ବିନ୍ୟାସଯୋଗ୍ୟ ଭିଜନ ମଡେଲ୍ ଦ୍ୱାରା ପ୍ରସ୍ତୁତ ଟେକ୍ସଟ୍ ବର୍ଣ୍ଣନା ସହିତ ଛବି ଅଂଶଗୁଡ଼ିକୁ ବଦଳାଇଥାଏ। ଏହା କେବଳ-ଟେକ୍ସଟ୍ ପ୍ରୋଭାଇଡର୍ମାନଙ୍କୁ ସ୍ୱଚ୍ଛ ଭାବରେ ମଲ୍ଟିମୋଡାଲ୍ ପେଲୋଡ୍ ପରିଚାଳନା କରିବାକୁ ଦେଇଥାଏ।

ପ୍ରବାହ (Flow):

1. ଯଦି ଟାର୍ଗେଟ୍ ମଡେଲ୍ ପୂର୍ବରୁ ଭିଜନକୁ ସମର୍ଥନ କରେ ତେବେ ଏହାକୁ ଏଡ଼ାଇ ଯାଆନ୍ତୁ (ଯଦି ନା ଏହା ଫୋର୍ସଡ୍-ବ୍ରିଜ୍ ତାଲିକା `isVisionBridgeForcedModel` ରେ ଦୃଶ୍ମାନ ହୁଏ)।
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) ମାଧ୍ୟମରେ ଛବି ଅଂଶଗୁଡ଼ିକୁ ଏକ୍ସଟ୍ରାକ୍ଟ କରନ୍ତୁ, ଯାହା `open-sse/utils/mediaParts.ts` ରେ ଥିବା **ୟୁନିଫାଇଡ୍ ମିଡିଆ ଡିଟେକ୍ଟର୍** `detectMediaParts()` କୁ ଡେଲିଗେଟ୍ କରେ — ଏହା କମ୍ବୋ କମ୍ପାଟିବିଲିଟି ଫିଲ୍ଟର୍ ସହିତ ସେୟାର୍ ହୋଇଥିବା ଏକମାତ୍ର ସତ୍ୟର ଉତ୍ସ। ଏକ୍ସଟ୍ରାକ୍ସନ୍ କେବଳ ସେହି ଆକୃତିଗୁଡ଼ିକ ପାଇଁ ଆଲୋଲିଷ୍ଟ୍ ହୋଇଛି ଯାହାକୁ `replaceImageParts` ପୁନର୍ବାର ସ୍ପ୍ଲାଇସ୍ କରିପାରିବ (extract↔replace ଚୁକ୍ତି): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, ଏବଂ Responses API `input_image`। Claude Code `tool_result.content` ଏବଂ Responses ଟୁଲ୍ ଆଉଟପୁଟ୍ ଭିତରେ ନେଷ୍ଟ ହୋଇଥିବା ମେଚିଂ ଛବିଗୁଡ଼ିକୁ ମଧ୍ୟ ଏକ୍ସଟ୍ରାକ୍ଟ କରାଯାଏ ଏବଂ ସେମାନଙ୍କର ପ୍ରକୃତ ପାଥ୍ରେ ପ୍ରତିସ୍ଥାପିତ କରାଯାଏ; ଇଣ୍ଡିକେଟର୍-ମାତ୍ର ଆକୃତିଗୁଡ଼ିକ କମ୍ବୋ-ଫିଲ୍ଟର୍ ସାମଗ୍ରୀ ଏବଂ ଏକ୍ସଟ୍ରାକ୍ଟ କରାଯାଏ ନାହିଁ। ଯଦି କିଛି ମିଳେ ନାହିଁ ତେବେ ଏଡ଼ାଇ ଯାଆନ୍ତୁ।
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) ମାଧ୍ୟମରେ ରନ୍ଟାଇମ୍ କନଫିଗ୍ ସମାଧାନ କରନ୍ତୁ: ନୂତନ `modalityBridge*` ସେଟିଂସ୍ କି'ଗୁଡ଼ିକ ଜିତେ; ଲେଗାସି `visionBridge*` କି'ଗୁଡ଼ିକ ଏକ **ଓନ୍-ସାଇକଲ୍ ଫଲବ୍ୟାକ୍** (ରୋଲବ୍ୟାକ୍ ୱିଣ୍ଡୋ) ଭାବରେ ରହିଥାଏ। ବ୍ରିଜ୍ ଡିସେବଲ୍ ହୋଇଥିବାବେଳେ ଯେକୌଣସି ମିଡିଆ ଟ୍ରାଭର୍ସାଲ୍ ପୂର୍ବରୁ ଏହାକୁ ଏଡ଼ାଇ ଯାଆନ୍ତୁ।
4. ମୋଡ୍ ସେଲେକ୍ଟର୍ (`modalityBridgeVisionMode`, ତଳ ତାଲିକା ଦେଖନ୍ତୁ) ପୁନଃପଥ ବନାମ୍ ବର୍ଣ୍ଣନା ସ୍ଥିର କରେ। ପୁନଃପଥ କେବଳ `model` ସ୍ୱାପ୍ ହୋଇଥିବା `modifiedPayload` ଫେରାଇଥାଏ, ଏବଂ ମେଟା `{ rerouted, fromModel, toModel, imagesKept }` ଦେଇଥାଏ।
5. ବର୍ଣ୍ଣନା ପାଥ୍: ଛବିଗୁଡ଼ିକୁ `maxImages` ରେ କ୍ୟାପ୍ କରନ୍ତୁ, ଟାସ୍କ-ଜ୍ଞାନକୌଶଳ ପ୍ରମ୍ପଟ୍ ପ୍ରସ୍ତୁତ କରନ୍ତୁ, ବର୍ଣ୍ଣନା କ୍ୟାଶ୍ ପରାମର୍ଶ କରନ୍ତୁ, ଭିଜନ ମଡେଲ୍ କୁ **ସମାନ୍ତରାଳ ଭାବରେ** (`Promise.allSettled`) କଲ୍ କରନ୍ତୁ, ଏବଂ ସେଗୁଡ଼ିକର ସ୍ଥାନରେ `[Image N]: <description>` ଟେକ୍ସଟ୍ ଅଂଶଗୁଡ଼ିକୁ ଇଞ୍ଜେକ୍ଟ କରନ୍ତୁ। ଏକ ବିଫଳ ବର୍ଣ୍ଣନା `null` ପ୍ରଦାନ କରେ: ଅଜ୍ଞାତ/ଭିଜନ-ସକ୍ଷମ ଟାର୍ଗେଟ୍ (#4012) ପାଇଁ ର' ଇମେଜ୍ ସଂରକ୍ଷିତ ହୋଇଥାଏ, କିନ୍ତୁ ଏକ **ନିଶ୍ଚିତ କେବଳ-ଟେକ୍ସଟ୍ ପ୍ରତ୍ୟକ୍ଷ ଟାର୍ଗେଟ୍** କିମ୍ବା ଜିରୋ-ଭିଜନ କମ୍ବୋ ପ୍ରତ୍ୟେକ ବର୍ଣ୍ଣନା କରାଯାଇନଥିବା ଛବି ପାଇଁ ଏକ ସ୍ପଷ୍ଟ `(unavailable — no vision-capable provider connected)` ଟେକ୍ସଟ୍ ସ୍ଟବ୍ ପାଇଥାଏ, ଯେଉଁଥିରେ ଆଂଶିକ ବିଫଳତା ଏବଂ ବର୍ଣ୍ଣନା-କଲ୍ କ୍ୟାପ୍ (#17069) ବାହାରେ ଥିବା ଛବିଗୁଡ଼ିକ ମଧ୍ୟ ଅନ୍ତର୍ଭୁକ୍ତ। ବିଦ୍ୟମାନ ସମସ୍ତ-ବିଫଳ କମ୍ବୋ ବର୍ଣ୍ଣନା ଫଲବ୍ୟାକ୍ ସେହିପରି ରହିଛି (#8430)।
6. `modifiedPayload` + ମେଟା (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ଫେରାନ୍ତୁ।

#### API-କି ସ୍କୋପ୍ (`visionBridgeKeyScope.ts`)

ଯେତେବେଳେ କଲରଙ୍କ API କି `allowedConnections`, କୋଟା ପୁଲ୍ (`allowedQuotas`) କିମ୍ବା ମଡେଲଗୁଡ଼ିକୁ (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) ସୀମିତ କରେ, ସେତେବେଳେ ବ୍ରିଜ୍ କେବଳ ସେହି ପୁନଃପଥପ୍ରାପ୍ତ ଏବଂ ବର୍ଣ୍ଣନା ମଡେଲଗୁଡ଼ିକୁ ଚୟନ କରେ ଯାହା କି ବ୍ୟବହାର କରିପାରିବ, ସେହି ସଂଯୋଗଗୁଡ଼ିକରେ ଯାହା କି କି ବ୍ୟବହାର କରିପାରିବ। ବର୍ଣ୍ଣନା କଲ୍ ତା'ପରେ ସର୍ବଦା OmniRoute ସେଲ୍ଫ-ଲୁପ୍ ମାଧ୍ୟମରେ `x-omniroute-self-loop-key-id` ହେଡର୍ ସହିତ ଯାଏ, ଯାହାଫଳରେ ଗ୍ରହଣ କରୁଥିବା ଚାଟ୍ ଅନୁରୋଧ ସେହି କି'ର ସଂଯୋଗ ଏବଂ ମଡେଲ୍ ନୀତିକୁ ପୁନର୍ବାର ପ୍ରୟୋଗ କରେ। `enforceApiKeyPolicy()` କେବଳ ସେଲ୍ଫ-ଲୁପ୍ ବିୟରର୍ ସହିତ ସେହି ହେଡର୍ କୁ ସମ୍ମାନ ଦିଏ, ତେଣୁ ଏହା କେବଳ ପ୍ରବେଶକୁ ସଂକୁଚିତ କରିପାରେ, ଏବଂ ଏକ ଆଇଡି ଯାହା ରିଜୋଭ୍ ହୁଏ ନାହିଁ ତାହା ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ।

ଯଦି କି' ପାଇଁ କୌଣସି ଭିଜନ୍ ମଡେଲ୍ ଅନୁମତିପ୍ରାପ୍ତ ନୁହେଁ, ତେବେ ଏକ **ନିଶ୍ଚିତ କେବଳ ଟେକ୍ସଟ୍ ଟାର୍ଗେଟ୍** ଏକ ଅସମର୍ଥ ଅପଷ୍ଟ୍ରିମ୍ (#17069) କୁ ଇମେଜ୍ ବାଇଟ୍ ପଠାଇବା ପରିବର୍ତ୍ତେ ଏକ ସ୍ପଷ୍ଟ HTTP 400 ସହିତ ସ୍ଥାନୀୟ ଭାବରେ ଇମେଜ୍ ଅନୁରୋଧକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଅଜ୍ଞାତ କିମ୍ବା ନେଟିଭ୍ ଭିଜନ୍ କ୍ଷମତା ଥିବା ଟାର୍ଗେଟ୍ ଗୁଡ଼ିକ ପାଇଁ, ବର୍ଣ୍ଣନା ପାଥ୍ ଏହାର ପୂର୍ବବର୍ତ୍ତୀ ଫେଲ୍-ଓପନ୍ ବ୍ୟବହାରକୁ ବଜାୟ ରଖେ (ମେଟା `{ skipped: true, reason: "no_permitted_vision_model" }`). କି' ବିନା ଅନୁରୋଧ, ଏବଂ ଏହି ପ୍ରତିବନ୍ଧକ ବିନା କି'ଗୁଡ଼ିକ, ପୂର୍ବପରି ସଠିକ୍ ଭାବରେ ଆଚରଣ କରନ୍ତି।

#### ଟାସ୍କ-ସଚେତନ ବର୍ଣ୍ଣନା ପ୍ରମ୍ପଟ୍ (`modalityBridgeVisionTaskAware`)

ଡିଫଲ୍ଟ **true** ଅଟେ। `composeVisionPrompt()` (`visionBridgeHelpers.ts`) ମୂଳ ବର୍ଣ୍ଣନା ପ୍ରମ୍ପଟ୍ ରେ **ଶେଷ ବ୍ୟବହାରକାରୀ ବାର୍ତ୍ତା** ର ଟେକ୍ସଟ୍ (500 ଅକ୍ଷର ପର୍ଯ୍ୟନ୍ତ କଟାଯାଇଛି) ଯୋଡ଼ିଥାଏ, ଯାହା ବର୍ଣ୍ଣନାକୁ ବ୍ୟବହାରକାରୀ ପ୍ରକୃତରେ କ'ଣ ପଚାରିଥିଲେ (codex-vision-proxy ପ୍ୟାଟର୍ଣ୍ଣ) ସେଥିପ୍ରତି ପରିଚାଳିତ କରେ ଏବଂ ଭିଜନ୍ ମଡେଲକୁ ଦୃଶ୍ୟମାନ ଟେକ୍ସଟ୍ ଟ୍ରାନ୍ସକ୍ରାଇବ୍ କରିବାକୁ କୁହେ। ଫ୍ଲାଗ୍ ଅଫ୍ ଥିଲେ — କିମ୍ବା କୌଣସି ବ୍ୟବହାରକାରୀ ଟେକ୍ସଟ୍ ନଥିଲେ — ମୂଳ ପ୍ରମ୍ପଟ୍ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ବ୍ୟବହୃତ ହୁଏ।

ବର୍ଣ୍ଣନା ସେଲ୍ଫ-ଲୁପ୍ର ନିଜସ୍ୱ OpenAI-ସୁସଙ୍ଗତ ଅନୁରୋଧ (`visionBridgeHelpers.ts` ରେ `callVisionModelSingle()`) ସର୍ବଦା `image_url.detail: "high"` ଅନୁରୋଧ କରେ — ସର୍ତ୍ତହୀନ ଭାବରେ, ପ୍ରତ୍ୟେକ କଲର/ପ୍ରଦାତାଙ୍କ ପାଇଁ, କୌଣସି କ୍ଲାଏଣ୍ଟ ସିଗନାଲ୍ ଉପରେ ଗେଟ୍ ହୋଇ ନାହିଁ। କମ୍-ବିସ୍ତୃତ ସାମ୍ପଲିଂ ଠିକ୍ ସେହି ଟେକ୍ସଟ୍-ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଟାସ୍କ ପାଇଁ OCR ସଠିକତାକୁ ହ୍ରାସ କରେ ଯାହା ଏହି ପ୍ରମ୍ପଟ୍ ପଚାରେ, ତେଣୁ ବର୍ଣ୍ଣନା କଲ୍ ନିଜେ ସର୍ବଦା ଉଚ୍ଚ ବିସ୍ତୃତି ପାଇଁ ପଚାରେ ଯେକୌଣସି ବିସ୍ତୃତି ସ୍ତର ମୂଳ ଇନବାଉଣ୍ଡ ଅନୁରୋଧ ବ୍ୟବହାର କରିଥିଲେ ମଧ୍ୟ। ଏହା କେବଳ ଆଭ୍ୟନ୍ତରୀଣ ବର୍ଣ୍ଣନା ଅନୁରୋଧ ବଡିକୁ ପ୍ରଭାବିତ କରେ; ଏହା ପରିବର୍ତ୍ତନ କରେ ନାହିଁ କିପରି OmniRoute ପ୍ରାଥମିକ ଅନୁରୋଧରେ କଲରଙ୍କ ନିଜସ୍ୱ `image_url.detail` କୁ ଫରୱାର୍ଡ କରେ — ସେହି ଡିଫଲ୍ଟ ଅଲଗା ଭାବରେ ପ୍ରୟୋଗ କରାଯାଏ, ଏବଂ କେବଳ ଚିହ୍ନଟ ହୋଇଥିବା OpenCode କ୍ଲାଏଣ୍ଟମାନଙ୍କ ପାଇଁ, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) ରେ। ବର୍ଣ୍ଣନା ସେଲ୍ଫ-ଲୁପ୍ର ଆନ୍ଥ୍ରୋପିକ୍ ୱାୟାର୍-ଫର୍ମାଟ୍ ବ୍ରାଞ୍ଚରେ କୌଣସି `detail` ଫିଲ୍ଡ ନାହିଁ ଏବଂ କୌଣସି ଡିଫଲ୍ଟ ଦ୍ୱାରା ପ୍ରଭାବିତ ହୁଏ ନାହିଁ।

#### ବର୍ଣ୍ଣନା ଆଉଟପୁଟ୍ କ୍ୟାପ୍ (`modalityBridgeVisionMaxChars`)

| କି                             | ଡିଫଲ୍ଟ | ପରିସର                |
| ------------------------------ | ------ | -------------------- |
| `modalityBridgeVisionMaxChars` | `0`    | `0` କିମ୍ବା 100–50000 |

`0` (ଡିଫଲ୍ଟ) ର ଅର୍ଥ ହେଉଛି **କୌଣସି କ୍ୟାପ୍ ନାହିଁ** — `callVisionModel()` ଦ୍ୱାରା ଫେରାଯାଇଥିବା ବର୍ଣ୍ଣନା ଅପରିବର୍ତ୍ତିତ ଭାବରେ ପାସ୍ ହୁଏ, ପୂର୍ବବର୍ତ୍ତୀ ବ୍ୟବହାରକୁ ବଜାୟ ରଖେ। 100–50000 ପରିସର ମଧ୍ୟରେ ଯେକୌଣସି ମୂଲ୍ୟ ବର୍ଣ୍ଣନାକୁ `…` ପ୍ରତ୍ୟୟ ସହିତ କାଟିଦିଏ ଏହା ପୂର୍ବରୁ ଯେ ଏହା `[Image N]: <description>` (`src/lib/guardrails/visionBridge.ts` ରେ `VisionBridgeGuardrail.preCall()`) ଭାବରେ ପୁନର୍ବାର ସ୍ପ୍ଲାଇସ୍ ହୁଏ। ବିସ୍ତୃତି-ଭାରୀ OCR ଟାସ୍କଗୁଡ଼ିକ ପାଇଁ ଏହାକୁ ବୃଦ୍ଧି କରନ୍ତୁ ଯେଉଁଠାରେ ଡାଉନଷ୍ଟ୍ରିମ୍ ମଡେଲ୍ ସମ୍ପୂର୍ଣ୍ଣ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଆବଶ୍ୟକ କରେ; ଚାଟି ଭିଜନ୍ ମଡେଲଗୁଡ଼ିକରେ ଟୋକନ୍ ବ୍ୟବହାରକୁ ବାନ୍ଧିବା ପାଇଁ ଏହାକୁ ହ୍ରାସ କରନ୍ତୁ। ଡ୍ୟାସବୋର୍ଡ ଫିଲ୍ଡ ଭିଜନ୍ ଟ୍ୟାବ୍ର ଆଡଭାନ୍ସଡ୍ ପ୍ୟାନେଲ୍ (`ModalityBridgeVisionTab.tsx` ରେ `modality-bridge-max-chars`) ରେ ରହେ ଏବଂ 1 ଏବଂ 99 ମଧ୍ୟରେ ଯେକୌଣସି ମୂଲ୍ୟକୁ 100 ଫ୍ଲୋର୍ ପର୍ଯ୍ୟନ୍ତ କ୍ଲାମ୍ପ କରେ ଯେତେବେଳେ ଏକ ସ୍ପଷ୍ଟ `0` କୁ ଅପରିବର୍ତ୍ତିତ ରଖେ — `0` ନିଜସ୍ୱ ଅଧିକାରରେ ଏକ ବୈଧ Zod ମୂଲ୍ୟ ଅଟେ (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), କେବଳ "unset" ଡିଫଲ୍ଟ ନୁହେଁ।

#### ବର୍ଣ୍ଣନା କ୍ୟାଶ୍ (`modalityBridge/bridgeCache.ts`)

ବର୍ଣ୍ଣନା ଆଉଟପୁଟ୍ ପାଇଁ ଇନ୍-ମେମୋରୀ LRU + TTL କ୍ୟାଶ୍, ସମଗ୍ର ପ୍ରକ୍ରିୟା ସେୟାର୍ ହୋଇଛି। କି = `sha256(imageRef + composedPrompt + configuredBridgeModel)` ଦୈର୍ଘ୍ୟ-ପ୍ରିଫିକ୍ସ ଫ୍ରେମିଂ ସହିତ (କୌଣସି ଫିଲ୍ଡ-ସୀମା ସଂଘର୍ଷ ନାହିଁ)। ମଡେଲ୍ ଉପାଦାନଟି ହେଉଛି କନଫିଗର୍ ହୋଇଥିବା ବ୍ରିଜ୍ ମଡେଲ୍, ଯେଉଁ ମଡେଲ୍ ପ୍ରକୃତରେ ଉତ୍ତର ଦେଇଥିଲା ତାହା ନୁହେଁ — `callVisionModel` ଆଭ୍ୟନ୍ତରୀଣ ଭାବରେ ଫଲ୍ ବ୍ୟାକ୍ କରିପାରେ, ଏବଂ ପ୍ରତ୍ୟେକ ପ୍ରଚେଷ୍ଟା ପାଇଁ କିଇଂ କ୍ୟାଶ୍କ ଖଣ୍ଡଖଣ୍ଡ କରିବ। ବିଫଳ ବର୍ଣ୍ଣନାଗୁଡ଼ିକ କେବେ ମଧ୍ୟ କ୍ୟାଶ୍ ହୁଏ ନାହିଁ। ସେଟିଂସମୂହ:

| କି                              | ଡିଫଲ୍ଟ | ପରିସର   |
| ------------------------------- | ------ | ------- |
| `modalityBridgeCacheEnabled`    | `true` | —       |
| `modalityBridgeCacheTtlMinutes` | `60`   | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`  | 10–5000 |

#### ରିମୋଟ୍ ପ୍ରତିଛବି ସାଧାରଣୀକରଣ (self-loop describe/base64 fetch)

ଯେତେବେଳେ ବ୍ରିଜ୍ ନିଜେ ଏକ **ରିମୋଟ୍** ପ୍ରତିଛବି ଆଣେ — ଆନ୍ଥ୍ରୋପିକର describe ସେଲ୍-କଲ୍ ଏବଂ claude-wire-format base64 ରୂପାନ୍ତରଣ (`ensureBase64ImagesForClaudeWire`), ଏହା ଉଭୟ `visionBridgeHelpers.ts` ର `fetchRemoteImageAsDataUri()` ମାଧ୍ୟମରେ ହୋଇଥାଏ — ଫଳସ୍ୱରୂପ ଡାଟା URI କୁ ଭିଜନ-ମଡେଲ୍ ଅନୁରୋଧରେ ଏମ୍ବେଡ୍ କରିବା ପୂର୍ବରୁ `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) ମାଧ୍ୟମରେ ପାସ୍ କରାଯାଇଥାଏ। ବଡ଼ ଆକାରର ପ୍ରତିଛବିଗୁଡ଼ିକୁ **2048px long edge** କୁ ଡାଉନସ୍କେଲ୍ କରାଯାଇଥାଏ (OpenAI/Anthropic ପୂର୍ବରୁ ସର୍ଭର-ସାଇଡ୍ ରେ ପ୍ରୟୋଗ କରୁଥିବା ରିସାଇଜ୍ କ୍ୟାପ୍ ସହିତ ମେଳ ଖାଏ), ଯାହା ଭିଜନ ମଡେଲ୍ ଦେଖୁଥିବା ଜିନିଷକୁ ପରିବର୍ତ୍ତନ ନକରି ଅପଲୋଡ୍ ବାଇଟ୍/ଲେଟେନ୍ସିକୁ କମାଇଥାଏ। ରିସାଇଜ୍ କରିବା ପାଇଁ `sharp` ବ୍ୟବହାର କରାଯାଇଥାଏ, ଯାହା ଡାଇନାମିକ୍ ଇମ୍ପୋର୍ଟ ମାଧ୍ୟମରେ ଲୋଡ୍ ହୁଏ: ଏକ ପ୍ଲାଟଫର୍ମରେ ଯେଉଁଠାରେ ଏହାର ନେଟିଭ୍ ବାଇନାରୀ ଲୋଡ୍ ହେବାରେ ବିଫଳ ହୁଏ, `normalizeDataUri()` କେବେବି **throw କରେ ନାହିଁ** — ଏହା ମୂଳ ବାଇଟ୍ର ଏକ ପାସ୍‌ଥ୍ରୁକୁ ଫେରାଇଥାଏ, ତେଣୁ describe/base64-conversion ପାଥ୍ ସର୍ବଦା କାମ କରିଚାଲେ। ଅନ୍-ଇମେଜ୍ ବାଇଟ୍ ଗୁଡ଼ିକ (ଏକ ଫେଚ୍ ଯାହା ଏକ ଡିକୋଡ୍ କରିହେଉଥିବା ପ୍ରତିଛବି ଫେରାଇ ନଥିଲା) ମଧ୍ୟ ଅପରିବର୍ତ୍ତିତ ଭାବରେ ପାସ୍ ହୋଇଥାଏ। ଏହି ସାଧାରଣୀକରଣ କେବଳ ବ୍ରିଜ୍ ଏହାର ନିଜସ୍ୱ ସେଲ୍-କଲ୍ ପାଇଁ ଆଣୁଥିବା ପ୍ରତିଛବିଗୁଡ଼ିକ ପାଇଁ ସୀମିତ ଅଟେ — ଏହା କେବେ ମଧ୍ୟ କଲର୍ ର ର କଞ୍ଚା ପାସ୍‌ଥ୍ରୁ ପେଲ୍‌ଲୋଡ୍ ରେ ପ୍ରୟୋଗ କରାଯାଏ ନାହିଁ, ଯାହା ଅପ୍-ଇନ୍-ଓନ୍ଲି ମ୍ୟୁଟେସନ୍ ନୀତି (Hard Rule #20) ସହିତ ସଙ୍ଗତିପୂର୍ଣ୍ଣ ଅଟେ।

#### ସେଟିଂସ୍ ସ୍କେମା + ମାଇଗ୍ରେସନ୍

ନୂତନ `modalityBridge*` କି ଗୁଡ଼ିକ `updateSettingsSchema` (`src/shared/validation/settingsSchemas.ts`) ରେ Zod-validated ଅଟେ: `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCache*` ଟ୍ରିଓ, ଏବଂ ଅଡିଓ ବ୍ରିଜ୍ ଦ୍ୱାରା ବ୍ୟବହୃତ `modalityBridgeAudio*` ଗ୍ରୁପ୍। ମାଇଗ୍ରେସନ୍ `141_modality_bridge_settings.sql` ବିଦ୍ୟମାନ ଲେଗାସି `visionBridge*` ମୂଲ୍ୟଗୁଡ଼ିକୁ ମେଳ ହେଉଥିବା ନୂତନ କି ଗୁଡ଼ିକୁ କପ୍ କରିଥାଏ (idempotent, କୌଣସି ଅପରେଟର୍-ସେଟ୍ `modalityBridge*` ମୂଲ୍ୟକୁ କେବେବି ଓଭରରାଇଟ୍ କରେ ନାହିଁ); ଲେଗାସି କି ଗୁଡ଼ିକ ଗୋଟିଏ ରିଲିଜ୍ ସାଇକେଲ୍ ପାଇଁ ଏକ ପଠନ ଫଲବ୍ୟାକ୍ ଭାବରେ ଗ୍ରହଣ କରାଯାଏ।

#### ସ୍ୱଚ୍ଛତା ହେଡର୍ + ପରିସଂଖ୍ୟାନ

Describe-ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ବହନ କରିଥାଏ (`modalityBridge/bridgeStats.ts` ରେ `buildModalityBridgeHeader()` ଦ୍ୱାରା ନିର୍ମିତ, `src/sse/handlers/chatHelpers.ts` ରେ `withModalityBridgeHeader()` ଦ୍ୱାରା ଷ୍ଟାମ୍ପ୍ କରାଯାଇଥାଏ)। ପୁନଃରୁଟ୍ ହୋଇଥିବା ଅନୁରୋଧଗୁଡ଼ିକ କୌଣସି ହେଡର୍ **ପାଆନ୍ତି ନାହିଁ** — ପେଲ୍‌ଲୋଡ୍ ଅପରିବର୍ତ୍ତିତ ରହିଥିଲା ଏବଂ ମଡେଲ୍ ସ୍ୱାପ୍ ପୂର୍ବରୁ ପ୍ରତିକ୍ରିୟା ବଡିର `model` ଫିଲ୍ଡରେ ଦୃଶ୍ୟମାନ ହୋଇଥାଏ।

`GET /api/modality-bridge/stats` (ମ୍ୟାନେଜମେଣ୍ଟ୍ ଅଥ୍, `GET /api/settings` ପରି ସମାନ ଟାୟାର୍) `vision`, `audio`, ଏବଂ `video` ପାଇଁ ଇନ୍-ମେମୋରୀ ପ୍ରତି-ମୋଡାଲିଟି କାଉଣ୍ଟରଗୁଡ଼ିକୁ ଫେରାଇଥାଏ: `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }`। `averageLatencyMs` ସମସ୍ତ ପ୍ରୟାସ ନୁହେଁ, ବରଂ `latencySamples` କୁ ଏହାର ଡେନୋମିନେଟର୍ ଭାବରେ ବ୍ୟବହାର କରିଥାଏ; ସମୟ ନଥିବା ଏକ ଅପରେସନ୍ ଶୂନ୍ୟ-ମିଲିସେକେଣ୍ଡ୍ ସାମ୍ପଲ୍ ତିଆରି କରେ ନାହିଁ। `bridged` ସଫଳ ରୂପାନ୍ତରଣଗୁଡ଼ିକ ପାଇଁ ପଛକୁ-ସୁସଙ୍ଗତ ଏଲିଆସ୍ ଭାବରେ ରହିଥାଏ; ବିଫଳ ପ୍ରୟାସଗୁଡ଼ିକ ଏହାକୁ ବୃଦ୍ଧି କରେ ନାହିଁ। ଡିଜାଇନ୍ ଅନୁଯାୟୀ ପ୍ରକେସ ରିଷ୍ଟାର୍ଟ ହେଲେ କାଉଣ୍ଟରଗୁଡ଼ିକ ରିସେଟ୍ ହୋଇଯାଏ (ଟେଲିମେଟ୍ରି, ଆକାଉଣ୍ଟିଂ ନୁହେଁ)।

#### ଡ୍ୟାସବୋର୍ଡ କନଫିଗରେସନ୍

ଉତ୍ସର୍ଗୀକୃତ ଡ୍ୟାସବୋର୍ଡ ପୃଷ୍ଠା ହେଉଛି `/dashboard/settings/modality-bridge`। ଏହାର URL-addressable `Vision`, `Audio`, ଏବଂ `Video` ଟ୍ୟାବ୍ ଗୁଡ଼ିକ `tab` ମୂଲ୍ୟ ସୁଇଚ୍ କରିବା ସମୟରେ କ୍ୱେରି ପାରାମିଟରଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରିଥାଏ। ଭିଜନ ଟ୍ୟାବ୍ ଏବଲ୍‌ମେଣ୍ଟ୍, ମୋଡ୍, ମଡେଲ୍ ଚୟନ (ସ୍ୱୟଂଚାଳିତ ଡିଫଲ୍ଟ ସହିତ), ଟାସ୍କ-ଆୱାର୍ ପ୍ରମ୍ପ୍ଟିଂ, ଆଡ୍ଭାନ୍ସଡ୍ ଟାଇମ୍‌ଆଉଟ୍/ଇମେଜ୍/ବର୍ଣ୍ଣନା-ଦୈର୍ଘ୍ୟ/କ୍ୟାଚ୍ ସୀମା, ରନଟାଇମ୍ କାଉଣ୍ଟର, ଏବଂ ଏକ ଗାର୍ଡେଡ୍ ସାମ୍ପଲ୍ ଅନୁରୋଧ ପ୍ରକାଶ କରେ। ଅଡିଓ ଟ୍ୟାବ୍ ମଧ୍ୟ ଲାଇଭ୍ ଅଛି: ଏହା ଏବଲ୍‌ମେଣ୍ଟ୍, Auto ସହିତ ଏକ STT-only ମଡେଲ୍ ପିକର୍, ଟାଇମ୍‌ଆଉଟ୍/ମ୍ୟାକ୍ସ-କ୍ଲିପ୍ ସୀମା, ଅଡିଓ କାଉଣ୍ଟର, ଏବଂ ଏକ `input_audio` ସାମ୍ପଲ୍ ପରୀକ୍ଷା ପ୍ରକାଶ କରେ। ଭିଡିଓ ଟ୍ୟାବ୍ କାର୍ଯ୍ୟକ୍ଷମ ଅଟେ: ଏହା FFmpeg/ffprobe ରନଟାଇମ୍ ଅବସ୍ଥା ରିପୋର୍ଟ କରେ — ଚାରୋଟି ସ୍ପଷ୍ଟ UI ଅବସ୍ଥା ମଧ୍ୟରୁ ଗୋଟିଏ (`unknown` ଯେତେବେଳେ ପ୍ରୋବ୍ ଚାଲିଥାଏ ବା ସମ୍ପୂର୍ଣ୍ଣ ହୋଇପାରେ ନାହିଁ, `restricted` ଏକ ଅନ୍-ଲୁପ୍‌ବ୍ୟାକ୍ ଡ୍ୟାସବୋର୍ଡ ହୋଷ୍ଟରେ ଯେଉଁଠାରେ ପ୍ରୋବ୍ କ୍ଲାଏଣ୍ଟ-ସାଇଡ୍ ରେ ଏଡ଼ାଇ ଦିଆଯାଏ, `unavailable` ଥରେ ପ୍ରୋବ୍ ହୋଇ ନିଖୋଜ ବୋଲି ନିଶ୍ଚିତ ହେଲେ, ବା FFmpeg/ffprobe ସଂସ୍କରଣ ସହିତ `available`) — ଏବଲ୍/ମଡେଲ୍/ଫ୍ରେମ୍/ଭିଡିଓ/ଟାଇମ୍‌ଆଉଟ୍ ସୀମାଗୁଡ଼ିକୁ ସଞ୍ଚୟ କରେ, ମଡେଲ୍ ପିକର୍ କୁ ଭିଜନ-ସକ୍ଷମ ମଡେଲ୍ ଗୁଡ଼ିକରେ ଫିଲ୍ଟର୍ କରେ, ଏବଂ ଭିଡିଓ କାଉଣ୍ଟର ପ୍ରକାଶ କରେ।

AI ସେଟିଂସ୍ ଅଧୀନରେ ଥିବା ପୂର୍ବତନ ଭିଜନ ବ୍ରିଜ୍ କାର୍ଡ ହେଉଛି ନୂତନ ପୃଷ୍ଠା ପାଇଁ ଏକ ସୁସଙ୍ଗତତା ଲିଙ୍କ୍; ଏହାର ଆଉ ଫର୍ମର ଦ୍ୱିତୀୟ କପ୍ ନାହିଁ। ମିଡିଆ ପ୍ରୋଭାଇଡର୍ସ ମଧ୍ୟ ଇମେଜ୍-ଟୁ-ଟେକ୍ସଟ୍ ଏବଂ ସ୍ପିଚ୍-ଟୁ-ଟେକ୍ସଟ୍ ୱାର୍କଫ୍ଲୋଗୁଡ଼ିକୁ ବିଦ୍ୟମାନ ସ୍ପିଚ୍-ଟୁ-ଟେକ୍ସଟ୍ ପ୍ଲେଗ୍ରାଉଣ୍ଡ୍ କୁ ହଟାଇ ନକରି ସ୍ୱାଭାବିକ ମୋଡାଲିଟି ବ୍ରିଜ୍ ଟ୍ୟାବ୍ ସହିତ ଲିଙ୍କ୍ କରିଥାଏ।

**ସେଲ୍-ଲୁପ୍ ଆଡମିସନ୍ ବାଇପାସ୍:** ଯେତେବେଳେ describe କଲ୍ OmniRoute ର ନିଜସ୍ୱ `/v1` ସେଲ୍-ଲୁପ୍ (ଅଣ-ମାନ୍ୟ ପ୍ରୋଭାଇଡର୍ ମଡେଲ୍) ମାଧ୍ୟମରେ ରୁଟ୍ ହୁଏ, ସେବେ ସବ୍-ଅନୁରୋଧ `x-omniroute-admission-bypass: internal` ପଠାଏ ଏବଂ ସମାଧାନ ହୋଇଥିବା ସେଲ୍-ଲୁପ୍ କ୍ରେଡେନ୍ସିଆଲ୍ ସହିତ ପ୍ରମାଣିତ ହୁଏ — ଲୋକାଲ୍ ମୋଡ୍ ରେ ଲୋକାଲ୍ `sk_omniroute` ସେଣ୍ଟିନେଲ୍, ବା ଅପରେଟର୍-କନ୍ଫିଗର୍ଡ `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env କି (#1350) ଯାହାଫଳରେ `REQUIRE_API_KEY=true` ଡିପ୍ଲୟମେଣ୍ଟ୍ ଗୁଡ଼ିକ ଏବେ ବି describe କଲ୍ ଚଲାଇ ପାରିବେ। ବାଇପାସ୍ କେବଳ ସେହି ସଠିକ୍ କ୍ରେଡେନ୍ସିଆଲ୍ ଗୁଡ଼ିକ ପାଇଁ ଗ୍ରହଣ କରାଯାଇଥାଏ, ତେଣୁ ବାହ୍ୟ କ୍ଲାଏଣ୍ଟମାନେ ଆଡମିସନ୍ ଏଡ଼ାଇବା ପାଇଁ ହେଡର୍ ବ୍ୟବହାର କରିପାରିବେ ନାହିଁ।

ଲେଗାସି ଡିଫଲ୍ଟଗୁଡ଼ିକ `src/shared/constants/visionBridgeDefaults.ts` ରେ ରହିଥାଏ; ନୂତନ ମୋଡ୍/ଟାସ୍କ-ଆୱାର୍/କ୍ୟାଚ୍ ଡିଫଲ୍ଟ ଏବଂ ସେଟିଂସ୍ ରିଜଲ୍ଭର୍ `src/shared/constants/modalityBridgeDefaults.ts` ରେ ରହିଥାଏ। ଗାର୍ଡରେଲ୍ ଏକ `deps` କନଷ୍ଟ୍ରକ୍ଟର ଅପ୍ସନ୍ର ପ୍ରକାଶ କରେ ଯାହାଫଳରେ ଟେଷ୍ଟଗୁଡ଼ିକ ନକଲି `getSettings` ଏବଂ `callVisionModel` ଇମ୍ପ୍ଲିମେଣ୍ଟେସନ୍ ଇଞ୍ଜେକ୍ଟ କରିପାରିବେ।

### ଅଡିଓ ବ୍ରିଜ୍ (`audioBridge.ts`) — ମୋଡାଲିଟି ବ୍ରିଜ୍ PR-3

ଅଡିଓ-ଧାରଣକାରୀ ଚାଟ୍ ଅନୁରୋଧଗୁଡ଼ିକୁ ସେତେବେଳେ ବାଧାପ୍ରାପ୍ତ କରେ ଯେତେବେଳେ ସେଗୁଡ଼ିକ ଏକ ଲକ୍ଷ୍ୟରେ ପହଞ୍ଚେ ଯାହା ଅଡିଓ ଇନପୁଟ୍ ଗ୍ରହଣ କରିବା ପାଇଁ ଜଣାଶୁଣା ନୁହେଁ। ଏହା କେବେ ମଧ୍ୟ ଚାଟ୍ ଅନୁରୋଧକୁ ପୁନଃରୁଟ୍ କରେ ନାହିଁ: ଅଡିଓ ଅଂଶଗୁଡ଼ିକ ବିଦ୍ୟମାନ OpenAI-compatible ମଲ୍ଟିପାର୍ଟ ଏଣ୍ଡପଏଣ୍ଟ୍ ମାଧ୍ୟମରେ ଟ୍ରାନ୍ସକ୍ରାଇବ୍ ହୋଇଥାଏ ଏବଂ ଚୟନିତ ଚାଟ୍ ମଡେଲ୍ ଟେକ୍ସଟ୍ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ସହିତ ଜାରି ରହେ।

ପ୍ରବାହ:

1. `getResolvedModelCapabilities()` ମାଧ୍ୟମରେ `supportsAudio` ସମାଧାନ କରନ୍ତୁ। ସ୍ପଷ୍ଟ ପ୍ରଦାତା-ରେଜିଷ୍ଟ୍ରି ମେଟାଡାଟା ଜିତେ, ତା'ପରେ ଷ୍ଟାଟିକ୍ ମଡେଲ୍ ମେଟାଡାଟା, ଏବଂ ତା'ପରେ ସିଙ୍କ୍ ହୋଇଥିବା `modalities_input`। `audio` ବିନା ଏକ ଘୋଷିତ ଇନପୁଟ୍ ତାଲିକା `false` ଅଟେ; କୌଣସି କ୍ଷମତା ପ୍ରମାଣ `null` ରହେ। `false` ଏବଂ `null` ଉଭୟ ରକ୍ଷଣଶୀଳ ବ୍ରିଜ୍ ସକ୍ରିୟ କରନ୍ତି, ଯେତେବେଳେ କି `true` ଏହାକୁ ବାଇପାସ୍ କରେ।
2. `modalityBridgeAudio*` ସେଟିଂସ୍ ସମାଧାନ କରନ୍ତୁ ଏବଂ ସେୟାର୍ଡ `detectMediaParts()` ଡିଟେକ୍ଟର୍ ମାଧ୍ୟମରେ ପ୍ରତ୍ୟେକ ବାର୍ତ୍ତାରୁ ସ୍ପ୍ଲାଇସ୍ ହୋଇପାରିବା ଭଳି ଟପ୍-ଲେଭଲ୍ ଅଡିଓ ଅଂଶଗୁଡ଼ିକୁ ଏକ୍ସଟ୍ରାକ୍ଟ କରନ୍ତୁ। ସମର୍ଥିତ ୱାୟାର୍ ଆକାରଗୁଡ଼ିକ ହେଲା OpenAI `input_audio`, `audio_url`, ଏବଂ `source.media_type: "audio/*"`। ନେଷ୍ଟେଡ୍ ଅଡିଓ ରୁଟିଂ ପାଇଁ ଡିଟେକ୍ଟ ହୁଏ କିନ୍ତୁ ସ୍ପ୍ଲାଇସ୍ ପାଥ୍ ଦ୍ୱାରା ଅପସାରିତ ହୁଏ ନାହିଁ। କାର୍ଯ୍ୟ `modalityBridgeAudioMaxClips` ଦ୍ୱାରା ସୀମିତ; ପରବର୍ତ୍ତୀ ଅଂଶଗୁଡ଼ିକ ଅପରିବର୍ତ୍ତିତ ରହେ।
3. ଏକ କନଫିଗର୍ ହୋଇଥିବା `provider/model` କୁ ସମ୍ମାନ ଦିଅନ୍ତୁ, କିମ୍ବା `selectAudioBridgeModel()` କୁ ସ୍ଥିର କାଟାଲଗ୍ କ୍ରମରେ `AUDIO_TRANSCRIPTION_PROVIDERS` ବୁଲିବାକୁ ଦିଅନ୍ତୁ ଏବଂ ଏକ ବ୍ୟବହାରଯୋଗ୍ୟ ସକ୍ରିୟ ପ୍ରଦାତା ପ୍ରମାଣପତ୍ର ସହିତ ପ୍ରଥମ ମଡେଲ୍ ଚୟନ କରନ୍ତୁ।
4. `callAudioTranscription()` base64/data-URI ଅଡିଓକୁ ଏକ ମଲ୍ଟିପାର୍ଟ `file` ରେ ରୂପାନ୍ତର କରେ, କିମ୍ବା DNS ପିନିଂ ଏବଂ `25 MB` ବାଉଣ୍ଡ୍ ସହିତ କେବଳ-ପବ୍ଲିକ୍ ଆଉଟ୍‌ବାଉଣ୍ଡ୍ ଗାର୍ଡ ମାଧ୍ୟମରେ ଏକ ରିମୋଟ୍ `audio_url` ଡାଉନଲୋଡ୍ କରେ। ଏହା ପରେ ଏହା `file` ଏବଂ ଚୟନିତ ମଡେଲ୍‌କୁ ସ୍ଥାନୀୟ `/v1/audio/transcriptions` ସେଲ୍-ଲୁପ୍ କୁ POST କରେ, ଯାହା `resolveSelfLoopBearer()` ସହିତ ପ୍ରମାଣିତ ହୋଇଥାଏ। ବିଦ୍ୟମାନ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍ ରୁଟ୍ ସାଧାରଣ ପ୍ରମାଣପତ୍ର ଲୁକ୍ଅପ୍, କୁଡ୍‌ଡାଉନ୍/ରେଟ୍-ଲିମିଟ୍ ହାଣ୍ଡଲିଂ, ଏବଂ ପ୍ରଦାତା ଡିସ୍ପାଚ୍ ସମ୍ପାଦନ କରେ।
5. ସଫଳ କଲଗୁଡ଼ିକ ସେମାନଙ୍କର ଅଂଶଗୁଡ଼ିକୁ `[Audio N]: <transcript>` ଦ୍ୱାରା ବଦଳାଇଥାନ୍ତି। କଲଗୁଡ଼ିକ `Promise.allSettled` ସହିତ ଚାଲେ: ଏକ ବ୍ୟକ୍ତିଗତ ବିଫଳତା ସେହି ମୂଳ ଅଡିଓ ଅଂଶକୁ ସଂରକ୍ଷଣ କରେ (`#4012` ଚୁକ୍ତି)। ଯଦି ପ୍ରତ୍ୟେକ କଲ୍ ବିଫଳ ହୁଏ ଏବଂ ଲକ୍ଷ୍ୟ ପ୍ରମାଣିତ ହୁଏ `supportsAudio === false`, ତେବେ ଅଂଶଗୁଡ଼ିକ `[Audio N]: (unavailable — no STT provider connected)` ହୋଇଯାଏ (`#8430` ଚୁକ୍ତି)। ଏକ ଅଜ୍ଞାତ ଲକ୍ଷ୍ୟ (`null`) ପାଇଁ, ଏକ ସର୍ବ-ବିଫଳତା ଫଳାଫଳ ଅପରିବର୍ତ୍ତିତ ରହେ। କୌଣସି ବ୍ୟବହାରଯୋଗ୍ୟ STT ପ୍ରମାଣପତ୍ର ନଥିବା ଏକ ପ୍ରମାଣିତ ଟେକ୍ସଟ୍-ମାତ୍ର ଲକ୍ଷ୍ୟ ଏକ ନେଟୱାର୍କ କଲ୍ ଜାରି ନକରି ସମାନ ସ୍ପଷ୍ଟ ଷ୍ଟବ୍ ଗ୍ରହଣ କରେ।

ସଫଳ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟଗୁଡ଼ିକ ପ୍ରୋସେସ୍-ବ୍ୟାପୀ Modality Bridge LRU/TTL କ୍ୟାଚ୍ ବ୍ୟବହାର କରେ। କି' (key) ଅଡିଓ ରେଫରେନ୍ସ, ସ୍ଥିର `audio-transcription` ଅପରେସନ୍ ଲେବଲ୍, ଏବଂ ଚୟନିତ STT ମଡେଲ୍ କୁ ମିଶ୍ରଣ କରେ; ବିଫଳତାଗୁଡ଼ିକ କେବେ ମଧ୍ୟ କ୍ୟାଚ୍ ହୁଏ ନାହିଁ। ଅଡିଓ ପ୍ରଚେଷ୍ଟାଗୁଡ଼ିକ ସେୟାର୍ଡ `bridged`, `cacheHits`, `failures`, ଏବଂ `lastUsedAt` କାଉଣ୍ଟରଗୁଡ଼ିକୁ ଅପଡେଟ୍ କରେ। ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ବହନ କରେ; ଅପରିବର୍ତ୍ତିତ ଅନୁରୋଧଗୁଡ଼ିକ ଏକ ଅଡିଓ ବ୍ରିଜ୍ ସେଗ୍‌ମେଣ୍ଟ୍ ଗ୍ରହଣ କରନ୍ତି ନାହିଁ।

ରନ୍‌ଟାଇମ୍ ସେଟିଂସ୍ ଗୁଡ଼ିକ DB-backed ଏବଂ Zod-validated ଅଟେ:

| କି'                           | ଡିଫଲ୍ଟ  | ରେଞ୍ଜ୍        |
| ----------------------------- | ------- | ------------- |
| `modalityBridgeAudioEnabled`  | `true`  | —             |
| `modalityBridgeAudioModel`    | `""`    | ଅଟୋ ବା STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000   |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10          |

ସେୟାର୍ଡ କ୍ୟାଚ୍ `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, ଏବଂ `modalityBridgeCacheMaxEntries` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ ରହେ।

### ଭିଡିଓ ବ୍ରିଜ୍ (`videoBridge.ts`, `videoBridgePipeline.ts`)

ଜଣାଶୁଣା ନେଟିଭ୍ ଭିଡିଓ ସମର୍ଥନ ନଥିବା ଏକ ଲକ୍ଷ୍ୟକୁ କଲ୍ କରିବା ପୂର୍ବରୁ Chat Completions `messages` ଏବଂ Responses API `input` ରେ ଟପ୍-ଲେଭଲ୍ ଭିଡିଓ ଅଂଶଗୁଡ଼ିକୁ ଇଣ୍ଟରସେପ୍ଟ କରେ। ସମର୍ଥିତ ଆକାରଗୁଡ଼ିକ ହେଲା `input_video`, `video_url`, `video_source`, HTTPS URLs, ଏବଂ `data:video/*;base64,...` ଡାଟା URI ଗୁଡ଼ିକ। ଟେକ୍ସଟ୍‌ରେ ଥିବା ସାଧାରଣ ଫାଇଲ୍ ନାମଗୁଡ଼ିକୁ ଭିଡିଓ ଭାବରେ ବିଚାର କରାଯାଏ ନାହିଁ।

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ଅନୁରୋଧ ଟ୍ରାଭେର୍ସାଲ୍, କ୍ଷମତା/ନୀତି ଯାଞ୍ଚ, ପ୍ରତି-ଅନୁରୋଧ ଆଗ୍ରିଗେସନ୍, ଏବଂ ପ୍ରତିକ୍ରିୟା ପେଲ୍‌ଲୋଡ୍ ମାଲିକାନା କରେ। ପ୍ରତି-ଭିଡିଓ କାର୍ଯ୍ୟ — ଅଧିଗ୍ରହଣ, ସମ୍ପୂର୍ଣ୍ଣ-ଫଳାଫଳ କ୍ୟାଚ୍, ଏକ ଫ୍ରେମ୍ କ୍ରମ ବର୍ଣ୍ଣନା କରିବା (ଯାହା କୌଣସି କଲର୍-ଘୋଷିତ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ଫ୍ୟୁଜ୍ କରେ), ଏବଂ ପ୍ରତି-ପ୍ରଚେଷ୍ଟା ମେଟ୍ରିକ୍ସ/ଆବର୍ଟ/କ୍ଲିନଅପ୍ — `videoBridgePipeline.ts` ରେ `processVideoPart` ପଛରେ ଲୁଚାଯାଇଥାଏ, ଯାହା `preCall` ର ଲୁପ୍ ଭିତରେ ପ୍ରତି ଭିଡିଓ ଅଂଶ ପାଇଁ ଥରେ କଲ୍ ହୋଇଥାଏ। ସେହି ମଡ୍ୟୁଲ୍ ସ୍ପଷ୍ଟ ପୋର୍ଟ ସୀମାଗୁଡ଼ିକୁ ମଧ୍ୟ ପରିଭାଷିତ କରେ: `VideoMediaBrokerPort` (ବାଇଟ୍ସ ଅଧିଗ୍ରହଣ କରିବା ଏବଂ ସାମ୍ପଲ୍ ହୋଇଥିବା ଫ୍ରେମ୍‌ଗୁଡ଼ିକୁ ଏକ୍ସଟ୍ରାକ୍ଟ କରିବା), `VideoAudioTranscriptionPort` (ଏକ କଲର୍-ଘୋଷିତ ଅଡିଓ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟକୁ ସାମ୍ପଲ୍ ହୋଇଥିବା କ୍ୟାପ୍ସନଗୁଡ଼ିକ ସହିତ ଫ୍ୟୁଜ୍ କରିବା), ଏବଂ `VideoDrilldownPort` (ଫ୍ରେମ୍ ଡ୍ରିଲ୍-ଡାଉନ୍ ପର୍ସିଷ୍ଟେନ୍ସ ସୀମା; ଏପର୍ଯ୍ୟନ୍ତ `processVideoPart` ରେ ୱାୟାର୍ ହୋଇନାହିଁ — କେବଳ ପୃଥକ `/api/modality-bridge/video/drilldown` ରୁଟ୍ ଆଜି ଡ୍ରିଲ୍-ଡାଉନ୍ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ଲେଖେ)।

ପବ୍ଲିକ୍ `/v1` ଅନୁରୋଧ ପାଥ୍ କେବେ ମଧ୍ୟ ଏକ ସବ୍‌ପ୍ରୋସେସ୍ ଇମ୍ପୋର୍ଟ କରେ ନାହିଁ କିମ୍ବା ଆହ୍ୱାନ କରେ ନାହିଁ। ରିମୋଟ୍ ଭିଡିଓଗୁଡ଼ିକ `50 MiB` ବାଉଣ୍ଡ୍ ଅଧୀନରେ ଡାଉନଲୋଡ୍ ହୁଏ; ଇନଲାଇନ୍ base64 ଭିଡିଓଗୁଡ଼ିକର ଏକ ରକ୍ଷଣଶୀଳ `36 MiB` ଡିକୋଡ୍ ହୋଇଥିବା ପ୍ରତି-ଭିଡିଓ କ୍ୟାପ୍ ଅଛି ଯାହାଫଳରେ ମଡେଲ୍/ବାର୍ତ୍ତା/ଫ୍ରେମିଂ ଏନଭଲପ୍ `50 MiB` ର ପବ୍ଲିକ୍ JSON ଅନୁରୋଧ ଆଡମିଶନ ସୀମା ଭିତରେ ରହିପାରିବ। ଆଲୋକେସନ୍ ପୂର୍ବରୁ ଇନଲାଇନ୍ ଦୈର୍ଘ୍ୟ ଏବଂ ଡିକୋଡ୍ ହୋଇଥିବା-ଆକାର ଆକଳନ ଯାଞ୍ଚ କରାଯାଏ। ପ୍ରାରମ୍ଭିକ ରିମୋଟ୍ URL ଏବଂ ପ୍ରତ୍ୟେକ ରେଡିରେକ୍ଟରେ HTTPS ଆବଶ୍ୟକ, ଯାହା DNS ପିନିଂ ସହିତ ବିଦ୍ୟମାନ କେବଳ-ପବ୍ଲିକ୍ ଆଉଟ୍‌ବାଉଣ୍ଡ୍ ଗାର୍ଡ ବ୍ୟବହାର କରେ। ଏହାପରେ ବାଇଟ୍ସଗୁଡ଼ିକ ସଠିକ୍ ଆଭ୍ୟନ୍ତରୀଣ `POST /api/modality-bridge/video/extract` ବ୍ରୋକର ସୀମା ଅତିକ୍ରମ କରେ। ସେହି ରୁଟ୍ ଉଭୟ `LOCAL_ONLY` ଏବଂ `SPAWN_CAPABLE` ଅଟେ, କେବଳ ଏକ ପ୍ରୋସେସ୍-ପ୍ରତି ପ୍ରମାଣିତ, ବିଶ୍ୱାସନୀୟ-ଲୁପବ୍ୟାକ୍ ଅନୁରୋଧ ଗ୍ରହଣ କରେ, ଏବଂ କେବେ ମଧ୍ୟ ଏକ URL, ଫାଇଲ୍ ସିଷ୍ଟମ୍ ପାଥ୍, ଏକ୍ସକ୍ୟୁଟେବଲ୍, କିମ୍ବା ଆର୍ଗୁମେଣ୍ଟ ତାଲିକା ଗ୍ରହଣ କରେ ନାହିଁ। API ବଡି-ସାଇଜ୍ ପାଇପ୍‌ଲାଇନ୍ ଏବଂ ହାଣ୍ଡଲର୍‌ର ଇନକ୍ରିମେଣ୍ଟାଲ୍ ବଡି ରିଡର୍ ସ୍ୱାଧୀନ ଭାବରେ `50 MiB` ବ୍ରୋକର ଇନପୁଟ୍ କ୍ୟାପ୍ କାର୍ଯ୍ୟକାରୀ କରନ୍ତି। ଏହାର ସୀମିତ କ୍ୟୁ ଏକ ସମୟରେ ଗୋଟିଏ ଏକ୍ସଟ୍ରାକ୍ସନ୍ ଚଲାଏ, ଚାରୋଟି ପେଣ୍ଡିଂ ଜବ୍ ଅନୁମତି ଦିଏ, ଏବଂ `100 MiB` ରେ ପେଣ୍ଡିଂ ଇନପୁଟ୍ କ୍ୟାପ୍ କରେ।

ବ୍ରୋକର ମଧ୍ୟରେ, `ffprobe` ଏକ ବ୍ୟକ୍ତିଗତ ଲୋକାଲ୍ ଫାଇଲ୍ ପଢ଼େ; ସ୍ଥିର ଫର୍ମାଟ୍ ଆଲୋୱଲିଷ୍ଟ୍ ପ୍ଲେଲିଷ୍ଟ୍ ଏବଂ ମାନିଫେଷ୍ଟ୍ ଫର୍ମାଟ୍ଗୁଡ଼ିକୁ ବାଦ ଦିଏ। ଅନୁମତିପ୍ରାପ୍ତ MOV-ପରିବାର କଣ୍ଟେନର୍ ପାଇଁ, ବାହ୍ୟ MOV ଡାଟା ରେଫରେନ୍ସଗୁଡ଼ିକ ଡିଫଲ୍ଟ ଭାବରେ ଅକ୍ଷମ ରହେ, ଏବଂ ସ୍ଥିର କମାଣ୍ଡ୍ ସେଗୁଡ଼ିକୁ ସକ୍ରିୟ କରେ ନାହିଁ। `ffprobe` ଏବଂ `ffmpeg` ଉଭୟ `file`-ମାତ୍ର ପ୍ରୋଟୋକଲ୍ ହ୍ୱାଇଟ୍‌ଲିଷ୍ଟ୍, ଗୋଟିଏ ଥ୍ରେଡ୍, ସ୍ଥିର ଆର୍ଗୁମେଣ୍ଟ ଆରେ, କୌଣସି ସେଲ୍ ନାହିଁ, ଏବଂ `PATH` ରୁ ରିଜଲ୍ଭ ହୋଇଥିବା ଏକ୍ଜିକ୍ୟୁଟେବଲ୍ ବ୍ୟବହାର କରନ୍ତି। ସଂଲଗ୍ନ-ଚିତ୍ର କଭର୍ ଷ୍ଟ୍ରିମ୍ଗୁଡ଼ିକ ପ୍ଲେ-ଯୋଗ୍ୟ ପ୍ରାର୍ଥୀ ନୁହଁନ୍ତି। ସମସ୍ତ ପ୍ଲେ-ଯୋଗ୍ୟ ଷ୍ଟ୍ରିମ୍ଗୁଡ଼ିକ ସୀମା ପୂରଣ କରିବା ଆବଶ୍ୟକ, ଏବଂ ଡିଟର୍ମିନିଷ୍ଟକ୍ ସବୁଠାରୁ କମ୍-ଇଣ୍ଡେକ୍ସ ଫଲବ୍ୟାକ୍ ପୂର୍ବରୁ ଏକ ସ୍ପଷ୍ଟ ଡିଫଲ୍ଟ ଷ୍ଟ୍ରିମ୍ ପସନ୍ଦ କରାଯାଏ। ଭିଡିଓଗୁଡ଼ିକ ୬୦୦ ସେକେଣ୍ଡ, ପ୍ରତି ଡାଇମେନ୍ସନ୍ ୮,୧୯୨ ପିକ୍ସେଲ୍, ଏବଂ ୩୩,୫୫୪,୪୩୨ ସୋର୍ସ ପିକ୍ସେଲ୍ ମଧ୍ୟରେ ସୀମିତ। FFmpeg ୧–୧୬ ମଧ୍ୟଭାଗର JPEG ଫ୍ରେମ୍ ସାମ୍ପଲ୍ କରେ, ଛୋଟ ଇନପୁଟ୍ଗୁଡ଼ିକୁ ଅପସ୍କେଲ୍ ନକରି ଲମ୍ବା ଧାରକୁ ସର୍ବାଧିକ ୧,୦୨୪ ପିକ୍ସେଲ୍ ପର୍ଯ୍ୟନ୍ତ ଛୋଟ କରେ, ଏବଂ କେବେ ମଧ୍ୟ URL ଗ୍ରହଣ କରେ ନାହିଁ। ସାମ୍ପଲିଂ ଡିଫଲ୍ଟ ଭାବରେ `uniform` ଅଟେ। ଇଚ୍ଛାଧୀନ `scene_aware` ଏବଂ ପରୀକ୍ଷାମୂଳକ `segment_aware` ନୀତିଗୁଡ଼ିକ ପୂର୍ବରୁ ଯାଞ୍ଚ ହୋଇଥିବା ଲୋକାଲ୍ ଷ୍ଟ୍ରିମ୍ ଉପରେ ଆଉ ଏକ ଅତିରିକ୍ତ ସ୍ଥିର FFmpeg ପାସ୍ କରିଥାଏ, ସୀମାବଦ୍ଧ `showinfo` ସିନ୍ ଟାଇମ୍‌ଷ୍ଟାମ୍ପଗୁଡ଼ିକୁ ଚୟନ କରିଥାଏ, ଏବଂ ଡିଟେକ୍ଟର୍ ବିଫଳତା, ଟାଇମ୍‌ଆଉଟ୍, ତ୍ରୁଟିପୂର୍ଣ୍ଣ ଆଉଟପୁଟ୍, କିମ୍ବା ଖାଲି ପ୍ରାର୍ଥୀ ସେଟ୍ କ୍ଷେତ୍ରରେ ସେହି ସମାନ ୟୁନିଫର୍ମ ମଧ୍ୟଭାଗକୁ ଡିଟର୍ମିନିଷ୍ଟକ୍ ଭାବରେ ଫଲବ୍ୟାକ୍ କରିଥାଏ। ସେଗମେଣ୍ଟ-ସଚେତନ ମୋଡ୍ ଯାଞ୍ଚ ହୋଇଥିବା ସିନ୍ ଅନ୍ତର୍ଭୁକ୍ତି ସହିତ ସମାନୁପାତିକ ଭାବରେ ମଧ୍ୟଭାଗର ସାମ୍ପଲ୍ ଆବଣ୍ଟନ କରେ; ସେଗମେଣ୍ଟ-ସଚେତନ ପ୍ରମାଣ ଏବଂ ଫଲବ୍ୟାକ୍ ଆଚରଣ ନିମ୍ନରେ ବିସ୍ତୃତ ଭାବରେ ବର୍ଣ୍ଣନା କରାଯାଇଛି। କଠିନ 16-ଫ୍ରେମ୍ କ୍ଯାପ୍ ପ୍ରତ୍ୟେକ ନୀତିରେ ଚୟନ ପରେ ପ୍ରୟୋଗ କରାଯାଏ। ଯେତେବେଳେ ଏକ ସିନ୍-ସଚେତନ ଅନୁରୋଧର କେବଳ ଗୋଟିଏ-ଫ୍ରେମ୍ ବଜେଟ୍ ଥାଏ, ଏହା ସକ୍ରିୟ ସମ୍ପୂର୍ଣ୍ଣ-ଭିଡିଓ କିମ୍ବା ଫୋକସ୍ ୱିଣ୍ଡୋର ୟୁନିଫର୍ମ ମଧ୍ୟଭାଗ ବ୍ୟବହାର କରେ ଏବଂ `policyEffective: uniform` ରିପୋର୍ଟ କରେ: ଏକକ ଚୟନିତ ସିନ୍ ଫ୍ରେମ୍ ଉଭୟ ଟେମ୍ପୋରାଲ୍ ପ୍ରାନ୍ତକୁ ସଂରକ୍ଷଣ କରିପାରିବ ନାହିଁ। ଜଣେ କଲର୍ ଇଚ୍ଛାଧୀନ ଭାବରେ ଏକ ସୀମିତ ଫୋକସ୍ ୱିଣ୍ଡୋ (`start`/`end` ସେକେଣ୍ଡ) ପ୍ରଦାନ କରିପାରନ୍ତି; ସୀମାଗୁଡ଼ିକୁ ମିଡିଆ ଅବଧି ସହିତ କ୍ଲ୍ୟାମ୍ପ୍ କରାଯାଇଥାଏ, ଓଲଟା କିମ୍ବା ଅସୀମିତ ୱିଣ୍ଡୋଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ, ଏବଂ ସମସ୍ତ ସାମ୍ପଲିଂ ନୀତିଗୁଡ଼ିକ କେବଳ ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ଇଣ୍ଟରଭାଲ୍ ଭିତରେ କରାଯାଇଥାଏ। ଫଳସ୍ୱରୂପ ୱିଣ୍ଡୋକୁ ସାମ୍ପଲିଂ ମେଟାଡାଟାରେ ଏବଂ ଅବିଶ୍ୱସନୀୟ ବର୍ଣ୍ଣନା ପ୍ରିଫିକ୍ସରେ ଅନ୍ତର୍ଭୁକ୍ତ କରାଯାଇଥାଏ ଯାହାଫଳରେ ଡାଉନଷ୍ଟ୍ରିମ୍ ମଡେଲଗୁଡ଼ିକ ସମ୍ପୂର୍ଣ୍ଣ ଟାଇମଲାଇନ୍ଠାରୁ ଏକ ଫୋକସ୍ ହୋଇଥିବା ଏକ୍ସର୍ପଟ୍କୁ ପୃଥକ୍ କରିପାରିବେ।

ସେମାଣ୍ଟିକ୍ କ୍ୟାପ୍ସନ୍ ଫୋକସ୍ ହେଉଛି ଏକ ପୃଥକ୍, ସ୍ପଷ୍ଟ ସେଟିଂ। ଡିଫଲ୍ଟ `full` ବିଶ୍ଳେଷଣ ମୋଡ୍ ବିଦ୍ୟମାନ ଫ୍ରେମ୍ ପ୍ରୋମ୍ପଟ୍କୁ ସଂରକ୍ଷଣ କରେ ଏବଂ କେବେ ମଧ୍ୟ ଅନୁରୋଧ ଟେକ୍ସଟ୍କୁ କ୍ୟାପ୍ସନ୍ ମଡେଲକୁ ଫରୱାର୍ଡ କରେ ନାହିଁ। `focused` ମୋଡ୍ରେ, ବ୍ରିଜ୍ ସେହି ସମାନ ଚାଟ୍ କିମ୍ବା ରେସ୍ପନ୍ସେସ୍ କଣ୍ଟେନର୍ରୁ କେବଳ ସବୁଠାରୁ ଶେଷ ଅଣ-ଖାଲି ୟୁଜର୍-ରଚିତ `text`/`input_text` ପଢ଼େ, ଏହାକୁ NFC କୁ ନର୍ମାଲାଇଜ୍ କରେ, କଣ୍ଟ୍ରୋଲ୍ କ୍ୟାରେକ୍ଟର୍ ଏବଂ ହ୍ୱାଇଟ୍‌ସ୍ପେସ୍କୁ ସଙ୍କୁଚିତ କରେ, ଏବଂ ଏହାକୁ 500 ୟୁନିକୋଡ୍ କୋଡ୍ ପଏଣ୍ଟରେ ସୀମିତ କରେ। ଏକ ଖାଲି ଫଳାଫଳଠାରୁ ସଠିକ୍ `full` ପ୍ରୋମ୍ପଟ୍ କୁ ଫଲବ୍ୟାକ୍ ହୁଏ। ଏକ ବ୍ୟବହାରଯୋଗ୍ୟ ହିଣ୍ଟ୍ ଏକ ଉତ୍ସର୍ଗୀକୃତ ଅବିଶ୍ୱସନୀୟ-ବ୍ୟବହାରକାରୀ-ପ୍ରସଙ୍ଗ ବ୍ଲକ୍ରେ JSON ଭାବରେ ସିରିଏଲାଇଜ୍ ହୋଇଥାଏ ଏବଂ କେବଳ ପର୍ଯ୍ୟବେକ୍ଷଣଯୋଗ୍ୟ ବିବରଣୀଗୁଡ଼ିକୁ ପ୍ରାଥମିକତା ଦେଇପାରେ; ଏହା ମିଡିଆରେ ଦୃଶ୍ୟମାନ କିମ୍ବା ଶ୍ରବଣଯୋଗ୍ୟ ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକୁ ଅନୁସରଣ କରିବା ବିରୁଦ୍ଧରେ ଥିବା ପୃଥକ୍ ଚେତାବନୀକୁ ଓଭରରାଇଡ୍ କରିପାରିବ ନାହିଁ। ଟେକ୍ସଟୁଆଲ୍ ଫୋକସ୍ କେବେ ମଧ୍ୟ `start`/`end` ଅନୁମାନ କରେ ନାହିଁ କିମ୍ବା ଟେମ୍ପୋରାଲ୍ ସାମ୍ପଲର୍ ପରିବର୍ତ୍ତନ କରେ ନାହିଁ।

#### FU-07 ଗଠନଗତ ସେଗମେଣ୍ଟ ପ୍ରମାଣ

`segment_aware` ପୂର୍ବରୁ ଯାଞ୍ଚ ହୋଇଥିବା ଲୋକାଲ୍ ଭିଡିଓ ଷ୍ଟ୍ରିମ୍ ଉପରେ ଗୋଟିଏ ସୀମାବଦ୍ଧ ପ୍ରି-ଆନାଲିସିସ୍ ପାସ୍ ବ୍ୟବହାର କରେ। ସ୍ଥିର ଫିଲ୍ଟର୍ ଚେନ୍ ପ୍ରଥମେ ସର୍ବାଧିକ 320 ପିକ୍ସେଲ୍ ଚଉଡ଼ାକୁ ସ୍କେଲ୍ କରେ, ସିନ୍ ପରିବର୍ତ୍ତନ ଏବଂ ଫ୍ରୋଜେନ୍ ଇଣ୍ଟରଭାଲଗୁଡ଼ିକୁ ଡିଟେକ୍ଟ କରେ, ତା’ପରେ ବ୍ଲର୍, ହାରାହାରି ଲୁମା, ଏବଂ ସ୍ପେସିଆଲ୍/ଟେମ୍ପୋରାଲ୍ ସୂଚନା ପାଇଁ ପ୍ରତି ସେକେଣ୍ଡରେ 1 ଫ୍ରେମ୍ ରେଟ୍ରେ ସାମ୍ପଲ୍ କରେ। ଏହି ପାସ୍ 600 ଗଠନଗତ ସାମ୍ପଲ୍, ଗୋଟିଏ FFmpeg/ଫିଲ୍ଟର୍ ଥ୍ରେଡ୍, ସେହି ସମାନ `file`-ମାତ୍ର ପ୍ରୋଟୋକଲ୍ ଏବଂ କଣ୍ଟେନର୍ ଆଲୋୱଲିଷ୍ଟ୍, 1 MiB ପ୍ରୋସେସ୍-ଆଉଟପୁଟ୍ ସୀମା, ଏବଂ ବ୍ରୋକରର ସାମୂହିକ ବନ୍ଦ/ଡେଡ୍‌ଲାଇନ୍ ଭିତରେ ସର୍ବାଧିକ 30 ସେକେଣ୍ଡ ମଧ୍ୟରେ ସୀମିତ। ଏହା ଅନୁରୋଧରୁ କୌଣସି କମାଣ୍ଡ୍, ଫିଲ୍ଟର୍, ପାଥ୍, କିମ୍ବା URL କେବେ ମଧ୍ୟ ଗ୍ରହଣ କରେ ନାହିଁ।

ଗଠନଗତ ମୂଲ୍ୟଗୁଡ଼ିକ ହେଉଛି ଡିଟର୍ମିନିଷ୍ଟକ୍ ସାମ୍ପଲିଂ ପ୍ରମାଣ, ସେମାଣ୍ଟିକ୍ ଭିଡିଓ ବୁଝାମଣା ନୁହେଁ। ସେଗୁଡ଼ିକ ବିଷୟବସ୍ତୁ, କାର୍ଯ୍ୟ, କ୍ୟାପ୍ସନ୍, ସ୍ପିଚ୍, କିମ୍ବା ୟୁଜର୍ ଇଣ୍ଟେଣ୍ଟ୍ ଅନୁମାନ କରନ୍ତି ନାହିଁ। ସିନ୍ ଏବଂ ଫ୍ରିଜ୍ ସୀମାଗୁଡ଼ିକ ସେଗମେଣ୍ଟ ଗଠନ କରେ; ଫ୍ରିଜ୍ କଭରେଜ୍, ବ୍ଲର୍, ଏକ୍ସପୋଜର୍, ସ୍ପେସିଆଲ୍ ଡିଟେଲ୍, ଏବଂ ଟେମ୍ପୋରାଲ୍ ପରିବର୍ତ୍ତନ କେବଳ ବିଦ୍ୟମାନ 1–16 ଫ୍ରେମ୍ ବଜେଟ୍ କିପରି ଆବଣ୍ଟନ କରାଯାଏ ତାହା ପ୍ରଭାବିତ କରେ। ଏକ ସମ୍ପୂର୍ଣ୍ଣ ଫ୍ରୋଜେନ୍ ସେଗମେଣ୍ଟ ଏକ ଫ୍ରେମ୍ରେ ସୀମିତ, ଯେତେବେଳେ କି ଅନ୍ୟାନ୍ୟ ଅଣ-ଫ୍ରୋଜେନ୍ ସେଗମେଣ୍ଟଗୁଡ଼ିକ ବାକି ବଜେଟ୍ ପାଇଁ ପ୍ରତିଯୋଗିତା କରନ୍ତି। ଯେତେବେଳେ ସୀମାଗୁଡ଼ିକ ଫ୍ରେମ୍ ତୁଳନାରେ ଅଧିକ ହୁଏ, ସମାନ ଟାଇମଲାଇନ୍ କଭରେଜ୍ ବଜାୟ ରହେ ଯାହାଦ୍ୱାରା ଦ୍ରୁତ ପ୍ରାରମ୍ଭିକ କଟ୍ଗୁଡ଼ିକ ଏକ ଦୀର୍ଘ ଟ୍ରେଲିଂ ସେଗମେଣ୍ଟକୁ ଲୁଚାଇ ପାରିବ ନାହିଁ। ଫ୍ରିଜ୍ ସୀମାର 1-ସେକେଣ୍ଡ ବିଶ୍ଳେଷଣ ରିଜୋଲ୍ୟୁସନ୍ ମଧ୍ୟରେ ଥିବା ସିନ୍ ସୀମାଗୁଡ଼ିକୁ ଏକାଠି କରାଯାଇଥାଏ।

ନିଖୋଜ ଫିଲ୍ଟର୍, ତ୍ରୁଟିପୂର୍ଣ୍ଣ/ଖାଲି ପ୍ରମାଣ, ଡିଟେକ୍ଟର୍ ତ୍ରୁଟି, କିମ୍ବା ସୀମାବଦ୍ଧ ପ୍ରି-ଆନାଲିସିସ୍ ଟାଇମ୍‌ଆଉଟ୍ ସଠିକ୍ ୟୁନିଫର୍ମ ମଧ୍ୟଭାଗ ନୀତିରେ ଫେଲ୍ ଓପନ୍ ହୁଏ। ଏକ କଲର୍ ଏବୋର୍ଟ କିମ୍ବା ବ୍ରୋକର ଡେଡ୍‌ଲାଇନ୍ ଫେଲ୍ ଓପନ୍ ହୁଏ ନାହିଁ: ଏହା ଇନ୍-ଫ୍ଲାଇଟ୍ ସବପ୍ରୋସେସ୍ ସମାପ୍ତ କରେ, ପରବର୍ତ୍ତୀ ଫ୍ରେମ୍ ଏକ୍ସଟ୍ରାକ୍ସନ୍ କୁ ରୋକେ, ଏବଂ ବ୍ୟକ୍ତିଗତ ଅସ୍ଥାୟୀ ଟ୍ରି କୁ `finally` ରେ ହଟାଇ ଦିଆଯାଏ।

`scripts/perf/video-bridge-fu07-eval.ts` ପୋଷ୍ଟ-ଡେଡପ୍ କ୍ୟାପ୍ସନ୍-କଲ୍ ସଞ୍ଚୟ, ଡେନ୍ସ-ମୋସନ୍ ବଜେଟ୍ ଆବଣ୍ଟନ, ବ୍ଲର୍/ଏକ୍ସପୋଜର୍/SI-TI ପ୍ରମାଣ, ଏକ ଲମ୍ବା ଟେଲ୍ ସହିତ ଦ୍ରୁତ କଟ୍, ଏବଂ ଗ୍ରାଜୁଆଲ୍-ଫେଡ୍ ଫଲ୍ସ୍ ପଜିଟିଭ୍ ପାଇଁ ଡିଟର୍ମିନିଷ୍ଟକ୍ ପ୍ରକୃତ FFmpeg ଫିକ୍ସଚର୍ ଜେନେରେଟ୍ କରେ। ଏହା ପ୍ରି-ଆନାଲିସିସ୍ ୱାଲ୍ ଟାଇମ୍ ଏବଂ, ଯେଉଁଠାରେ `/usr/bin/time` ଉପଲବ୍ଧ ଅଛି, ସେଠାରେ ଚାଇଲ୍ଡ CPU ଏବଂ ପିକ୍ RSS ରେକର୍ଡ କରେ। ଏହାର କ୍ୱାଲିଟି ଚେକ୍ଗୁଡ଼ିକ କେବଳ ଗଠନଗତ ଓରାକଲ୍ ଅଟେ। ପ୍ରକୃତ କ୍ୟାପ୍ସନ୍-ମଡେଲ୍ କ୍ୱାଲିଟି `HOLD` ରହେ କାରଣ ଏହି ହାର୍ନେସ୍ର କୌଣସି ଅଧିକୃତ ଏଣ୍ଡପଏଣ୍ଟ କିମ୍ବା ଫ୍ରୋଜେନ୍ ଜଜ୍ ନାହିଁ। ମୌଦ୍ରିକ ସଞ୍ଚୟ ମଧ୍ୟ `HOLD` ରହେ ଯେପର୍ଯ୍ୟନ୍ତ `--caption-cost-per-call-usd` ଏକ ସ୍ପଷ୍ଟ ସକରାତ୍ମକ ପ୍ରତି-କଲ୍ ଆକଳନ ପ୍ରଦାନ ନ କରେ; ସ୍କ୍ରିପ୍ଟ କେବେ ମଧ୍ୟ କୌଣସି ଫଳାଫଳ ତିଆରି କରେ ନାହିଁ।

ପ୍ରତ୍ୟେକ ଫ୍ରେମ୍ 4 MiB ରେ ସୀମିତ, ସମସ୍ତ କଞ୍ଚା ଫ୍ରେମ୍ ମିଶି 23 MiB, ଏବଂ ସିରିଆଲାଇଜଡ୍ ବ୍ରୋକର ପ୍ରତିକ୍ରିୟା 32 MiB ରେ ସୀମିତ। ଏକ ପ୍ରାଇଭେଟ୍ ଅସ୍ଥାୟୀ ଡାଇରେକ୍ଟୋରୀକୁ `finally` ରେ ହଟାଇ ଦିଆଯାଏ। OmniRoute, FFmpeg କୁ ବଣ୍ଡଲ୍ କରେ ନାହିଁ ଏବଂ ଏକ କଷ୍ଟମ୍ ଏକଜିକ୍ୟୁଟେବଲ୍ ପାଥ୍ ଗ୍ରହଣ କରେ ନାହିଁ। କ୍ୟାପ୍‌ସନିଂ ପୂର୍ବରୁ, ବ୍ରିଜ୍ ଏକ ରକ୍ଷଣଶୀଳ ଭିଜୁଆଲ୍ ଡିଡୁପ୍ଲିକେସନ୍ ପାସ୍ ପ୍ରୟୋଗ କରେ: ପ୍ରତ୍ୟେକ JPEG କୁ ଏକ 16×16 ଗ୍ରେସ୍କେଲ୍ ବଫର୍‌କୁ ହ୍ରାସ କରାଯାଏ ଏବଂ କେବଳ ଶେଷରେ ରଖାଯାଇଥିବା ଫ୍ରେମ୍ ସହିତ ତୁଳନା କରାଯାଏ। ଏକ ଫ୍ରେମ୍‌ରୁ ଅଧିକ ଅନୁରୋଧ କରାଯାଇଥିବା କ୍ୟାପ୍‌ସନ୍ ବଜେଟ୍ ପାଇଁ, ଏକ୍ସଟ୍ରାକସନ୍ ସେହି ବଜେଟ୍‌ର ଦ୍ୱିଗୁଣ ପର୍ଯ୍ୟନ୍ତ ଏବଂ କେବେବି 16 ଟି ଫ୍ରେମ୍‌ରୁ ଅଧିକ ନୁହେଁ ଏକ ସୀମିତ କାଣ୍ଡିଡେଟ୍ ପୁଲ୍ ଯୋଗାଇଥାଏ। ଅନୁରୋଧ କରାଯାଇଥିବା କ୍ୟାପ୍ କେବଳ ଡିଡୁପ୍ଲିକେସନ୍ ପରେ ପ୍ରୟୋଗ କରାଯାଏ, ଯେତେବେଳେ ବଜେଟ୍ କମ୍ରେ ଦୁଇଟି ଥାଏ ସେତେବେଳେ ଚୂଡ଼ାନ୍ତ ଥିନିଂ ସମୟରେ ପ୍ରଥମ ଏବଂ ଚୂଡ଼ାନ୍ତ ମନୋନୀତ କାଣ୍ଡିଡେଟ୍ ଗୁଡ଼ିକୁ ସଂରକ୍ଷିତ କରାଯାଇଥାଏ। ସଂସ୍କରଣଯୁକ୍ତ `grayscale-16x16-mean-cells-v2` ପଲିସି ମିନ୍ ଲୁମା ଡେଲ୍ଟା ଏବଂ ଥମ୍ବନେଲ୍ ସେଲ୍ ଗୁଡ଼ିକର ଅନୁପାତ ମଧ୍ୟରୁ ବଡ଼ଟିକୁ ବ୍ୟବହାର କରେ ଯାହାର ନର୍ମାଲାଇଜଡ୍ ଡେଲ୍ଟା କମ୍ରେ 0.05 ଅଟେ। ଡୁପ୍ଲିକେଟ୍ ଥ୍ରେସହୋଲ୍ଡ ହେଉଛି ସ୍ଥିରାଙ୍କ 0.04, ଯାହା ଏକ ରନଟାଇମ୍ ସେଟିଂ ଭାବରେ ପ୍ରକାଶ କରିବା ଅପେକ୍ଷା ପୂର୍ବାନୁମାନଯୋଗ୍ୟତା ପାଇଁ ବଛାଯାଇଛି। ଏହି ଦ୍ୱିତୀୟ ହାଇ-କଣ୍ଟ୍ରାଷ୍ଟ ସିଗ୍ନାଲ୍ ଛୋଟ ଗତି ଏବଂ ଦୃଶ୍ୟମାନ-ପାଠ୍ୟ ପରିବର୍ତ୍ତନଗୁଡ଼ିକୁ ସଂରକ୍ଷଣ କରେ ଯାହା କେବଳ-ମିନ୍ ତୁଳନା ଲୁଚାଇପାରେ। କମ୍ପାରିଟର କିମ୍ବା ଡିକୋଡର୍ ତ୍ରୁଟିଗୁଡ଼ିକ ଓପନ୍ ଫେଲ୍ ହୁଏ ଏବଂ କଭରେଜ୍ ବଜାୟ ରଖେ। ଆଉଟପୁଟ୍ ମେଟାଡାଟା ଏକ୍ସଟ୍ରାକ୍ଟ ହୋଇଥିବା କାଣ୍ଡିଡେଟ୍, ସଫଳତାର ସହିତ ବ୍ୟବହୃତ ଫ୍ରେମ୍, ଏବଂ ବାଦ ଦିଆଯାଇଥିବା ଭିଜୁଆଲ୍ ଡୁପ୍ଲିକେଟ୍ ଗୁଡ଼ିକୁ ଅଲଗା କରିଥାଏ।

ଏକ ସ୍ପଷ୍ଟ ଭାବରେ ଚିହ୍ନିତ ଭିଡିଓ ଅଂଶ ଏକ ଟାଇମଷ୍ଟାମ୍ପଡ୍ କଣ୍ଟାକ୍ଟ ସିଟ୍ ଅନୁରୋଧ କରିପାରେ। ବ୍ରିଜ୍ ସର୍ବାଧିକ 4-କଲମ୍, 16-ଫ୍ରେମ୍ JPEG ଗ୍ରିଡ୍ ନିର୍ମାଣ କରେ। ପ୍ରତ୍ୟେକ 512-ପିକ୍ସେଲ୍ ସେଲ୍ ଏହାର ସ୍ରୋତ ଟାଇମଷ୍ଟାମ୍ପକୁ ଏକ ହାଇ-କଣ୍ଟ୍ରାଷ୍ଟ ନିମ୍ନ ବ୍ୟାଣ୍ଡରେ ବର୍ଣ୍ଣ କରେ, ଯେତେବେଳେ ସମାନ ଟାଇମଷ୍ଟାମ୍ପଗୁଡ଼ିକ ଡାଉନଷ୍ଟ୍ରିମ୍ ଆସୋସିଏସନ୍ ଏବଂ ଅଡିଟ୍ ପାଇଁ ପାଠ୍ୟ ମେଟାଡାଟାରେ ରହିଥାଏ। ସମ୍ପୂର୍ଣ୍ଣ JPEG 32 MiB ରେ ସୀମିତ ରହିଥାଏ। ଯଦି `sharp` ଗ୍ରିଡ୍ ଡିକୋଡ୍ କିମ୍ବା କମ୍ପୋଜ୍ କରିପାରିବ ନାହିଁ, ତେବେ ବ୍ରିଜ୍ ବ୍ୟକ୍ତିଗତ JPEG ଫ୍ରେମ୍ ଗୁଡ଼ିକରେ ଫେରିଯାଏ; ଏକ କ୍ଲାଏଣ୍ଟ୍ ଆବର୍ଟ ସିଟ୍ ଅପରେସନ୍ ମାଧ୍ୟମରେ ମଧ୍ୟ ପ୍ରସାରିତ ହୁଏ।

ପ୍ରମୋସନ୍ ପ୍ରମାଣ ସିନ୍ଥେଟିକ୍ କମ୍ପୋଜିସନ୍ ମାଇକ୍ରୋବେଞ୍ଚମାର୍କଠାରୁ ଜାଣିଶୁଣି ଅଲଗା ଅଟେ। `scripts/perf/video-bridge-contact-sheet-eval.ts` ପ୍ରକୃତ OpenAI-ସୁସଙ୍ଗତ ଭିଜନ୍ ମଡେଲଗୁଡ଼ିକ ପାଇଁ ଏକ ସ୍କିମା-ସଂସ୍କରଣଯୁକ୍ତ A/B ହାର୍ନେସ୍ ବର୍ଣ୍ଣନା କରେ। ଏହା ପ୍ରଦାନକାରୀ-ରିପୋର୍ଟ ହୋଇଥିବା ଟୋକନ୍, ଏଣ୍ଡ୍-ଟୁ-ଏଣ୍ଡ୍ ୱାଲ୍ ଲାଟେନ୍ସି (ସିଟ୍ କମ୍ପୋଜିସନ୍ ସହିତ), ମଡେଲ୍-କଲ୍ ସଂଖ୍ୟା, ଏବଂ ମାନିଫେଷ୍ଟ-ଜଣାଶୁଣା ତଥ୍ୟ ସଂରକ୍ଷଣକୁ ମାପିଥାଏ। କଞ୍ଚା ମଡେଲ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ ରିପୋର୍ଟରେ ଲେଖାଯାଏ ନାହିଁ; କେବଳ SHA-256 ଡାଇଜେଷ୍ଟ ଏବଂ ମେଳ ହୋଇଥିବା ତଥ୍ୟ ID ଗୁଡ଼ିକୁ ସଂରକ୍ଷିତ କରାଯାଏ। ହାର୍ନେସ୍ କୌଣସି ନେଟୱାର୍କ କିମ୍ବା ପେଡ୍ ମଡେଲ୍ କଲ୍ କରେ ନାହିଁ ଯେପର୍ଯ୍ୟନ୍ତ `--execute-real` ପାସ୍ କରାଯାଏ ନାହିଁ ଏବଂ `--model`, `OMNIROUTE_BASE_URL`, ଏବଂ `OMNIROUTE_API_KEY` କନଫିଗର୍ ହୋଇନାହିଁ। ସେହି ସ୍ପଷ୍ଟ ପ୍ରକୃତ ରନ୍ ବିନା, ଏହାର ମେସିନ୍-ପାଠ୍ୟ ରାୟ `HOLD` ରହିଥାଏ; ସିନ୍ଥେଟିକ୍ ପେଲୋଡ୍/କଲ୍-ସଂଖ୍ୟା ମାପ କେବଳ ପ୍ରମୋସନ୍ ପ୍ରମାଣ ନୁହେଁ।

କଲର୍ସମାନେ ଏକ ସମର୍ଥିତ ଭିଡିଓ ଅଂଶରେ ଏକ ଇଚ୍ଛାଧୀନ `transcript.cues` ଆରେ ସଂଲଗ୍ନ କରିପାରିବେ ଯେତେବେଳେ ସେମାନଙ୍କ ପାଖରେ ପୂର୍ବରୁ ଆଲାଇନ୍ ହୋଇଥିବା ପାଠ୍ୟ ଥାଏ। ପ୍ରତ୍ୟେକ କ୍ୟୁରେ `text`, ପ୍ରୋବ୍ଡ ଅବଧି ଭିତରେ ଏକ ସୀମିତ `start`/`end` ଇଣ୍ଟରଭାଲ୍, ଏବଂ ଏକ ହ୍ୱାଇଟଲିଷ୍ଟେଡ୍ `source` (`client`, `embedded`, କିମ୍ବା `audio-bridge`) ଥିବା ଆବଶ୍ୟକ; `confidence` ଡିଫଲ୍ଟ ଭାବରେ `1` ଅଟେ ଏବଂ `0` ଏବଂ `1` ମଧ୍ୟରେ ରହିବା ଆବଶ୍ୟକ। ସଠିକ୍ ଡୁପ୍ଲିକେଟ୍ କ୍ୟୁ ଗୁଡ଼ିକୁ କୋଲାପ୍ସ କରାଯାଇଥାଏ। OmniRoute କେବେବି ଏହି ମେଟାଡାଟାରୁ ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଆରମ୍ଭ କରେ ନାହିଁ: ଭାଲିଡେଟ୍ ହୋଇଥିବା କ୍ୟୁ ଗୁଡ଼ିକୁ ସ୍ରୋତ, କନଫିଡେନ୍ସ, ଏବଂ ଇଣ୍ଟରଭାଲ୍ ସହିତ ବର୍ଣ୍ଣିତ ଫଳାଫଳରେ କପି କରାଯାଏ, ଏବଂ ଫ୍ରେମ୍ କ୍ୟାପ୍‌ସନ୍ ସହିତ ଅବିଶ୍ୱସନୀୟ ପର୍ଯ୍ୟବେକ୍ଷଣ ଭାବରେ ରେଣ୍ଡର୍ କରାଯାଏ। ଅବୈଧ, ସୀମା ବାହାରେ, କିମ୍ବା ପ୍ରୋଭେନାନ୍ସ-ମୁକ୍ତ ପାଠ୍ୟକୁ କ୍ୟାପ୍‌ସନ୍ ଷ୍ଟ୍ରିମ୍‌ରେ ମିଶାଇବା ପରିବର୍ତ୍ତେ ପ୍ରତାଖ୍ୟାନ କରାଯାଏ। ଉଭୟ ରେକ୍ୱେଷ୍ଟ-ବଡି ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଚ୍ୟାନେଲ୍ ପ୍ରଦାନ କରାଯାଇଥିବା ପ୍ରୋଭେନାନ୍ସକୁ `client` କୁ ନର୍ମାଲାଇଜ୍ କରେ, ଯେଉଁଥିରେ ସେଲ୍ଫ-ଆସର୍ଟେଡ୍ `embedded` କିମ୍ବା `audio-bridge` ଲେବଲ୍ ଅନ୍ତର୍ଭୁକ୍ତ। କେବଳ ଏକ ସର୍ଭର-ମାଲିକାନା ଆଡାପ୍ଟର୍ କୋଡ୍-ମାତ୍ର `trustedSource` ଆର୍ଗୁମେଣ୍ଟ ମାଧ୍ୟମରେ ସେହି ବିଶ୍ୱସନୀୟ ଲେବଲ୍ ଗୁଡ଼ିକୁ ଆସାଇନ୍ କରିପାରେ; ଏକ ରେକ୍ୱେଷ୍ଟ JSON ଫିଲ୍ଡ ସେହି ଆର୍ଗୁମେଣ୍ଟରେ ପହଞ୍ଚିପାରିବ ନାହିଁ। ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ପାଠ୍ୟ ଏହାର ପ୍ରୋଭେନାନ୍ସ ନିର୍ବିଶେଷରେ ଅବିଶ୍ୱସନୀୟ ମିଡିଆ-ଉତ୍ପନ୍ନ ସାମଗ୍ରୀ ହୋଇ ରହିଥାଏ, ଏବଂ କେବେବି ଅଥୋରାଇଜେସନ୍ ନିର୍ଣ୍ଣୟ କରିବା ଉଚିତ୍ ନୁହେଁ।

ଏକ ଆଡ୍‌ଭାନ୍ସଡ୍ କଲର୍ ସମାନ ଭିଡିଓ ପାଇଁ ଏକ `audioTranscript` ଟ୍ରାକ୍ ପ୍ରଦାନ କରିପାରେ; ଏହାକୁ କ୍ଲାଏଣ୍ଟ-ପ୍ରଦାନ କରାଯାଇଥିବା ପାଠ୍ୟ ଭାବରେ ବିଚାର କରାଯାଏ, ସର୍ଭର ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ର ପ୍ରମାଣ ନୁହେଁ। ଫ୍ୟୁଜନ୍ ସିମ୍ ଗୋଟିଏ ଡେଡଲାଇନ୍ ଏବଂ ଆବର୍ଟ ସିଗ୍ନାଲ୍ ଅଧୀନରେ ଭିଜୁଆଲ୍ ଏବଂ ଅଡିଓ ପର୍ଯ୍ୟବେକ୍ଷଣ ଚଲାଏ, ସେଗୁଡ଼ିକୁ ଏକ ସାଧାରଣ ଟାଇମଲାଇନ୍ରେ ଅର୍ଡର କରେ, ସଠିକ୍ ଡୁପ୍ଲିକେଟ୍ ଗୁଡ଼ିକୁ କୋଲାପ୍ସ କରେ, ଏବଂ କେବଳ ଗୋଟିଏ ପାର୍ଶ୍ୱ ସଫଳ ହେଲେ ଏକ ଆଂଶିକ ଫଳାଫଳ ରିପୋର୍ଟ କରେ। ଏକ ଅବୈଧ `audioTranscript` ସେହି ଆଂଶିକ ଫଳାଫଳକୁ ଡିଗ୍ରେଡ୍ ହୁଏ — ଭିଜୁଆଲ୍ ବର୍ଣ୍ଣନା ରଖାଯାଏ ଏବଂ ଅଡିଓ ବ୍ରାଞ୍ଚ ଏକ ସାନିଟାଇଜ୍ ଫେଲ୍ କୋଡ୍ ରେକର୍ଡ କରେ — ସମଗ୍ର ଭିଡିଓକୁ ଫେଲ୍ କରିବା ପରିବର୍ତ୍ତେ। ପ୍ରତି-ବ୍ରାଞ୍ଚ ଉପଲବ୍ଧତା, ଆଂଶିକ ଫ୍ଲାଗ୍, ଏବଂ ସାନିଟାଇଜ୍ ଫେଲ୍ କୋଡ୍ ଗୁଡ଼ିକୁ ବର୍ଣ୍ଣିତ ଫଳାଫଳରେ, ଗାର୍ଡରେଲ୍ ମେଟାଡାଟାରେ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ଫଳାଫଳ-କ୍ୟାଚ୍ ମେଟାଡାଟାରେ, ଏବଂ ବ୍ରିଜ୍ ଫ୍ୟୁଜନ୍ କାଉଣ୍ଟରରେ ସଂରକ୍ଷିତ କରାଯାଇଥାଏ। ଡିଫଲ୍ଟ ଭିଡିଓ ବ୍ରିଜ୍ ପାଥ୍ ସ୍ପିଚ୍-ଟୁ-ଟେକ୍ସଟ୍ ଆହ୍ୱାନ କରେ ନାହିଁ କିମ୍ବା ଦ୍ୱିତୀୟ ମିଡିଆ କପି ଡାଉନଲୋଡ୍ କରେ ନାହିଁ; ସେହି ସ୍ପଷ୍ଟ ଟ୍ରାକ୍ ବିନା, ଏହା କେବଳ-ଭିଡିଓ ଭାବରେ ରହିଥାଏ।

**ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ରିଟେନସନ୍ (#12150 P1).** ଭିଡିଓ ବ୍ରିଜ୍ (ଯାହା ନିଜେ ଅପ୍ଟ-ଇନ୍ ଅଟେ) ଯେକୌଣସି ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ କିଉ ରେଣ୍ଡର କଲାବେଳେ ଏହା ସ୍ୱୟଂଚାଳିତ ଭାବରେ ପ୍ରଯୁଜ୍ୟ ହୋଇଥାଏ — ଏଥିପାଇଁ କୌଣସି ପୃଥକ ରିଟେନସନ୍ ଫ୍ଲାଗ୍ ନାହିଁ। ଯେତେବେଳେ ଏକ ଅନୁରୋଧ କୌଣସି ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ କିଉ (ଏକ କଲର-ଘୋଷିତ `transcript` ବା ଏକ ଫ୍ୟୁଜଡ୍ `audioTranscript`) ରେଣ୍ଡର କରେ, ସେତେବେଳେ ଗାର୍ଡରେଲ୍ ଏହାକୁ `videoBridgeObserved` ଭାବରେ ଚିହ୍ନିତ କରେ ଏବଂ ଭିଡିଓ ବର୍ଣ୍ଣନାର ଏକ ରେଡାକ୍ଟେଡ୍ ସ୍ୟାଡୋ ପ୍ରସ୍ତୁତ କରେ — ଏକ ସମାନ ରେଣ୍ଡରିଂ ଯେଉଁଥିରେ ପ୍ରତ୍ୟେକ କିଉର ଫ୍ରି-ଟେକ୍ଟ ବଡି `[redacted-video-transcript]` ଦ୍ୱାରା ପ୍ରତିସ୍ଥାପିତ ହୋଇଥାଏ, ଏହାକୁ ଷ୍ଟ୍ରିଂ ଆସେମ୍ବଲ ହେବା ପୂର୍ବରୁ ଷ୍ଟ୍ରକଚର୍ଡ କିଉ ଫିଲ୍ଡକୁ ପ୍ରତିସ୍ଥାପିତ କରି ନିର୍ମାଣ କରାଯାଇଥାଏ (ଫ୍ଲାଟେନ୍ ହୋଇଥିବା ଟେକ୍ଟକୁ ପାର୍ସ କରି କେବେ ନୁହେଁ, ଯପରିକି କୌଣସି କିଉ ବିଷୟବସ୍ତୁ — ପ୍ରତିକୂଳ କିମ୍ବା ସାଧାରଣ, ଯେଉଁଥିରେ `]` ଯଥା `[inaudible]`/`[music]` ଧାରଣ କରିଥିବା ବଡି ଅନ୍ତର୍ଭୁକ୍ତ — ବଞ୍ଚିପାରିବ ନାହିଁ)। ପର୍ସିଷ୍ଟେଡ୍ କଲ୍-ଲଗ୍ ଅନୁରୋଧ ବଡି ପ୍ରତ୍ୟେକ ଭିଡିଓ-ଉତ୍ପନ୍ନ ଟେକ୍ଟ ପାର୍ଟକୁ ସେହି ରେଡାକ୍ଟେଡ୍ ସ୍ୟାଡୋ ସହିତ ସ୍ୱାପ୍ କରେ, ଯାହା ବିଷୟବସ୍ତୁ ସମାନତା ଦ୍ୱାରା ମେଳ ଖାଏ; `fullText` ଆଙ୍କରଟି ସମାପ୍ତ ପ୍ରି-କଲ୍ ଗାର୍ଡରେଲ୍ ପେଲୋଡ୍ ରୁ ପୁନର୍ବାର ପଢ଼ାଯାଇଥାଏ, ଯାହାଫଳରେ ପରବର୍ତ୍ତୀ ଚେନ୍ ଗାର୍ଡରେଲ୍ସ (PII ଏବଂ କ୍ରେଡେନ୍ସିଆଲ୍ ମାସ୍କର୍, ପ୍ରାଥମିକତା 10/95) ବର୍ଣ୍ଣନା ଟେକ୍ଟକୁ ସ୍ଥାନରେ ପୁନଃଲିଖନ କରିବା ପରେ ଏବଂ ସିଷ୍ଟମ-ପ୍ରମ୍ପ୍ଟ/ହାଣ୍ଡଅଫ୍/ମେମୋରୀ ଇଞ୍ଜେକ୍ସନ ମେସେଜ୍ ଆରେକୁ ପୁନଃଗଠନ କରିବା ପରେ ମଧ୍ୟ ମେଳ ସଫଳ ହୋଇଥାଏ। ମଡେଲକୁ ଅପଷ୍ଟ୍ରିମରେ ପଠାଯାଇଥିବା ବଡି ଅପରିବର୍ତ୍ତିତ ରହିଥାଏ। ଏକ ଅବଜର୍ଭଡ୍ ଅନୁରୋଧ ମଧ୍ୟ କୌଣସି ଡ୍ୟୁରେବଲ୍ ମେମୋରୀ ପପୁଲେଟ୍ କରେ ନାହିଁ (ଅନୁରୋଧ- ଏବଂ ପ୍ରତିକ୍ରିୟା-ଉତ୍ପନ୍ନ ଏକ୍ସଟ୍ରାକସନ୍ ଉଭୟ ଛାଡ଼ିଦିଆଯାଇଥାଏ), ତେଣୁ ମଡେଲର ନିଜର ପ୍ରତିକ୍ରିୟା ମେମୋରୀରେ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଟେକ୍ଟକୁ ଇକୋ କରିପାରିବ ନାହିଁ।

**Raw video fields (#12430).** ଯେତେବେଳେ ବ୍ରିଜ୍ ସକ୍ଷମ ହୋଇଥାଏ ଏବଂ ନେଟିଭ୍ ଭିଡିଓ ସପୋର୍ଟ ଅଜ୍ଞାତ କିମ୍ବା ଅନୁପସ୍ଥିତ ଥାଏ, ସେତେବେଳେ ନିର୍ଦ୍ଧାରିତ `transcript`/`audioTranscript` ଫିଲ୍ଡଗୁଡ଼ିକ ମଧ୍ୟ ବର୍ଣ୍ଣନା ବିଫଳତା କିମ୍ବା `maxVideos` ସୀମା ପରେ ମଧ୍ୟ `videoBridgeObserved` କୁ ସକ୍ରିୟ କରିଥାଏ। `null` ଏବଂ ଖାଲି ଷ୍ଟ୍ରିଂଗ୍ ଗଣନା କରାଯାଏ; ଅନୁପସ୍ଥିତ ଫିଲ୍ଡ ଏବଂ ଅଣ-ଭିଡିଓ ମେଟାଡାଟା ଗଣନା କରାଯାଏ ନାହିଁ। ରିଟେନଡ୍ କପିଗୁଡ଼ିକ ଏହି ଫିଲ୍ଡଗୁଡ଼ିକୁ ରେଡାକ୍ଟ କରନ୍ତି କିମ୍ବା ଅନୁରୋଧକୁ ବାଦ ଦିଅନ୍ତି, ଏବଂ କ୍ୟାଚ୍/ମେମୋରୀ ବାଇପାସ୍ ହୋଇଯାଏ।

ସେହି ଫଲବ୍ୟାକ୍ ପାଥରେ, ବୈଧ କଲର କିଉଗୁଡ଼ିକ ଅନମାତୃକ ପ୍ରଦାନକାରୀ ଫିଲ୍ଡ ପରିବର୍ତ୍ତେ ସମର୍ଥିତ `text`/`input_text` ପାର୍ଟ ହୋଇଯାଏ। ଉଭୟ ଅନୁରୋଧ-ପ୍ରଦାନ କରାଯାଇଥିବା ଟ୍ରାକ୍ଗୁଡ଼ିକ ଅବିଶ୍ୱାସନୀୟ `client` ଅବଜରଭେସନ୍ ଭାବରେ ରହିଥାଏ, ଏକ ସ୍ପଷ୍ଟ ଚେତାବନୀ ସହିତ ଯେ ଭିଡିଓ ବର୍ଣ୍ଣନା କରାଯାଇ ନଥିଲା ଏବଂ ଟାଇମଷ୍ଟାମ୍ପଗୁଡ଼ିକ ମିଡିଆ ବିରୁଦ୍ଧରେ ଯାଞ୍ଚ କରାଯାଇ ନଥିଲା। ବିଦ୍ୟମାନ 256-କିଉ/64-KiB ମୋଟ ଏବଂ ପ୍ରତି-କିଉ ବଜେଟ୍ ଉଭୟ ଟ୍ରାକ୍ ଉପରେ ଏକାଠି ପ୍ରଯୁଜ୍ୟ ହୋଇଥାଏ; ଟାଇମଷ୍ଟାମ୍ପଗୁଡ଼ିକ ବ୍ରୋକରଙ୍କ 600-ସେକେଣ୍ଡ୍ ସିଲିଂ ଏବଂ ଯେକୌଣସି ପ୍ରଦତ୍ତ ଫୋକସ୍ ୱିଣ୍ଡୋ ସହିତ ଖାପ ଖାଇବା ଆବଶ୍ୟକ। ଅବୈଧ ଟ୍ରାକ୍ଗୁଡ଼ିକୁ ଡିସ୍କାର୍ଡ କରାଯାଇଥାଏ, ମନଇଚ୍ଛା ଟେକ୍ଟ ଭାବରେ ଫର୍ୱାର୍ଡ କରାଯାଏ ନାହିଁ; ଏକ ବୈଧ ସିବ୍ଲିଂ ବ୍ୟବହାର କରାଯାଇପାରିବ ଯଦି ନା ସେମାନଙ୍କର ମିଳିତ ବଜେଟ୍ ଅତିକ୍ରମ ହୋଇଥାଏ। `null`/ଖାଲି ଫିଲ୍ଡ କୌଣସି ଟେକ୍ଟ ଯୋଡ଼େ ନାହିଁ। ଏହି ଫଲବ୍ୟାକ୍ ଦ୍ୱାରା କୌଣସି ମିଡିଆ ଫେଚ୍ କିମ୍ବା ଟ୍ରାନ୍ସକ୍ରିପସନ୍ ଯୋଡ଼ାଯାଏ ନାହିଁ। ଫଲବ୍ୟାକ୍ ଭିଡିଓ କେରିଅର୍ ଏବଂ ଏହାର `video_url`/`source` ଅବ୍ଜେକ୍ଟରୁ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଏକ୍ସଟେନସନ୍ ଫିଲ୍ଡଗୁଡ଼ିକୁ ହଟାଇ ଦିଆଯାଇଛି। OpenAI ୱାୟାର୍ ଆଲୋଲିଷ୍ଟ କଠିନ ରହିଥାଏ; ଅଜ୍ଞାତ-ନେଟିଭ୍ ଭିଡିଓ କେରିଅରଗୁଡ଼ିକ ଉପଲବ୍ଧ ରହିଥାଏ ଏବଂ ଜଣାଶୁଣା ଟେକ୍ଟ-ମାତ୍ର ଟାର୍ଗେଟଗୁଡ଼ିକ ସୁରକ୍ଷିତ ମାର୍କର ରଖିଥାନ୍ତି। ଷ୍ଟ୍ରକଚର୍ଡ ରେଡାକ୍ସନ୍ ସ୍ୟାଡୋ ସଂଲଗ୍ନ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଟେକ୍ଟକୁ ସୁରକ୍ଷା ଦିଏ, ଯେତେବେଳେ କି ମୂଳ କଲର-ମାଲିକାନା ଅନୁରୋଧ ଅପରିବର୍ତ୍ତିତ ରହିଥାଏ। ନେଟିଭ୍-ସମର୍ଥିତ ଟାର୍ଗେଟ୍ ଏବଂ ଅକ୍ଷମ ବ୍ରିଜ୍ଗୁଡ଼ିକ ସେମାନଙ୍କର ବିଦ୍ୟମାନ ବାଇପାସ୍ ଆଚରଣ ବଜାୟ ରଖନ୍ତି।

ଅତିରିକ୍ତ ରିଟେନଡ୍ କପିଗୁଡ଼ିକ ସେହି ସମାନ ଅବଜର୍ଭଡ୍-ରିକ୍ୱେଷ୍ଟ ସିଗନାଲ୍ ବ୍ୟବହାର କରନ୍ତି। ର କ ପ୍ରି-ଗାର୍ଡରେଲ୍ କ୍ଲାଏଣ୍ଟ-ରିକ୍ୱେଷ୍ଟ ସ୍ନାପସଟ୍, ଇନ୍-ମେମୋରୀ ପେଣ୍ଡିଂ ରିକ୍ୱେଷ୍ଟ, ଏବଂ ପ୍ରାରମ୍ଭିକ ରିଜେକ୍ଟେଡ୍-ରିକ୍ୱେଷ୍ଟ ଲଗ୍ ଭିଡିଓ ପାର୍ଟଗୁଡ଼ିକରେ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ଫିଲ୍ଡଗୁଡ଼ିକୁ ଗଠନମୂଳକ ଭାବରେ ପ୍ରତିସ୍ଥାପିତ କରେ; ପାଇପଲାଇନ୍ ଷ୍ଟେଜ୍ ଏବଂ କଣ୍ଟେକ୍ଟ ହାଣ୍ଡଅଫ୍ ଦ୍ୱାରା ସିନ୍ଥେସାଇଜ୍ ହୋଇଥିବା ଷ୍ଟ୍ରିଂ ପ୍ରମ୍ପ୍ଟଗୁଡ଼ିକୁ ପର୍ସିଷ୍ଟେଡ୍-ରିକ୍ୱେଷ୍ଟ-ବଡି ସିଙ୍କ୍ ରେ ରେଡାକ୍ଟ କରାଯାଇଥାଏ। ପର୍ସିଷ୍ଟେଡ୍ `video_content_removed` ମାର୍କରଟି `previous_response_id` କଣ୍ଟିନୁଏସନକୁ ଜାଣିଶୁଣି ଡିସ୍କାର୍ଡ କରାଯାଇଥିବା ଟେକ୍ଟକୁ ପୁନଃନିର୍ମାଣ କରିବା ପରିବର୍ତ୍ତେ ବନ୍ଦ କରିବାରେ ବିଫଳ କରାଏ। ଯଦି ଏକ ଅବଜର୍ଭଡ୍ ଅନୁରୋଧ ଲଗିଂ ହେବା ପୂର୍ବରୁ ଏହାର ପର୍-ପାର୍ଟ ରେଡାକ୍ସନ୍ ସ୍ୟାଡୋ ହରାଇଥାଏ, କିମ୍ବା ପରବର୍ତ୍ତୀ ଅନୁରୋଧ ମ୍ୟୁଟେସନ୍ ପରେ ଅନେକ ଭିଡିଓ ସ୍ୟାଡୋ ମଧ୍ୟରୁ ଗୋଟିଏ ମଧ୍ୟ ମେଳ ଖାଇବାରେ ବିଫଳ ହୁଏ, ତେବେ ଏକ ଆଂଶିକ ରେଡାକ୍ଟେଡ୍ ଟ୍ରାନ୍ସକ୍ରିପ୍ଟ ରଖିବା ପରିବର୍ତ୍ତେ ରିଟେନଡ୍ ଅନୁରୋଧ ବଡିକୁ ସମ୍ପୂର୍ଣ୍ଣ ରୂପେ ବାଦ ଦିଆଯାଇଥାଏ।

ଏକ ଅବଜର୍ଭଡ୍ ଅନୁରୋଧ ପାଇଁ, ଏକ ମଡେଲ୍ ପ୍ରତିକ୍ରିୟା ଏକ ଷ୍ଟ୍ରକଚର୍ଡ କିଉ ବାଉଣ୍ଡାରୀ ବିନା ଟ୍ରାନ୍ସକ୍ରିପ୍ଟର ଯେକୌଣସି ଅଂଶକୁ କୋଟ୍ କରିପାରେ। ତେଣୁ ଏହାର ପର୍ସିଷ୍ଟେଡ୍ କଲ୍-ଲଗ୍ `responseBody` କୁ ଏକ ଓମିଶନ ମାର୍କର ଦ୍ୱାରା ପ୍ରତିସ୍ଥାପିତ କରାଯାଇଥାଏ; ବିସ୍ତୃତ ପାଇପଲାଇନ୍ ଆର୍ଟିଫାକ୍ଟ (ଯେଉଁଥିରେ ଅପଷ୍ଟ୍ରିମ/କ୍ଲାଏଣ୍ଟ ବଡି ଏବଂ ଷ୍ଟ୍ରିମ୍ ଚଙ୍କ୍ ଅନ୍ତର୍ଭୁକ୍ତ ହୋଇପାରେ) ରିଟେନ୍ କରାଯାଇ ନାହିଁ। ସେମାଣ୍ଟିକ, ଆଇଡୋପୋଟେନ୍ସି, ଏବଂ ରିଜନିଂ-ରିପ୍ଲେ କ୍ୟାଚ୍ ସେହି ଅନୁରୋଧ ପାଇଁ ପଢ଼ିବା ଏବଂ ଲେଖିବାକୁ ବାଇପାସ୍ କରେ। ପ୍ରଦାନକାରୀ ଅନୁରୋଧ ଏବଂ କ୍ଲାଏଣ୍ଟ-ଦୃଶ୍ୟମାନ ପ୍ରତିକ୍ରିୟା ଅପରିବର୍ତ୍ତିତ ରହିଥାଏ। ବିସ୍ତୃତ ଆର୍ଟିଫାକ୍ଟ ବାଦ ଦିଆଯିବା ସମୟରେ ପ୍ରାରମ୍ଭିକ କିପ୍-ଆଲାଇଭ୍ ବାଇଟ୍ଗୁଡ଼ିକୁ ଅସ୍ଥାୟୀ ବଫରରୁ ଡ୍ରେନ୍ କରାଯାଇଥାଏ। Kiro ର ମାଲଫର୍ମଡ୍ EventStream ଚେତାବନୀ କେବଳ ପେଲୋଡ୍ ବାଇଟ୍ ଗଣନା ରିପୋର୍ଟ କରେ, ଏହାର ମାତ୍ରା କିମ୍ବା JSON ପାର୍ସରର ର କ ଏରୋର୍ କେବେ ମଧ୍ୟ ନୁହେଁ।
ଏହା ଦାବି କରେ ନାହିଁ ଯେ ପ୍ରତ୍ୟେକ ଅସମ୍ପୃକ୍ତ ପ୍ରଦାନକାରୀ/ପ୍ଲଗଇନ୍ ଡାଏଗ୍ନୋଷ୍ଟିକ୍ ଅଡିଟ୍ କରାଯାଇଛି; ବ୍ୟାପକ ରିଟେନଡ୍-ସିଙ୍କ୍ ସୁଇପ୍ #11658 ରେ ଟ୍ରାକ୍ କରାଯାଇଛି।

ଆଭ୍ୟନ୍ତରୀଣ `/api/modality-bridge/video/drilldown` ଲାଇଫସାଇକେଲ୍ ହେଉଛି ଏକ ପୃଥକ, ଲୁପ୍ବ୍ୟାକ୍/ଟୋକନ୍-ପ୍ରମାଣିତ କ୍ୟାଚ୍ ସବ୍ଷ୍ଟ୍ରେଟ୍। ପ୍ରତ୍ୟେକ ଅପରେସନ୍ ପାଇଁ ଏକ କାନୋନିକାଲ୍ ଓପେକ୍ ପ୍ରିନ୍ସିପାଲ୍ ID ମଧ୍ୟ ଆବଶ୍ୟକ ହୋଇଥାଏ। ଏକ ପ୍ରଡକ୍ସନ୍ କଲର ସକ୍ଷମ ହେବା ପୂର୍ବରୁ, ଏହାକୁ ପ୍ରମାଣିତ ଟେନେଣ୍ଟରୁ ସେହି ID ଡରାଇଭ୍ କରିବାକୁ ପଡିବ ଏବଂ କ୍ଲାଏଣ୍ଟ-ଚୟନିତ ମୂଲ୍ୟ କେବେବି ଫର୍ୱାର୍ଡ କରିବା ଉଚିତ ନୁହେଁ। କ୍ୟାଚ୍ କିଗୁଡ଼ିକ ସେହି ପ୍ରିନ୍ସିପାଲ୍ କୁ କାନୋନିକାଲ୍ ସେସନ୍ ଏବଂ ଭିଡିଓ-ରେଫରେନ୍ସ ID ସହିତ ବାନ୍ଧିଥାଏ, କେବଳ ସେମାନଙ୍କର SHA-256-ଡରାଇଭ୍ କିଗୁଡ଼ିକୁ ଷ୍ଟୋର୍ କରେ, ଏବଂ ସମାନ ପ୍ରିନ୍ସିପାଲ୍ ପାଇଁ ଉଭୟ ରିଡ୍ ଏବଂ ଡିଲିସନ୍ ସ୍କୋପ୍ କରେ। କ୍ୟାଚ୍ ପ୍ରତି ଏଣ୍ଟ୍ରିରେ ସର୍ବାଧିକ 16ଟି ଡରାଇଭ୍ JPEG ଫ୍ରେମ ସଂରକ୍ଷଣ କରେ, ଦଶ ମିନିଟ୍ ପରେ ସେଗୁଡ଼ିକର ମହଚ୍ଚ ଅନ୍ତ ଘଟାଏ, ଏବଂ ବାଉଣ୍ଡେଡ୍ `start`/`end` ରିଡ୍ କିମ୍ବା ସ୍ପଷ୍ଟ ସେସନ୍ ଡିଲିସନ୍ କୁ ସମର୍ଥନ କରେ।

ପ୍ରତ୍ୟେକ ପ୍ରିନ୍ସିପାଲ୍ 16ଟି ଏଣ୍ଟ୍ରି ଏବଂ 64 MiB କାନୋନିକାଲ୍ JPEG ଡାଟା ମଧ୍ୟରେ ସୀମିତ। ସେହି ସୀମାଗୁଡ଼ିକ ଗ୍ଲୋବାଲ୍ 64-ଏଣ୍ଟ୍ରି/256 MiB ସିଲିଂଠାରୁ ସ୍ୱାଧୀନ ଅଟେ: ପ୍ରିନ୍ସିପାଲ୍ କୋଟା ଚାପ ବିଶ୍ୱବ୍ୟାପୀ LRU ଏଭିକ୍ସନ୍ ବିଚାର କରାଯିବା ପୂର୍ବରୁ କେବଳ ସେହି ପ୍ରିନ୍ସିପାଲ୍ର ସବୁଠାରୁ କମ୍-ବ୍ୟବହୃତ (least-recently-used) ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ଏଭିକ୍ଟ କରେ। କ୍ୟାଚ୍ କାର୍ଯ୍ୟକଳାପ ଉପରେ ମହଚ୍ଚ ସମାପ୍ତ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ପ୍ରିନ୍ସିପାଲ୍ ଏବଂ ଗ୍ଲୋବାଲ୍ ଆକାଉଣ୍ଟିଂ ଉଭୟରୁ ସୁଇପ୍ କରାଯାଇଥାଏ, ଯେତେବେଳେ କି କାନ୍ସେଲେସନ୍ ଏବଂ ଭାଲିଡେସନ୍ ବିଫଳତା ଏକ ଆଂଶିକ ପ୍ରତିସ୍ଥାପନକୁ କମିଟ୍ କରେ ନାହିଁ।

କ୍ୟାଚ୍ ଅଣ-କାନୋନିକାଲ୍ Base64, ଅତିରିକ୍ତ ପ୍ୟାଡିଂ, ଅଣ-JPEG ମିଡିଆ, ତ୍ରୁଟିପୂର୍ଣ୍ଣ କିମ୍ବା କଟା ଯାଇଥିବା JPEG, ଏବଂ ସୀମିତ ସମ୍ପୂର୍ଣ୍ଣ-ଚିତ୍ର `sharp` ଡିକୋଡିଂ ସମୟରେ ଚେତାବନୀ ସୃଷ୍ଟି କରୁଥିବା JPEG ଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। ଏହା ପ୍ରତ୍ୟେକ ଗ୍ରହଣ କରାଯାଇଥିବା ପ୍ରତିଛବିକୁ ଏକ କାନୋନିକାଲ୍ JPEG ଭାବରେ ପୁନଃ-ଏକୋଡ୍ କରେ, କଲର୍ ଫିଲ୍ଡଗୁଡ଼ିକ ଉପରେ ଭରସା ନକରି ଡିକୋଡ୍ ହୋଇଥିବା ବାଇଟ୍ ଗୁଡ଼ିକରୁ ମୋଟେଇ ଏବଂ ଉଚ୍ଚତା ନିର୍ଣ୍ଣୟ କରେ, ଏବଂ ପଛରେ ଥିବା ପଲିଗ୍ଲଟ୍ ବାଇଟ୍ ଗୁଡ଼ିକୁ ରଖିବା ପରିବର୍ତ୍ତେ ବର୍ଜନ କରେ। କେବଳ ସୀମିତ କାନୋନିକାଲ୍ ସଙ୍କୁଚିତ ବଫର୍ ଉଭୟ କୋଟା ପାଇଁ ଚାର୍ଜ କରାଯାଏ। JSON ୱାୟାର୍ ସୀମା 32 MiB ଡିକୋଡ୍-ଇନପୁଟ୍ ସର୍ବୋଚ୍ଚ ସୀମା ପାଇଁ Base64 ଓଭରହେଡ୍ ଅନ୍ତର୍ଭୁକ୍ତ କରେ। ପ୍ରତ୍ୟେକ ସଂରକ୍ଷିତ ଉତ୍ପତ୍ତି ଏହାର ଯାଞ୍ଚ ହୋଇଥିବା JPEG ଫର୍ମାଟ୍/ରିଜୋଲ୍ୟୁସନ୍, ନମୁନା ନୀତି, ଉତ୍ପତ୍ତି ସଂସ୍କରଣ, ସୃଷ୍ଟି ସମୟ, ସର୍ଭର-ଗଣନା କରାଯାଇଥିବା ବିଷୟବସ୍ତୁ ହ୍ୟାଶ୍, ଏବଂ ହ୍ୟାଶ୍ ହୋଇଥିବା ପିତାମାତା ରେଫରେନ୍ସ ସହିତ ବିଶ୍ୱାସଯୋଗ୍ୟ କଲର୍‌ଙ୍କ ପିତାମାତା-ବିଷୟବସ୍ତୁ ହ୍ୟାଶ୍ ରେକର୍ଡ କରେ। ଆଟୋମିକ୍ କ୍ୟାଚ୍ କମିଟ୍ ପୂର୍ବରୁ ଅସିଙ୍କ୍ରୋନସ୍ ଡିକୋଡ୍/ହ୍ୟାଶ୍ ପର୍ଯ୍ୟାୟ ମଧ୍ୟରେ ବାତିଲ୍ ଯାଞ୍ଚ କରାଯାଏ।

ଏହି ଟ୍ରାଞ୍ଚ ଏପର୍ଯ୍ୟନ୍ତ ଏକ ପ୍ରଡକ୍ସନ୍ ପ୍ରଡ୍ୟୁସରକୁ ରୁଟ୍ ସହିତ ସଂଯୋଗ କରେ ନାହିଁ ଏବଂ ମଲ୍ଟି-ରିଜୋଲ୍ୟୁସନ୍ ଭାରିଏଣ୍ଟ୍ ଚୟନ ପ୍ରଦାନ କରେ ନାହିଁ। ତେଣୁ ସ୍ୱଚ୍ଛ ଭିଡିଓ ବ୍ରିଜ୍ ଅନୁରୋଧ ପଥ କୌଣସି ଅତିରିକ୍ତ କାର୍ଯ୍ୟ କରେ ନାହିଁ, ଯେତେବେଳେ କି ଟେନେଣ୍ଟ୍-ବନ୍ଧିତ ପ୍ରିନ୍ସିପାଲ୍ ଡେରିଭେସନ୍ ଏବଂ ସମ୍ପୂର୍ଣ୍ଣ FU-08 ମଲ୍ଟି-ରିଜୋଲ୍ୟୁସନ୍ ଜୀବନଚକ୍ର ସମ୍ପୂର୍ଣ୍ଣ ଆଚରଣ ଭାବରେ ଡକ୍ୟୁମେଣ୍ଟ୍ ହେବା ପରିବର୍ତ୍ତେ ସ୍ପଷ୍ଟ ଫଲୋ-ଅପ୍ କାର୍ଯ୍ୟ ଭାବରେ ରହିଥାଏ।

ଫ୍ରେମଗୁଡ଼ିକୁ କନଫିଗର୍ ହୋଇଥିବା ଭିଡିଓ ମଡେଲ୍ ସହିତ କ୍ରମାଗତ ଭାବରେ କ୍ୟାପସନ୍ କରାଯାଇଥାଏ। ଏକ ଖାଲି ଭିଡିଓ ଓଭରରାଇଡ୍ ଭିଜନ୍ ସେଟିଂକୁ ଗ୍ରହଣ କରେ; ଯଦି ଉଭୟ ଖାଲି ଥାଏ, ତେବେ ଭିଜନ୍ ଅଟୋ-ରାଉଟର୍ ପ୍ରଭାବଶାଳୀ ଭିଜନ୍-କ୍ଷମ ମଡେଲ୍ ଚୟନ କରେ। ସଫଳ କ୍ୟାପସନ୍ ଗୁଡ଼ିକ ମୂଳ ଅଂଶକୁ ଏକ ସ୍ଥିର `[Video description:` ପ୍ରିଫିକ୍ସ ସହିତ ବଦଳାଇଥାଏ ଯାହା ପାଠ୍ୟକୁ ଏକ ଅବିଶ୍ୱାସନୀୟ ମିଡିଆ-ଉତ୍ପନ୍ନ ପର୍ଯ୍ୟବେକ୍ଷଣ ଭାବରେ ଚିହ୍ନିତ କରେ ଏବଂ ଡାଉନଷ୍ଟ୍ରିମ୍ ମଡେଲଗୁଡ଼ିକୁ ମିଡିଆରେ ମିଳିଥିବା ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକୁ ଅନୁସରଣ ନକରିବାକୁ କୁହେ। ଫ୍ରେମ-କ୍ୟାପସନ୍ କ୍ୟାଚ୍ କି' ଗୁଡ଼ିକରେ JPEG ବାଇଟ୍, ପ୍ରମପ୍ଟ, ଟାଇମ୍‌ଷ୍ଟାମ୍ପ ଏବଂ ପ୍ରଭାବଶାଳୀ ମଡେଲ୍ ଅନ୍ତର୍ଭୁକ୍ତ; କେବଳ ସଫଳ କ୍ୟାପସନ୍ ଗୁଡ଼ିକ କ୍ୟାଚ୍ କରାଯାଇଥାଏ। କ୍ୟାଚ୍ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପ୍ରକୃତ ସଫଳ ପ୍ରଡ୍ୟୁସର ମଡେଲକୁ ବଜାୟ ରଖେ, ଯେଉଁଥିରେ ଏକ ଫଲବ୍ୟାକ୍ ମଡେଲ୍ ଅନ୍ତର୍ଭୁକ୍ତ; ବିଭିନ୍ନ ଫ୍ରେମଗୁଡ଼ିକ ଭିନ୍ନ ମଡେଲ୍ ଦ୍ୱାରା ଉତ୍ପନ୍ନ ହୋଇଥିବାବେଳେ ବ୍ରିଜ୍ `mixed` ରିପୋର୍ଟ କରେ। ଏକ କ୍ୟାଚ୍ ହିଟ୍ (cache hit) ଏହାକୁ ଅନୁରୋଧ କରାଯାଇଥିବା ରାଉଟିଂ ପ୍ଲାନ୍ ଭାବରେ ପୁନଃନାମକରଣ କରିବା ପରିବର୍ତ୍ତେ ସେହି ପ୍ରଡ୍ୟୁସର ପରିଚୟକୁ ପୁନଃ ବ୍ୟବହାର କରେ। ସମ୍ପୂର୍ଣ୍ଣ-ଭିଡିଓ ଫଳାଫଳ କ୍ୟାଚ୍ ପ୍ରତ୍ୟେକ ଇନପୁଟ୍ ଉପରେ ଆଧାରିତ ଯାହା ଆଉଟପୁଟ୍ ପରିବର୍ତ୍ତନ କରେ — ପ୍ରମପ୍ଟ, ପ୍ରଭାବଶାଳୀ ମଡେଲ୍, ନମୁନା ନୀତି, ଫ୍ରେମ୍ ଗଣନା, ସେମାଣ୍ଟିକ୍ ଆନାଲିସିସ୍ ମୋଡ୍, ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ଫୋକସ୍ ଇଙ୍ଗିତର SHA-256 ଫିଙ୍ଗରପ୍ରିଣ୍ଟ, ଫୋକସ୍ ୱିଣ୍ଡୋ, `transcript`, `audioTranscript`, ଏବଂ କଣ୍ଟାକ୍ଟ-ସିଟ୍ ଫ୍ଲାଗ୍ — ତେଣୁ ସେହି ମାତ୍ରାଗୁଡ଼ିକ ମଧ୍ୟରୁ ଯେକୌଣସି ଗୋଟିଏ ପରିବର୍ତ୍ତନ କରିବା ଏକ କ୍ୟାଚ୍ ମିସ୍ ଅଟେ, କେବେବି ପୁରୁଣା ପୁନଃବ୍ୟବହାର ନୁହେଁ। ଭିଜୁଆଲ୍ ଡେଡପ୍ ନୀତି ସଂସ୍କରଣ, ଥ୍ରେସହୋଲ୍ଡ, ଏବଂ ସୀମିତ କ୍ୟାଣ୍ଡିଡେଟ୍-ଫ୍ରେମ୍ ଗଣନା ମଧ୍ୟ ଫଳାଫଳ-କ୍ୟାଚ୍ କି' ଏବଂ ମେଟାଡାଟାରେ ସ୍ପଷ୍ଟ ଅଟେ; ତେଣୁ ଏକ ନୀତି ପରିବର୍ତ୍ତନ ପୁରୁଣା ସମ୍ପୂର୍ଣ୍ଣ-ଭିଡିଓ ବର୍ଣ୍ଣନାକୁ ପୁନଃବ୍ୟବହାର କରିପାରିବ ନାହିଁ। ଫଳାଫଳ-କ୍ୟାଚ୍ v4 ମେଟାଡାଟା ମୋଡ୍ ଏବଂ ଫିଙ୍ଗରପ୍ରିଣ୍ଟକୁ ରଖେ, କେବେବି ରଫ୍ ବ୍ୟବହାରକାରୀ କାର୍ଯ୍ୟ ନୁହେଁ। ଗାର୍ଡରେଲ୍ ମେଟାଡାଟା ଅନୁରୋଧିତ ଏବଂ ପ୍ରଭାବଶାଳୀ ବିଶ୍ଳେଷଣ ମୋଡ୍ ଉଭୟ ରିପୋର୍ଟ କରେ; ବ୍ୟବହାରଯୋଗ୍ୟ ବ୍ୟବହାରକାରୀ ପାଠ୍ୟ ବିନା ଏକ ଅନୁରୋଧିତ `focused` ମୋଡ୍ ପ୍ରଭାବଶାଳୀ ଭାବରେ `full` ବୋଲି ରିପୋର୍ଟ କରାଯାଏ।

| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, ବା ଅନୁପାତିକ `segment_aware`; ଡିଟେକ୍ଟର୍ ବିଫଳତା `uniform` କୁ ଫେରିଯାଏ           |

120 ସେକେଣ୍ଡରୁ ଅଧିକ ପୁରୁଣା ସଂରକ୍ଷିତ ଭିଡିଓ ଟାଇମଆଉଟ୍ ମୂଲ୍ୟଗୁଡ଼ିକୁ ବ୍ରୋକର୍ ଡେଡ୍‌ଲାଇନ୍ ସହିତ କ୍ଲାମ୍ପ୍ କରାଯାଇଛି; ସେହି ସୀମାଠାରୁ ଅଧିକ ନୂତନ ସେଟିଂସ୍ ଲେଖାଗୁଡ଼ିକୁ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ। `GET /api/modality-bridge/video/runtime` ପ୍ରମାଣୀକରଣ କିମ୍ବା ରନ୍‌ଟାଇମ୍ ପ୍ରୋବିଂ ପୂର୍ବରୁ ବିଶ୍ୱାସଯୋଗ୍ୟ ଷ୍ଟାମ୍ପ୍ ହୋଇଥିବା ଲୁପବ୍ୟାକ୍ ଲୋକାଲିଟି ଆବଶ୍ୟକ କରେ, ତାପରେ ପରିଚାଳନା ପ୍ରମାଣୀକରଣ ଆବଶ୍ୟକ କରେ। ଏହା କେବଳ `available`, ସାନିଟାଇଜ୍ ହୋଇଥିବା FFmpeg/ffprobe ସଂସ୍କରଣ, ଏବଂ ରନ୍‌ଟାଇମ୍ ଅନୁପଲବ୍ଧ ଥିବାବେଳେ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ କାରଣ ଫେରାଇଥାଏ। ଆଭ୍ୟନ୍ତରୀଣ ଏକ୍ସଟ୍ରାକସନ୍ ଏଣ୍ଡପଏଣ୍ଟ୍ ଏକ ସାଧାରଣ ଅପଲୋଡ୍ API ନୁହେଁ: କ୍ୟୁ ସାଚୁରେସନ୍ `503` ଏବଂ `Retry-After` ଫେରାଇଥାଏ, ଏକ କଲର୍ ବିଚ୍ଛିନ୍ନତା `499` ଫେରାଇଥାଏ, ଏବଂ ସ୍ଥିର ବ୍ରୋକର୍ ଡେଡ୍‌ଲାଇନ୍ `504` ଫେରାଇଥାଏ। ରୂପାନ୍ତରିତ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ ଭିଜନ୍ କିମ୍ବା ଅଡିଓ ସେଗମେଣ୍ଟଗୁଡ଼ିକୁ ନ ହଟାଇ କେନ୍ଦ୍ରୀୟ `x-omniroute-modality-bridge` ହେଡରରେ `video->text;model=<visionModel>;parts=<videos>` ଯୋଗ କରେ।

### PII ମାସ୍କର୍ (`piiMasker.ts`)

ଉଭୟ ପର୍ଯ୍ୟାୟରେ ଚାଲେ।

- **`preCall`** ଏହା `payload` କ୍ଲୋନ୍ କରେ, `system`, `messages`, `input`, ଏବଂ `prompt` (ସାଧାରଣ ଷ୍ଟ୍ରିଂ ଆଇଟମ୍‌ଗୁଡ଼ିକ ସହିତ) ମାଧ୍ୟମରେ ଯାଏ, ଏବଂ ଷ୍ଟ୍ରିଂ `content`/`text` ଫିଲ୍ଡଗୁଡ଼ିକରେ `processPII()` (`@/shared/utils/inputSanitizer` ରୁ) ପ୍ରୟୋଗ କରେ। ଯେତେବେଳେ `PII_REDACTION_ENABLED=true` ଥାଏ, ଚିହ୍ନଟ ହୋଇଥିବା PII ଆଉଟବାଉଣ୍ଡ `payload` ରେ ସଂଶୋଧିତ (redacted) ହୋଇଥାଏ। ଏହା `INPUT_SANITIZER_MODE` ଠାରୁ ସ୍ୱାଧୀନ ଅଟେ (ଯାହା କେବଳ ପ୍ରମ୍ପ୍ଟ-ଇଞ୍ଜେକ୍ସନ୍ ନୀତିକୁ ନିୟନ୍ତ୍ରଣ କରେ)। ଯେତେବେଳେ ରିଡକ୍ସନ୍ ବନ୍ଦ ଥାଏ, ସେତେବେଳେ କଲ୍ ବିଷୟବସ୍ତୁକୁ ପୁନର୍ଲିଖନ ନକରି ଚିହ୍ନଟ ଗଣନା (detection counts) ରେକର୍ଡ କରେ।
- **`postCall`** ପ୍ରତିକ୍ରିୟାକୁ ଡିପ୍-କ୍ଲୋନ୍ କରେ, `sanitizePIIResponse()` ଏବଂ Responses-API-ଆକାର ମାସ୍କର୍ (`maskResponsesOutput` — `output_text` ଏବଂ `output[].content[].text` କଭର କରେ) ଚଲାଏ। ଯଦି କୌଣସି ରିଡକ୍ସନ୍ ଘଟେ, ତେବେ ପରିବର୍ତ୍ତିତ ପ୍ରତିକ୍ରିୟା ମୂଳ ପ୍ରତିକ୍ରିୟାକୁ ବଦଳାଇଥାଏ।

ଗାର୍ଡରେଲ୍ କେବେବି ବ୍ଲକ୍ କରେ ନାହିଁ; ଏହା କେବଳ ଆନୋଟେଟ୍ କରେ (`meta.detections`, `meta.redacted`) କିମ୍ବା ପୁନର୍ଲିଖନ କରେ।

#### ପ୍ରତି-ପ୍ରକାର ଚୟନ, କଷ୍ଟମ୍ ପ୍ୟାଟର୍ନ ଏବଂ ଚିହ୍ନଟ କାଉଣ୍ଟର

**Dashboard → Settings → Security → PII masking** କେଉଁଟି ମାସ୍କ ହେବ ତାହା ବାଛିଥାଏ। ଏହା ମାସ୍କିଂକୁ ଅନ୍ କରେ ନାହିଁ: ତାହା ଏବଂ `PII_REDACTION_ENABLED` (ଅନୁରୋଧ) ଏବଂ `PII_RESPONSE_SANITIZATION` (ପ୍ରତିକ୍ରିୟା + SSE) ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ ହୁଏ, ଯାହା ଉଭୟ ଡିଫଲ୍ଟ ଭାବରେ ବନ୍ଦ ଥାଏ।

- **Per-type selection** — ବିଲ୍ଟ-ଇନ୍ ଆଇଡିଗୁଡ଼ିକ `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) ରେ ତାଲିକାଭୁକ୍ତ ଅଛି। ସେଟ୍ ହୋଇନଥିବା ଅର୍ଥ ହେଉଛି ପ୍ରତ୍ୟେକ ପ୍ରକାର (ଏହି ସେଟିଂ ବିଦ୍ୟମାନ ହେବା ପୂର୍ବର ଆଚରଣ)। ଅନୁରୋଧ ଇଞ୍ଜିନର `ssn_us` ପ୍ୟାଟର୍ନ `ssn` ସହିତ ମ୍ୟାପ୍ ହୁଏ। ଟେମ୍ପଲେଟ୍ (Minimal, Standard, Financial, Brazilian, USA, Full) କେବଳ UI ରେ ଚେକ୍‌ବକ୍ସଗୁଡ଼ିକୁ ପୂର୍ଣ୍ଣ କରେ।
- **Custom patterns** — ୨୦ ଟି ପର୍ଯ୍ୟନ୍ତ regex କିମ୍ବା ୱାଇଲ୍ଡକାର୍ଡ ପ୍ୟାଟର୍ନ (`*` = ୬୪ ଟି ଅଣ-ହ୍ଵାଇଟସ୍ପେସ୍ ବର୍ଣ୍ଣ ପର୍ଯ୍ୟନ୍ତ, `?` = ଗୋଟିଏ)। ମ୍ୟାଚ୍ଗୁଡ଼ିକ `[CUSTOM_REDACTED]` ହୋଇଯାଏ। ପ୍ରତ୍ୟେକ ପ୍ୟାଟର୍ନ `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) ମାଧ୍ୟମରେ ଯାଏ: ସର୍ବାଧିକ ୫୦୦ ଅକ୍ଷର, ଫ୍ଲାଗଗୁଡ଼ିକ `g i m s u` ରେ ସୀମିତ, କମ୍ପାଇଲ୍ ହେବା ଜରୁରୀ, `safe-regex` (ବିନାଶକାରୀ ବ୍ୟାକଟ୍ରାକିଂ) ପାସ୍ କରିବା ଜରୁରୀ, ଏବଂ ଏକ ଖାଲି ଷ୍ଟ୍ରିଂ କିମ୍ବା ରିଡକ୍ସନ୍ ପ୍ଲେସ୍‌ହୋଲ୍ଡର୍ ସହିତ ମେଳ ହେବା ଉଚିତ୍ ନୁହେଁ। ଏକ ପ୍ୟାଟର୍ନ ଯାହା ବିଫଳ ହୁଏ ତାହା ସେଭ୍ ହେବା ଏବଂ ପରୀକ୍ଷା କରାଯିବା ସମୟରେ ଅସ୍ୱୀକାର କରାଯାଏ, ଏବଂ ଏକ ସଂରକ୍ଷିତ ଧାଡ଼ି ଯାହା ବିଫଳ ହୁଏ ତାହା କମ୍ପାଇଲ୍ ହେବା ବଦଳରେ ରନ୍‌ଟାଇମ୍‌ରେ ଏଡ଼ାଇ ଦିଆଯାଏ। କଷ୍ଟମ୍ ପ୍ୟାଟର୍ନଗୁଡ଼ିକ କେବଳ ମାସ୍କିଂ ଚାଲୁଥିବା ସମୟରେ ରନ୍ ହୁଏ।
- **Detection counters** — ପ୍ରତି-ପ୍ରକାର ଗଣନା (କେବେ ବି ମ୍ୟାଚ୍ ହୋଇଥିବା ମୂଲ୍ୟ ନୁହେଁ), ମେମୋରୀରେ ରଖାଯାଏ ଏବଂ ରିଷ୍ଟାର୍ଟରେ ରିସେଟ୍ ହୁଏ (`src/lib/pii/piiDetectionStats.ts`)। ମାସ୍କିଂ ଚାଲୁଥିବା ସମୟରେ ସେଗୁଡ଼ିକ କେବଳ ବୃଦ୍ଧି ପାଏ।

ସେଟିଂଗୁଡ଼ିକ `key_value` ଟେବୁଲ୍ (ନେମସ୍ପେସ୍ `pii_settings`, `src/lib/db/piiSettings.ts`) ରେ ରହେ ଏବଂ 1 s କ୍ୟାଚ୍ ମାଧ୍ୟମରେ ପଢାଯାଏ। API:

| Method | Path                     | Purpose                                                                                  |
| ------ | ------------------------ | ---------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | ଫ୍ଲାଗ୍ ସ୍ଥିତି, `enabledTypes`, `customPatterns`, ଚିହ୍ନଟ କାଉଣ୍ଟର                          |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = ସମସ୍ତ) ଏବଂ/କିମ୍ବା `customPatterns` ବଦଳାନ୍ତୁ                     |
| `POST` | `/api/settings/pii/test` | ଅତିବେଶିରେ 8 KB ର ଏକ ନମୁନା ବିରୁଦ୍ଧରେ ଗୋଟିଏ ପ୍ୟାଟର୍ନ ଡ୍ରାଇ-ରନ୍ କରନ୍ତୁ; କିଛି ସଂରକ୍ଷିତ ନାହିଁ |

ଏହି ତିନୋଟି ଯାକ ପରିଚାଳନା ପ୍ରାମାଣିକରଣ (management auth) ଆବଶ୍ୟକ କରନ୍ତି ଏବଂ Zod (`src/shared/validation/schemas/piiSettings.ts`) ସହିତ ବଡିକୁ ଭାଲିଡେଟ୍ କରନ୍ତି।

### ପ୍ରମ୍ପ୍ଟ ଇଞ୍ଜେକ୍ସନ୍ (`promptInjection.ts`)

ବ୍ୟବହାରକାରୀଙ୍କ ଦ୍ୱାରା ପ୍ରଦତ୍ତ ବିଷୟବସ୍ତୁରେ ପ୍ରତିକୂଳ ଗଠନଗୁଡ଼ିକୁ ଚିହ୍ନଟ କରେ ଏବଂ କନଫିଗର୍ ହୋଇଥିବା ନୀତିକୁ ପ୍ରୟୋଗ କରେ। ଆଚରଣ ପରିବେଶ ଭେରିଏବଲ୍ ଏବଂ କନ୍‌ଷ୍ଟ୍ରକ୍ଟର୍ ବିକଳ୍ପଗୁଡ଼ିକ ଦ୍ୱାରା ପରିଚାଳିତ ହୁଏ:

| Setting         | Env var                                                                                               | Default | Effect                                                                                                                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enabled         | `INPUT_SANITIZER_ENABLED`                                                                             | `true`  | ଯେତେବେଳେ `false` ହୁଏ, ଗାର୍ଡରେଲ୍ ସର୍ଟ-ସର୍କିଟ୍ ହୁଏ।                                                                                                                                                         |
| Mode            | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn`  | ଇଞ୍ଜେକ୍ସନ୍ ନୀତି: `block`, `warn`, କିମ୍ବା `log`। (`redact` ପଛ କମ୍ପାଟିବିଲିଟି ପାଇଁ ଗ୍ରହଣ କରାଯାଇଛି କିନ୍ତୁ ଇଞ୍ଜେକ୍ସନ୍ ଟେକ୍ସଟ୍ କାଟି ନାହିଁ; ଅନୁରୋଧ PII ପୁନର୍ଲିଖନ `PII_REDACTION_ENABLED` ଦ୍ୱାରା ନିୟନ୍ତ୍ରିତ ହୁଏ।) |
| Block threshold | `blockThreshold` option / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`  | ବ୍ଲକ୍ କରିବା ପାଇଁ ଆବଶ୍ୟକ ସର୍ବନିମ୍ନ ଗମ୍ଭୀରତା। ମଧ୍ଯମ ଡିଫଲ୍ଟ ଭାବରେ କେବଳ-ଅବଜର୍ଭ ଅଟେ।                                                                                                                           |

**ମୋଡ୍ ପ୍ରାଥମିକତା** (`getMode`): କଲର୍ `options.mode` → `INJECTION_GUARD_MODE` **ଡେଟାବେସ୍ ଫିଚର-ଫ୍ଲାଗ୍ ଓଭରରାଇଡ୍** (ଡ୍ୟାସବୋର୍ଡ → ସେଟିଂସମୂହ → ଫିଚର ଫ୍ଲାଗ୍ସ) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. ଏକ ଡ୍ୟାସବୋର୍ଡ ଓଭରରାଇଡ୍ ସେଥିପାଇଁ ଏନଭର୍ମେଣ୍ଟ ଭେରିଏବଲ୍ ଉପରେ ବିଜୟୀ ହୁଏ, ତେଣୁ ଫିଚର ଫ୍ଲାଗ୍ସ UI ଚାଲୁଥିବା ଗାର୍ଡକୁ ଲାଇଭ୍ ଭାବରେ ନିୟନ୍ତ୍ରଣ କରେ (କୌଣସି ରିଷ୍ଟାର୍ଟ ନାହିଁ)। ଡେଟାବେସ୍ ପଠନ ଫେଲ୍-ସେଫ୍ ଅଟେ: ଯଦି ଏଥିରେ ତ୍ରୁଟି ହୁଏ, ତେବେ ଗାର୍ଡ ଏନଭର୍ମେଣ୍ଟ-ଆଧାରିତ ଆଚରଣକୁ ଫେରିଯାଏ, ଏବଂ ଯେତେବେଳେ କୌଣସି ଓଭରରାଇଡ୍ ସେଟ୍ ହୋଇନଥାଏ ସେତେବେଳେ ଆଚରଣ କେବଳ-ଏନଭର୍ମେଣ୍ଟ ରିଜୋଲୁସନ୍ ସହିତ ସମାନ ହୋଇଥାଏ।

ଚିହ୍ନଟ ଉତ୍ସଗୁଡ଼ିକ:

1. `sanitizeRequest()` `@/shared/utils/inputSanitizer` ରୁ (ପାଇପଲାଇନ୍ର ଅନ୍ୟ କୌଣସି ସ୍ଥାନରେ ବ୍ୟବହୃତ ସେୟାର୍ଡ ଡେଟେକ୍ଟର୍ ସେଟ୍)।
2. ବିଲ୍ଟ-ଇନ୍ `DEFAULT_GUARD_PATTERNS` (ବର୍ତ୍ତମାନ `system_override_inline` ଏବଂ `markdown_system_block`, ଉଭୟ `high` ଗମ୍ଭୀରତା)।
3. କନ୍‌ଷ୍ଟ୍ରକ୍ଟର୍ ବିକଳ୍ପଗୁଡ଼ିକ ମାଧ୍ୟମରେ ପାସ୍ ହୋଇଥିବା ଇଚ୍ଛାଧୀନ `customPatterns` (ଷ୍ଟ୍ରିଂ, ରେଜେକ୍ସ, କିମ୍ବା `{ name, pattern, severity }` ରେକର୍ଡଗୁଡ଼ିକ)।

ଯେତେବେଳେ `mode === "block"` ଏବଂ ଅତିକମ୍ରେ ଗୋଟିଏ ଚିହ୍ନଟ ଗମ୍ଭୀରତା ସୀମା ପୂରଣ କରେ, ସେତେବେଳେ `preCall` ଫେରାଇଥାଏ `{ block: true, message: "Request rejected: suspicious content detected" }`। `warn`/`log` ମୋଡ୍‌ଗୁଡ଼ିକରେ ଗାର୍ଡ଼ରେଲ୍ ଲଗ୍ କରେ କିନ୍ତୁ କଲ୍‌କୁ ଅନୁମତି ଦିଏ। ଅଂଶୀଦାର ହେଲ୍ପର୍ `evaluatePromptInjection()` ମଧ୍ୟ ସେହି କଲର୍‌ମାନଙ୍କ ପାଇଁ ଏକ୍ସପୋର୍ଟ କରାଯାଇଛି ଯାହାଙ୍କୁ ରେଜିଷ୍ଟ୍ରି ଦେଇ ନ ଯାଇ ପ୍ରମ୍ପ୍ଟଗୁଡ଼ିକୁ ମୂଲ୍ୟାୟନ କରିବାର ଆବଶ୍ୟକତା ରହିଛି।

**ସ୍କାନ୍ ବାଉଣ୍ଡ (v3.8.20):** ଡିଟେକ୍ଟର୍ କେବଳ ସଂଯୁକ୍ତ ପ୍ରମ୍ପ୍ଟ ପାଠ୍ୟର **ପ୍ରଥମ 16 KB** କୁ ଯାଞ୍ଚ କରେ — `src/shared/utils/inputSanitizer.ts` ରେ `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ବାଇଟ୍)। `detectInjection()` ଏବଂ `evaluatePromptInjection()` ଉଭୟ ପ୍ୟାଟର୍ଣ୍ଣ ଲୁପ୍ ଚଲାଇବା ପୂର୍ବରୁ `slice(0, MAX_INJECTION_SCAN_BYTES)` କରିଥାନ୍ତି। ଇଞ୍ଜେକ୍ସନ୍ ନିର୍ଦ୍ଦେଶଗୁଡ଼ିକ ଇନପୁଟ୍‌ର ଶୀର୍ଷ ନିକଟରେ ଥାଏ, ତେଣୁ ଏହା ଡିଟେକ୍ସନ୍‌କୁ ଦୁର୍ବଳ ନ କରି ମଲ୍ଟି-ହଣ୍ଡ୍ରେଡ୍-କେବି ପେଲ୍‌ଲୋଡ୍ ଉପରେ regex CPU/GC କୁ ସୀମିତ କରିଥାଏ (cf. #3932, #4041)।

### କ୍ରେଡେନ୍ସିଆଲ୍ ମାସ୍କର୍ (`credentialMasker.ts`)

ଏହା **ଉଭୟ** ପର୍ଯ୍ୟାୟରେ ଚାଲେ, ଡିଫଲ୍ଟ ଚେନ୍‌ରେ ଶେଷରେ (ପ୍ରାଥମିକତା `95`)। ଆଉଟ୍‌ବାଉଣ୍ଡ ପେଲ୍‌ଲୋଡ୍ (ମେସେଜ୍ ବିଷୟବସ୍ତୁ, ଟୁଲ୍-କଲ୍ ଆର୍ଗୁମେଣ୍ଟ୍, ଟୁଲ୍ ଫଳାଫଳ) ଏବଂ ପ୍ରୋଭାଇଡର୍ ପ୍ରତିକ୍ରିୟାରୁ ଜଣାଶୁଣା API-କି / ସିକ୍ରେଟ୍-ଟୋକନ୍ ପ୍ୟାଟର୍ଣ୍ଣଗୁଡ଼ିକୁ ରେଡାକ୍ଟ କରିଥାଏ, ଯାହାଫଳରେ ପ୍ରମ୍ପ୍ଟରେ ପେଷ୍ଟ କରାଯାଇଥିବା (ବା ଟୁଲ୍ ଫଳାଫଳ ଦ୍ୱାରା ଫେରାଇ ଦିଆଯାଇଥିବା) କୌଣସି କ୍ରେଡେନ୍ସିଆଲ୍ ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରୋଭାଇଡର୍ କିମ୍ବା କ୍ଲାଏଣ୍ଟ୍ ପାଖକୁ ଲିକ୍ ହୁଏ ନାହିଁ।

- **କେବଳ ଅପ୍-ଇନ୍ (Opt-in only)**, PII ରେଡାକ୍ସନ୍ ପରି ସମାନ କନଭେନ୍ସନ୍ (ହାର୍ଡ ରୁଲ୍ #20-ସଂଲଗ୍ନ): `settings.credentialRedactionEnabled === true` କିମ୍ବା `CREDENTIAL_REDACTION_ENABLED=true` ନହେଲେ ଏହା ଅକ୍ଷମ ଥାଏ। ଏହା ବନ୍ଦ ଥିବାବେଳେ, ଗାର୍ଡ଼ରେଲ୍ ଏକ ନୋ-ଅପ୍ ଅଟେ — ଏହା କେବେବି ବ୍ଲକ୍ କରେ ନାହିଁ ଏବଂ କେବେବି ପୁନଃଲିଖନ କରେ ନାହିଁ।
- `redactCredentials()` ସମ୍ପୂର୍ଣ୍ଣ ପେଲ୍‌ଲୋଡ୍/ରେସ୍ପନ୍ସ ଟ୍ରି କୁ ଟ୍ରାଭର୍ସ କରିଥାଏ (`walkValue()`, ପ୍ରୋଟୋଟାଇପ୍-ପୋଲ୍ୟୁସନ୍-ସେଫ୍, `WeakSet` ମାଧ୍ୟମରେ ସାଇକେଲ୍-ସେଫ୍) ଏବଂ ମେଚ୍‌ଗୁଡ଼ିକୁ `[REDACTED:<type>]` ପ୍ଲେସହୋଲ୍ଡର୍ ସହିତ ପ୍ରତିସ୍ଥାପିତ କରିଥାଏ, କେବଳ ସେହି ବ୍ରାଞ୍ଚଗୁଡ଼ିକୁ କ୍ଲୋନ୍ କରିଥାଏ ଯାହା ପ୍ରକୃତରେ ପରିବର୍ତ୍ତନ ହୋଇଛି।
- `CREDENTIAL_PATTERNS` ଏଲ୍ଏଲ୍ଏମ୍ ପ୍ରୋଭାଇଡର୍ କି (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ଟୋକନ୍ (GitHub, Slack, Linear, Notion, npm, Postman, Discord), ପେମେଣ୍ଟ କି (Stripe, Square), କ୍ଲାଉଡ୍ କି (AWS access key, Twilio, SendGrid, Mailgun), ପ୍ରାଇଭେଟ୍ କି / JWTs, କ୍ରେଡେନ୍ସିଆଲ୍-ଧାରଣକାରୀ କନେକ୍ସନ୍ ଷ୍ଟ୍ରିଙ୍ଗ୍ (`mongodb://user:pass@...`, ଇତ୍ୟାଦି), ଏବଂ ଏକ ଜେନେରିକ୍ `Authorization`/`x-api-key`/`api-key`/`apikey` ହେଡର୍-ଭାଲ୍ୟୁ ପ୍ୟାଟର୍ଣ୍ଣକୁ କଭର୍ କରେ। ହେଡର୍ ଆକାରର କିଗୁଡ଼ିକ (`authorization`, `x-api-key`, `api-key`, `apikey`) ଜେନେରିକ୍ ଟେକ୍ସଟ୍ regex ପରିବର୍ତ୍ତେ ଗଠନମାଳିକା ଅନୁଯାୟୀ ରେଡାକ୍ଟ ହୋଇଥାଏ (କେବଳ ଭାଲ୍ୟୁ, `Bearer `/`Basic ` ପରି ସ୍କିମ୍ ପ୍ରିଫିକ୍ସ ସଂରକ୍ଷିତ ଥାଏ)।
- ଗାର୍ଡ଼ରେଲ୍ କେବେବି ବ୍ଲକ୍ କରେ ନାହିଁ; ଏହା କେବଳ ପୁନଃଲିଖନ କରେ (`modifiedPayload` / `modifiedResponse`) ଏବଂ ଆନୋଟେଟ୍ କରେ (`meta.credentialsRedacted`, `meta.count`)।

ରଗ୍ରେସନ୍ ଗାର୍ଡ: `tests/unit/credential-masker-guardrail.test.ts`।

## ମୂଳ ଚୁକ୍ତି (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ଶୃଙ୍ଖଳାକୁ ସର୍ଟ-ସର୍କିଟ୍ କରେ
  message?: string; // ବ୍ଲକ୍ ହେବା ସମୟରେ ପ୍ରଦର୍ଶିତ ହୁଏ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ଅନୁରୋଧ ପୁନଃଲିଖନ କରିବା ପାଇଁ preCall ଦ୍ୱାରା ଫେରସ୍ତ କରାଯାଇଥାଏ
  modifiedResponse?: TValue; // ପ୍ରତିକ୍ରିୟା ପୁନଃଲିଖନ କରିବା ପାଇଁ postCall ଦ୍ୱାରା ଫେରସ୍ତ କରାଯାଇଥାଏ
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ଏକ ଗାର୍ଡରେଲ୍ `void`, `{}`, କିମ୍ବା `{ block: false }` ଫେରସ୍ତ କରି "କୌଣସି ପରିବର୍ତ୍ତନ ନାହିଁ" ବୋଲି ସଙ୍କେତ ଦେଇଥାଏ। ଏକ `modifiedPayload`/`modifiedResponse` ଫେରସ୍ତ କରିବା ଦ୍ୱାରା ଡାଉନଷ୍ଟ୍ରିମ୍ ଗାର୍ଡରେଲ୍ ଗୁଡ଼ିକ ପାଇଁ ଶୃଙ୍ଖଳା ଦେଇ ପ୍ରବାହିତ ହେଉଥିବା ମୂଲ୍ୟ ପ୍ରତିସ୍ଥାପିତ ହୋଇଥାଏ।
`signal?: AbortSignal` କଲର୍ ଜୀବନଚକ୍ରକୁ ଗାର୍ଡରେଲ୍ ମଧ୍ୟକୁ ବୋହିଥାଏ। ଏକ ଅନୁରୋଧ ବାତିଲ୍ ହେବା ହେଉଛି ଏକ ଜାଣିଶୁଣି କରାଯାଇଥିବା ଫେଲ୍-ଓପନ୍ ବ୍ୟତିକ୍ରମ: ମିଡିଆ ବ୍ରିଜ୍ ଗୁଡ଼ିକ କାର୍ଯ୍ୟ ବନ୍ଦ କରିଦିଅନ୍ତି ଏବଂ ଏହାକୁ ସମର୍ଥନ କରେ ନାହିଁ ବୋଲି ଜଣାଶୁଣା ଏକ ଲକ୍ଷ୍ୟକୁ କଞ୍ଚା ମିଡିଆ ପୁନଃସ୍ଥାପନ ନକରି ସଫା କରନ୍ତି।

## ରେଜିଷ୍ଟ୍ରି (`registry.ts`)

ସିଙ୍ଗଲ୍ଟନ୍ `guardrailRegistry` ନିମ୍ନଲିଖିତଗୁଡ଼ିକୁ ପ୍ରଦାନ କରେ:

- `register(guardrail)` — ଏକ ଗାର୍ଡରେଲ୍ ଯୋଡ଼ିଥାଏ (ବା ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ନାମ ଦ୍ୱାରା ପ୍ରତିସ୍ଥାପନ କରେ) ଏବଂ ଆରୋହୀ `priority` ଦ୍ୱାରା ପୁନଃ-ସର୍ଟ କରେ।
- `clear()` / `list()` — ପ୍ରଶାସନିକ ସହାୟକ।
- `runPreCallHooks(payload, context)` — ସକ୍ରିୟ ଗାର୍ଡରେଲ୍ ଗୁଡ଼ିକୁ ଇଟେରେଟ୍ କରେ, `modifiedPayload` ମାଧ୍ୟମରେ ପେଲ୍‌ଲୋଡ୍ କୁ ଥ୍ରେଡ୍ କରେ, ଏବଂ ପ୍ରଥମ `block: true` ରେ ଅଟକି ଯାଏ।
- `runPostCallHooks(response, context)` — ପ୍ରତିକ୍ରିୟା ପାର୍ଶ୍ୱରେ ସମାନ ପ୍ରବାହ।
- `resetGuardrailsForTests({ registerDefaults })` — ସ୍ଥିତିକୁ ସଫା କରେ ଏବଂ ପରିଷ୍କାର ପରୀକ୍ଷା ବିଚ୍ଛିନ୍ନତା ପାଇଁ ଡିଫଲ୍ଟଗୁଡ଼ିକୁ ଇଚ୍ଛାଧୀନ ଭାବରେ ପୁନଃ-ପଞ୍ଜୀକରଣ କରେ।

ଉଭୟ ରନର୍ `{ blocked, payload|response, results, guardrail?, message? }` ଫେରସ୍ତ କରନ୍ତି ଯେଉଁଠାରେ `results` ହେଉଛି `GuardrailExecutionResult` ରେକର୍ଡଗୁଡ଼ିକର ଏକ ଆରେ ଯାହା ପ୍ରତି-ଗାର୍ଡରେଲ୍ `blocked`, `skipped`, `modified`, `error`, ଏବଂ `meta` ଫିଲ୍ଡଗୁଡ଼ିକୁ ଅନ୍ତର୍ଭୁକ୍ତ କରେ, ଯାହା ଟ୍ରେସିଂ ପାଇଁ ଉପଯୋଗୀ ଅଟେ।

### ପ୍ରତି-ଅନୁରୋଧ ଗାର୍ଡରେଲ୍ ଗୁଡ଼ିକୁ ଅକ୍ଷମ କରୁଛି

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` ବର୍ତ୍ତମାନର ଅନୁରୋଧ ପାଇଁ ଏଡ଼ାଇ ଦିଆଯିବାକୁ ଥିବା ଗାର୍ଡରେଲ୍ ନାମଗୁଡ଼ିକର ଏକ ଡି-ଡୁପ୍ଲିକେଟ୍ ହୋଇଥିବା ତାଲିକାକୁ ସଂଗ୍ରହ କରେ। ଏଠାରେ ପାଞ୍ଚଟି ଚ୍ୟାନେଲ୍ ଅଛି, ଏହି କ୍ରମରେ ପଢ଼ାଯାଏ ଏବଂ ଗୋଟିଏ ତାଲିକାରେ ମିଶ୍ରିତ ହୁଏ (ଡି-ଡୁପ୍ଲିକେଟ୍ କରିବା ସମୟରେ ପ୍ରଥମ ଘଟଣା ଜିତେ):

1. `apiKeyInfo.disabledGuardrails`
2. Request body `disabledGuardrails` (top-level)
3. Request body `metadata.disabledGuardrails` (only when `metadata` is an object)
4. Header `x-omniroute-disabled-guardrails`
5. Legacy header `x-disabled-guardrails`

ସମସ୍ତ ପାଞ୍ଚଟି ଚ୍ୟାନେଲ୍ ମିଶ୍ରିତ ହୋଇଛି, ଦୁଇଟି ହେଡର୍ ଅନ୍ତର୍ଭୁକ୍ତ: ଉଭୟ `x-omniroute-disabled-guardrails` ଏବଂ `x-disabled-guardrails` ପଠାଇବା ଦ୍ୱାରା ସେମାନଙ୍କ ତାଲିକାର ୟୁନିଅନ୍ ଏଡ଼ାଇ ଯାଆଯାଏ, ଏବଂ ଏକ ଖାଲି ଆଧୁନିକ ହେଡର୍ ଆଉ ପୁରୁଣାଟିକୁ ଲୁକାଏ ନାହିଁ ([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), [#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805) ରେ ସଂଶୋଧିତ)।

ମୂଲ୍ୟଗୁଡ଼ିକ ଷ୍ଟ୍ରିଙ୍ଗ୍ ର ଆରେ କିମ୍ବା କମା-ବିଚ୍ଛିନ୍ନ ଷ୍ଟ୍ରିଙ୍ଗ୍ ହୋଇପାରେ; ନାମଗୁଡ଼ିକୁ ଟ୍ରିମ୍ କରାଯାଇଥାଏ ଏବଂ ଲୋୟରକେସ୍ କେବାବ୍-କେସ୍ (`pii_masker` → `pii-masker`) କୁ ନର୍ମାଲାଇଜ୍ କରାଯାଇଥାଏ, ଏବଂ ଖାଲି ଏଣ୍ଟ୍ରିଗୁଡ଼ିକୁ ହଟାଇ ଦିଆଯାଏ। ଫଳାଫଳଟି `context.disabledGuardrails` ମାଧ୍ୟମରେ ରେଜିଷ୍ଟ୍ରିକୁ ପାସ୍ ହୋଇଥାଏ, ଯାହା ମେଳ ହେଉଥିବା ଗାର୍ଡରେଲ୍ ଗୁଡ଼ିକୁ ଏଡ଼ାଇ ଯାଏ (`results` ରେ `skipped: true`)।

ଅକ୍ଷମ ତାଲିକା କେବଳ **ରେଜିଷ୍ଟ୍ରି**କୁ ପ୍ରଭାବିତ କରେ। ପ୍ରମ୍ପ୍ଟ-ଇଞ୍ଜେକ୍ସନ୍ `block` ମୋଡ୍ ହେଉଛି ଏକ ବାଧ୍ୟତାମୂଳକ ସୀମା: ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ ମିଡଲୱେର୍ (`src/middleware/promptInjectionGuard.ts`) କୌଣସି କଲର୍-ନିୟନ୍ତ୍ରିତ ଅକ୍ଷମ ତାଲିକା ବିନା `evaluatePromptInjection()` କୁ କଲ୍ କରେ (ଏହା ପୂର୍ବରୁ କରୁଥିବା ମୃତ `resolveDisabledGuardrails({ body })` କଲ୍ କୁ [#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934) ରେ ହଟାଇ ଦିଆଯାଇଥିଲା), ତେଣୁ ଏକ ଅନୁରୋଧ ଯାହା `prompt-injection` କୁ ଅକ୍ଷମ କରେ ତାହା `block` ମୋଡ୍ ରେ ମଧ୍ୟ ପ୍ରତ୍ୟାଖ୍ୟାନ କରାଯାଏ। ଏହା ଡିଜାଇନ୍ ଅନୁଯାୟୀ ଅଟେ। ଅକ୍ଷମ ଚ୍ୟାନେଲ୍ ଗୁଡ଼ିକ କଲର୍-ନିୟନ୍ତ୍ରିତ (ଅନୁରୋଧ ବଡି, ମେଟାଡାଟା, ହେଡର୍), ଏବଂ ଜଣେ କଲର୍ ଅପରେଟର୍ ସେଟ୍ କରିଥିବା ସୁରକ୍ଷା ନିୟନ୍ତ୍ରଣକୁ ବନ୍ଦ କରିବାକୁ ସକ୍ଷମ ହେବା ଉଚିତ୍ ନୁହେଁ ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))। [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412) ରୁ ହେଡର୍ ୟୁନିଅନ୍ କେବଳ ପରିବର୍ତ୍ତନ କରେ ଯେ କେଉଁ ରେଜିଷ୍ଟ୍ରି ଗାର୍ଡରେଲ୍ ଗୁଡ଼ିକୁ ଏଡ଼ାଇ ଦିଆଯାଇଛି; ଏହା କ୍ଲାଏଣ୍ଟକୁ ମିଡଲୱେର୍ ବାଇପାସ୍ କରିବାକୁ ଦେଇଥାଏ ନାହିଁ। ବାଧ୍ୟତାମୂଳକ ପ୍ରତି-କି ଏବଂ ପ୍ରତି-ଗ୍ରୁପ୍ ଗାର୍ଡରେଲ୍ ନୀତିଗୁଡ଼ିକ v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417) ରେ ଟ୍ରାକ୍ କରାଯାଇଛି। [Coverage and limits](#coverage-and-limits) ଦେଖନ୍ତୁ।

## କାର୍ଯ୍ୟାନ୍ୱୟନ କ୍ରମ

`src/sse/handlers/chat.ts` ଏବଂ `open-sse/handlers/chatCore.ts` (`[କଭରେଜ୍ ଏବଂ ସୀମା](#coverage-and-limits)` ଅଧୀନରେ ତାଲିକାଭୁକ୍ତ ଚାଟ୍-ପରିବାର ରୁଟ୍‌ଗୁଡ଼ିକ) ଦେଇ ପ୍ରବାହିତ ହେଉଥିବା ପ୍ରତ୍ୟେକ ଅନୁରୋଧ ପାଇଁ:

1. `resolveDisabledGuardrails(...)` API କି, ବଡି, ଏବଂ ହେଡର୍ସରୁ ସ୍କିପ୍ ତାଲିକା ତିଆରି କରେ।
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ଗାର୍ଡ଼ରେଲ୍‌ଗୁଡ଼ିକୁ ଆରୋହୀ ପ୍ରାଥମିକତା କ୍ରମରେ ଚଲାଏ:
   - ଅକ୍ଷମ କରାଯାଇଥିବା ଗାର୍ଡ଼ରେଲ୍‌ଗୁଡ଼ିକୁ `skipped` ଭାବରେ ରେକର୍ଡ କରାଯାଏ।
   - ପ୍ରତ୍ୟେକ ଗାର୍ଡ଼ରେଲ୍‌ର `preCall`, `modifiedPayload` ମାଧ୍ୟମରେ ପେଲୋଡ୍ ପୁନଃଲିଖନ କରିପାରେ।
   - ପ୍ରଥମ `block: true` ଶୃଙ୍ଖଳାକୁ ସର୍ଟ-ସର୍କିଟ୍ କରେ ଏବଂ ହ୍ୟାଣ୍ଡଲର୍ ଏକ ଗାର୍ଡ଼ରେଲ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ ପ୍ରତିକ୍ରିୟା ଫେରାଇଥାଏ।
3. (ସମ୍ଭବତଃ ପୁନଃଲିଖିତ) ପେଲୋଡ୍ କମ୍ବୋ ରାଉଟିଂ ଏବଂ ଅପଷ୍ଟ୍ରିମ୍ ଡିସପ୍ୟାଚ୍ ମଧ୍ୟକୁ ପ୍ରବାହିତ ହୁଏ।
4. **କେବଳ ଅଣ-ଷ୍ଟ୍ରିମିଂ:** ପ୍ରତିକ୍ରିୟା ଏକତ୍ରିତ ହେବା ପରେ, `guardrailRegistry.runPostCallHooks(...)` ପ୍ରତିକ୍ରିୟାରେ ସମାନ ଶୃଙ୍ଖଳା ଚଲାଏ। ଏଠାରେ `block: true` ଅପଷ୍ଟ୍ରିମ୍ ପ୍ରତିକ୍ରିୟାକୁ ଡ୍ରପ୍ କରେ ଏବଂ HTTP 400 ଫେରାଇଥାଏ। ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ ଏହି ପଦକ୍ଷେପକୁ ସମ୍ପୂର୍ଣ୍ଣ ରୂପେ ଏଡ଼ାଇ ଯାଏ।

ତ୍ରୁଟି ଘଟାଉଥିବା ଗାର୍ଡ଼ରେଲ୍‌ଗୁଡ଼ିକୁ `error: <message>` ସହିତ ରେକର୍ଡ କରାଯାଏ ଏବଂ `logger.warn` ମାଧ୍ୟମରେ ଲଗ୍ କରାଯାଏ, କିନ୍ତୁ ଶୃଙ୍ଖଳା ଜାରି ରହେ — ଡିଜାଇନ୍ ଅନୁଯାୟୀ ଏହା ଫେଲ୍-ଓପନ୍ ଅଟେ।

## କଭରେଜ୍ ଏବଂ ସୀମା

ଗାର୍ଡ଼ରେଲ୍ ପଞ୍ଜିକା କେବଳ ଚାଟ୍ ପାଇପଲାଇନ୍ ସହିତ ସଂଯୁକ୍ତ। ଏହି ସୀମାଗୁଡ଼ିକ `tests/unit/guardrail-pipeline-wiring-characterization.test.ts` ଏବଂ `tests/unit/guardrail-pipeline-characterization.test.ts` ଦ୍ୱାରା ନିର୍ଦ୍ଧାରିତ; ଆଚରଣ ପରିବର୍ତ୍ତନ ହେଲେ ସେହି ଟେଷ୍ଟଗୁଡ଼ିକୁ ସଚେତନ ଭାବରେ ଅପଡେଟ୍ କରନ୍ତୁ।

### ଯାହା କଭର୍ ହୋଇନାହିଁ

- **ମିଡିଆ, ଏମ୍ବେଡିଂ ଏବଂ ଡାଟା ରୁଟ୍‌ଗୁଡ଼ିକ** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) କେବେ ବି ପଞ୍ଜିକାରେ ପହଞ୍ଚେ ନାହିଁ। ସେଠାରେ କୌଣସି PII ମାସ୍କିଂ, କ୍ରେଡେନସିଆଲ୍ ମାସ୍କିଂ କିମ୍ବା ମୋଡାଲିଟି ବ୍ରିଜ୍ ଚାଲେ ନାହିଁ। ସେମାନଙ୍କର ଏକମାତ୍ର ଯାଞ୍ଚ ହେଉଛି ପୁରୁଣା ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ ମିଡଲୱେର୍।
- **ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟାଗୁଡ଼ିକ** କୌଣସି ପୋଷ୍ଟ-କଲ୍ ଗାର୍ଡ଼ରେଲ୍ ପାଆନ୍ତି ନାହିଁ: ପୋଷ୍ଟ-କଲ୍ ରେ କୌଣସି `pii-masker` କିମ୍ବା `credential-masker` ନାହିଁ, ଏବଂ କୌଣସି ପୋଷ୍ଟ-କଲ୍ ବ୍ଲକ୍ ନାହିଁ। କେବଳ ଷ୍ଟ୍ରିମିଂ PII ଟ୍ରାନ୍ସଫର୍ମ ପ୍ରୟୋଗ ହୁଏ (ଯେତେବେଳେ `PII_RESPONSE_SANITIZATION` ଚାଲୁ ଥାଏ)। ଏକ ଷ୍ଟ୍ରିମିଡ୍ ପ୍ରତିକ୍ରିୟାରେ ଫେରିଆସିଥିବା କୌଣସି କ୍ରେଡେନସିଆଲ୍ ରିଡାକ୍ଟ କରାଯାଏ ନାହିଁ।
- **ଅକ୍ଷମ ଚ୍ୟାନେଲ୍ ବନାମ ମିଡଲୱେର୍ (ଡିଜାଇନ୍ ଅନୁଯାୟୀ):** ମିଡଲୱେର୍ କୌଣସି କଲର୍-ନିୟନ୍ତ୍ରିତ ଅକ୍ଷମ ତାଲିକା ପାସ୍ ନକରି, `evaluatePromptInjection()` ର ନିଜର ଏକ କଲ୍ ସହିତ ପ୍ରମ୍ପ୍ଟ ଇଞ୍ଜେକ୍ସନ୍ ର ମୂଲ୍ୟାଙ୍କନ କରେ। `block` ମୋଡ୍ ହେଉଛି ଏକ ବାଧ୍ୟତାମୂଳକ ସୀମା ଯାହାକୁ କଲର୍-ନିୟନ୍ତ୍ରିତ ଅକ୍ଷମତାଗୁଡ଼ିକ ଏଡ଼ାଇ ପାରିବ ନାହିଁ, ଚାଟ୍-ପରିବାର ରୁଟ୍‌ଗୁଡ଼ିକ ସମେତ ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413))। `prompt-injection` ଅକ୍ଷମ କରିବା କେବଳ ପଞ୍ଜିକା ଗାର୍ଡ଼ରେଲକୁ ଏଡ଼ାଇ ଯାଏ।

### ପୋଷ୍ଟ-କଲ୍ ପୂର୍ବରୁ କିଏ ଏକ ପ୍ରତିକ୍ରିୟା ଦେଖେ

ଅଣ-ଷ୍ଟ୍ରିମିଂ ପଥରେ କ୍ରମଟି ହେଉଛି: ମେମୋରୀ ଏକ୍ସଟ୍ରାକ୍ସନ୍ → ବିଲ୍ଟ-ଇନ୍ ଟୁଲ୍ ଏକଜିକିଉସନ୍ → ପୋଷ୍ଟ-କଲ୍ ଗାର୍ଡ଼ରେଲ୍‌ଗୁଡ଼ିକ → ପୋଷ୍ଟ-କଲ୍ ବ୍ଲକ୍ ଏଗ୍ଜିଟ୍ → ସେମାଣ୍ଟିକ-କ୍ୟାଚ୍ ଷ୍ଟୋର୍।

- **ମେମୋରୀ ଏକ୍ସଟ୍ରାକସନ୍** ଏବଂ **ଟୁଲ୍ ଏକ୍ସକ୍ୟୁସନ୍** ପୋଷ୍ଟ-କଲ୍ ଗାର୍ଡରେଲଗୁଡ଼ିକ ଏହାକୁ ପୁନଃଲିଖନ କିମ୍ବା ବ୍ଲକ୍ କରିବା ପୂର୍ବରୁ ରିସ୍ପନ୍ସକୁ ଦେଖିଥାଆନ୍ତି। [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) ଠାରୁ, ଯେତେବେଳେ `PII_RESPONSE_SANITIZATION` ଅନ୍ ଥାଏ (ଷ୍ଟ୍ରିମିଂ ଏବଂ ନନ୍-ଷ୍ଟ୍ରିମିଂ ଉଭୟ କ୍ଷେତ୍ରରେ), ମେମୋରୀ ଏକ୍ସଟ୍ରାକସନ୍ ନିଷ୍କାସିତ ଟେକ୍ସଟ୍ କୁ `sanitizePII` ମାଧ୍ୟମରେ ଚାଳନ କରିଥାଏ, କିନ୍ତୁ ପରବର୍ତ୍ତୀ ସମୟରେ ପୋଷ୍ଟ-କଲ୍ ଦ୍ୱାରା ବ୍ଲକ୍ ହୋଇଥିବା ଏକ ରିସ୍ପନ୍ସ ସେଥିସତ୍ତ୍ୱେ ମେମୋରୀ ଏବଂ ଟୁଲ୍ସକୁ ପ୍ରଦାନ କରାଯାଇସାରିଥାଏ।
- **ସେମାଣ୍ଟିକ କ୍ୟାସ** ପୋଷ୍ଟ-କଲ୍ ପରେ ରିସ୍ପନ୍ସକୁ ସଂରକ୍ଷଣ କରିଥାଏ, ତେଣୁ ଏହା ପୁନଃଲିଖିତ ରିସ୍ପନ୍ସକୁ ସଂରକ୍ଷଣ କରେ, ଏବଂ ଏକ ବ୍ଲକ୍ ହୋଇଥିବା ରିସ୍ପନ୍ସ କେବେ ମଧ୍ୟ କ୍ୟାସ ହୋଇନଥାଏ। କ୍ୟାସ ଏଣ୍ଟ୍ରିଗୁଡ଼ିକ ପ୍ରତ୍ୟେକ API key ଅନୁଯାୟୀ କି (keyed) ହୋଇଥାଏ।

## ବିନ୍ୟାସ

ବିଲ୍ଟ-ଇନ୍ ଗାର୍ଡରେଲ୍ସଗୁଡ଼ିକ ଦ୍ୱାରା ପଢ଼ାଯାଉଥିବା ଏନଭାଇରନମେଣ୍ଟ ଭେରିଏବଲ୍ସ:

| ଭେରିଏବଲ୍                              | ଦ୍ୱାରା ବ୍ୟବହୃତ            | ପ୍ରଭାବ                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | ଚିହ୍ନଟକୁ ସଂପୂର୍ଣ୍ଣ ରୂପେ ନିଷ୍କ୍ରିୟ କରିବା ପାଇଁ `false` ସେଟ୍ କରନ୍ତୁ।                                                  |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ଇଞ୍ଜେକ୍ସନ୍ ପଲିସି: `warn`, `block`, କିମ୍ବା `log`। ପୁରୁଣା ଭାଲ୍ୟୁ `redact` ଇଞ୍ଜେକ୍ସନ୍ ଟେକ୍ସଟ୍ କୁ ପୁନର୍ଲିଖନ କରେ ନାହିଁ। |

| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` ପାଇଁ ଲେଗସି ଆଲିଆସ୍।                                                               |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | ଯେତେବେଳେ `true` ଅଟେ, ଅନୁରୋଧ PII ରିଡାକ୍ଟ କରାଯାଇଥାଏ (ଇଞ୍ଜେକ୍ସନ୍ ମୋଡ୍ ଠାରୁ ସ୍ୱାଧୀନ)।                                  |

ମୋଡାଲିଟି ବ୍ରିଜ୍ ଗାର୍ଡରେଲ୍ସଗୁଡ଼ିକ env ଭେରିଏବଲ୍ସରୁ ନୁହେଁ, ବରଂ DB-ବ୍ୟାକ୍ଡ୍ ସେଟିଂସ୍ ଷ୍ଟୋର (`getSettings()`) ରୁ ରନ୍‌ଟାଇମ୍ କନଫିଗ୍ ପଢ଼ିଥାନ୍ତି। ଭିଜନର ପ୍ରାଥମିକ କିଗୁଡ଼ିକ ହେଲା `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, ଏବଂ `modalityBridgeCacheMaxEntries`। ଲେଗସି `visionBridge*` କିଗୁଡ଼ିକ କେବଳ ଡକ୍ୟୁମେଣ୍ଟ ହୋଇଥିବା ଏକ-ସାଇକେଲ୍ ପଢ଼ିବା ଫଲବ୍ୟାକ୍ ଭାବରେ ଗ୍ରହଣ କରାଯାଏ; ଡ୍ୟାସବୋର୍ଡର ଲେଖାଗୁଡ଼ିକ ପ୍ରାଥମିକ କିଗୁଡ଼ିକୁ ବ୍ୟବହାର କରେ। ଡିଫଲ୍ଟ ଏବଂ ଫଲବ୍ୟାକ୍ ରିଜୋଭର୍ `src/shared/constants/modalityBridgeDefaults.ts` ରେ ରହିଥାଏ, ଏବଂ ଲେଗସି କନଷ୍ଟାଣ୍ଟଗୁଡ଼ିକ `src/shared/constants/visionBridgeDefaults.ts` ରେ ସଂରକ୍ଷିତ ଥାଏ।

ଅଡିଓ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, ଏବଂ `modalityBridgeAudioMaxClips`, ସହିତ ସେୟାର୍ ହୋଇଥିବା `modalityBridgeCache*` ସେଟିଂସ୍ ବ୍ୟବହାର କରେ। ଅଡିଓ ପାଇଁ କୌଣସି ଲେଗସି-କି ଫଲବ୍ୟାକ୍ ନାହିଁ କାରଣ ଏହି କିଗୁଡ଼ିକ ମୋଡାଲିଟି ବ୍ରିଜ୍ ସ୍କିମା ସହିତ ପ୍ରଚଳିତ ହୋଇଥିଲା।

ଭିଡିଓ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, ଏବଂ `modalityBridgeVideoTimeout`, ସହିତ ସେୟାର୍ ହୋଇଥିବା `modalityBridgeCache*` ସେଟିଂସ୍ ବ୍ୟବହାର କରେ। ଏହା ଡିଫଲ୍ଟ ଭାବରେ ନିଷ୍କ୍ରିୟ ଥାଏ କାରଣ FFmpeg/ffprobe ହେଉଛି ଇଚ୍ଛାଧୀନ ଅପରେସନାଲ୍ ଡିପେଣ୍ଡେନ୍ସି ଏବଂ ଫ୍ରେମ୍ କ୍ୟାପ୍ସନିଂ ଲାଟେନ୍ସି ଏବଂ ମଡେଲ୍ ମୂଲ୍ୟ ବଢ଼ାଇଥାଏ।

## କଷ୍ଟମ୍ ଗାର୍ଡରେଲ୍ସ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ପଦକ୍ଷେପଗୁଡ଼ିକ:

1. `BaseGuardrail` କୁ ଏକ୍ସଟେଣ୍ଡ କରି `src/lib/guardrails/myGuardrail.ts` ତିଆରି କରନ୍ତୁ।
2. `preCall` ଏବଂ/ବା `postCall` କାର୍ଯ୍ୟକାରୀ କରନ୍ତୁ।
3. ଇମ୍ପୋର୍ଟ ସମୟରେ ରେଜିଷ୍ଟର୍ କରନ୍ତୁ (`registerDefaultGuardrails` ରୁ ପୁସ୍ କରନ୍ତୁ) କିମ୍ବା ରନ୍‌ଟାଇମ୍‌ରେ `guardrailRegistry.register(...)` କଲ୍ କରନ୍ତୁ — ରେଜିଷ୍ଟ୍ରି ସମାନ ନର୍ମାଲାଇଜ୍ ହୋଇଥିବା ନାମ ସହିତ ଯେକୌଣସି ପୂର୍ବ ଗାର୍ଡରେଲ୍‌କୁ ବଦଳାଇଦିଏ।
4. `tests/unit/` ଅଧୀନରେ ଟେଷ୍ଟ୍ ଯୋଡନ୍ତୁ (ବର୍ତ୍ତମାନର ଉଦାହରଣଗୁଡ଼ିକ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## ଟେଷ୍ଟିଂ

ଏକ ଜଣାଶୁଣା ସ୍ଥିତିରୁ ଆରମ୍ଭ କରିବା ପାଇଁ ଟେଷ୍ଟ୍ ଗୁଡ଼ିକ ମଧ୍ୟରେ `resetGuardrailsForTests()` ବ୍ୟବହାର କରନ୍ତୁ।
ଖାଲି ରେଜିଷ୍ଟ୍ରିରୁ ଆରମ୍ଭ କରିବାକୁ ଏବଂ କେବଳ ଟେଷ୍ଟ୍ ହେଉଥିବା ଗାର୍ଡରେଲ୍‌ଗୁଡ଼ିକୁ ରେଜିଷ୍ଟର୍ କରିବାକୁ `{ registerDefaults: false }` ପାସ୍ କରନ୍ତୁ। ଭିଜନ ବ୍ରିଜ୍ ଡିପେଣ୍ଡେନ୍ସି ଇଞ୍ଜେକ୍ସନ୍ (`deps.getSettings`, `deps.callVisionModel`) ଗ୍ରହଣ କରେ; ଅଡିଓ ବ୍ରିଜ୍ ସେଟିଂସ୍, କ୍ଷମତା, STT ମଡେଲ୍ ଚୟନ, କ୍ରେଡେନ୍ସିଆଲ୍ ଯାଞ୍ଚ, ଏବଂ ଟ୍ରାନ୍ସକ୍ରିପ୍ସନ୍ ପାଇଁ ସମାନ ସିମ୍‌ଗୁଡ଼ିକୁ ପ୍ରକାଶ କରେ। ତେଣୁ ଟେଷ୍ଟ୍‌ଗୁଡ଼ିକ ଡିବି କିମ୍ବା ନେଟୱାର୍କ ଆକ୍‌ସେସ୍ ବିନା ଉଭୟ ଫ୍ଲୋର ପରୀକ୍ଷା କରିପାରିବ।

## ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ ରୁଟ୍ କଭରେଜ୍ ଏବଂ ରେଡ୍-ଟିମ୍ (ଫେଜ୍ 8 · ବ୍ଲକ୍ D)

ଇଞ୍ଜେକ୍ସନ୍-ଗାର୍ଡ (`createInjectionGuard` / `withInjectionGuard`) ବ୍ୟବହାରକାରୀଙ୍କ ପ୍ରୋମ୍ପ୍ଟ ଗ୍ରହଣ କରୁଥିବା ସମସ୍ତ ରୁଟ୍‌କୁ କଭର୍ କରେ। ଏହା `INJECTION_GUARD_MODE` କୁ ସମ୍ମାନ କରେ (ଡିଫଲ୍ଟ `warn` = କେବଳ ଲଗ୍; `block` = HTTP 400 `SECURITY_001` ଫେରାଇଥାଏ)।

| ପ୍ରକାର               | ରୁଟ୍‌ଗୁଡ଼ିକ                                                                                                                                          | ଡିଫଲ୍ଟ ମୋଡ୍ |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| ଟେକ୍ସଟ୍ (ବର୍ତ୍ତମାନର) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn        |
| ଜେନେରେଟିଭ୍           | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn        |
| ଡାଟା                 | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn        |

ଟେକ୍ସଟ୍ ଏକ୍ସଟ୍ରାକସନ୍ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` କୁ କଭର୍ କରେ।

**ରେଡ୍-ଟିମ୍ (ରାତ୍ରୀକାଳୀନ, `nightly-llm-security.yml`):** promptfoo ଯାଞ୍ଚ କରେ ଯେ ପ୍ରତ୍ୟେକ ରୁଟ୍ `INJECTION_GUARD_MODE=block` ରେ OWASP-LLM କର୍ପସ୍ କୁ ବ୍ଲକ୍ କରେ; garak ପ୍ରୋବ୍ ଚଲାଏ (ସିକ୍ରେଟ୍ ବିନା ସ୍କିପ୍ ହୁଏ)। ସଙ୍ଗତି ପାଇଁ `moderations` ଅନ୍ତର୍ଭୁକ୍ତ କରାଯାଇଛି। ବ୍ଲକ୍ ମୋଡ୍ ହେଉଛି ଏକ ବାଧ୍ୟତାମୂଳକ ସୀମା: `evaluatePromptInjection()` ମିଡଲୱେର୍ ପାସ୍ କରୁଥିବା ପର୍-ରିକ୍ୱେଷ୍ଟ୍ ଡିସେବଲ୍ ତାଲିକାକୁ ଅଣଦେଖା କରେ, ତେଣୁ `disabledGuardrails` ଏକ ରୁଟ୍‌କୁ ଏହାଠାରୁ ମୁକ୍ତ କରେ **ନାହିଁ** ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

ରାତ୍ରୀକାଳୀନ ୱାର୍କଫ୍ଲୋ (`.github/workflows/nightly-llm-security.yml`, କ୍ରନ୍ + ମାନୁଆଲ୍ ଡିସ୍‌ପ୍ୟାଚ୍‌) ର ଦୁଇଟି କାମ ଅଛି:

- **`promptfoo-guard` (ବ୍ଲକ୍ କରୁଛି)** — `INJECTION_GUARD_MODE=block` ସହିତ `promptfoo eval -c promptfooconfig.yaml` ଚଲାଏ। ପ୍ରତ୍ୟେକ ପ୍ରତିକୂଳ କେସ୍ (ଯେପରିକି "ସମସ୍ତ ପୂର୍ବ ନିର୍ଦ୍ଦେଶକୁ ଅଣଦେଖା କରନ୍ତୁ…", DAN-ଷ୍ଟାଇଲ୍ ଜେଲବ୍ରେକ୍) ଦାବି କରେ ଯେ ରେସ୍ପନ୍‌ରେ `error.code === "SECURITY_001"` ଅଛି, ଅର୍ଥାତ୍ ଗାର୍ଡ ପ୍ରକୃତରେ ରିକ୍ୱେଷ୍ଟ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ କରିଥିଲା।
- **`garak` (ପରାମର୍ଶଦାୟକ)** — ଏକ ଲୋକାଲ୍ OmniRoute ଇନଷ୍ଟାନ୍ସ (`http://localhost:20128/v1`) ବିରୁଦ୍ଧରେ garak `--probes promptinject,dan,leakreplay` ଚଲାଏ। ଏକ ପ୍ରୋଭାଇଡର୍ ସିକ୍ରେଟ୍ (`PROMPTFOO_PROVIDER_KEY`) ରେ ଗେଟ୍ ହୋଇଛି; ସୁନ୍ଦର ଭାବରେ ସ୍କିପ୍ ହୁଏ ଏବଂ `|| true` ସଫିକ୍ସ ହୋଇଥାଏ, ତେଣୁ ଏହା CI କୁ ଫେଲ୍ ନକରି ରିପୋର୍ଟ କରେ।

ଗାର୍ଡ ହେଲ୍ପର୍ (`createInjectionGuard` / `withInjectionGuard`) ର କଭରେଜ୍ ପ୍ରତ୍ୟେକ ପ୍ରୋମ୍ପ୍ଟ-ଧାରଣକାରୀ `/v1` ରୁଟ୍‌କୁ ବ୍ୟାପ୍ତ; ପ୍ରୋମ୍ପ୍ଟ ଟେକ୍ସଟ୍ `src/shared/utils/inputSanitizer.ts` ରେ `extractMessageContents()` ଦ୍ୱାରା `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ରୁ ଟାଣାଯାଇଥାଏ।
