காவல் கட்டமைப்புகள் (Guardrails) OmniRoute மற்றும் அப்ஸ்ட்ரீம் வழங்குநர்களுக்கு இடையேயான எல்லையில் பாதுகாப்பு, கொள்கை மற்றும் உள்ளடக்க மாற்றங்களை அமல்படுத்துகின்றன. ஒவ்வொரு காவல் கட்டமைப்பும் (guardrail) கோரிக்கை பேலோடுகளை (`preCall`) மற்றும் அப்ஸ்ட்ரீம் பதில்களை (`postCall`) ஆய்வு செய்ய முடியும் (மேலும் விருப்பத்தேர்வாக நிராகரிக்கலாம், மாற்றலாம் அல்லது குறிப்புகளைச் சேர்க்கலாம்).

இந்த அமைப்பு **பெயில்-ஓபன் (fail-open)** முறையில் செயல்படுகிறது: ஒரு காவல் கட்டமைப்பு (guardrail) இயங்கும் போது பிழையை ஏற்படுத்தினால் (throws), ரெஜிஸ்ட்ரி அந்தப் பிழையைப் பதிவு செய்துவிட்டு, கோரிக்கையைத் தோற்கடிக்காமல் அடுத்த காவல் அமைப்புடன் தொடரும். பிளாக்கிங் (Blocking) என்பது ஒரு வெளிப்படையான முடிவு (`block: true`), ஒருபோதும் தற்செயலானது அல்ல.
இதற்கான ஒரே விதிவிலக்கு கைவிடப்பட்ட கோரிக்கை (aborted request): அழைப்பாளரின் `signal` கைவிடப்படும் போது, பிழையை ஏற்படுத்தும் காவல் கட்டமைப்பு, அந்த ஹூக் இயக்கத்தைத் தவிர்ப்பதற்குப் பதிலாக அதனை நிராகரிக்கிறது.

இந்த ஹூக்குகள் ஒவ்வொரு ரூட்டிலும் அல்லது ஒவ்வொரு பதிலிலும் **இயங்குவதில்லை**. ஒரு காவல் அமைப்பை பாதுகாப்பு கட்டுப்பாடாக நம்புவதற்கு முன்பு [Coverage and limits](#coverage-and-limits) பகுதியைப் படிக்கவும்.

### விஷன் பிரிட்ஜ் (`visionBridge.ts`) — மாடாலிட்டி பிரிட்ஜ் PR-1

GLM 5.3 அடிப்படை மாதிரி மற்றும் `glm-5.3-{low,high,max}` ஆகியவை வெளிப்படையான `supportsVision:false` ரெஜிஸ்ட்ரி/ஸ்பெக் மெட்டாடேட்டாவைக் கொண்டுள்ளன. GLM 5.3 ஃபிளாஷ் வகைகளும் நேட்டிவ்-விஷன் (native-vision) மாதிரிகளாகவே இருக்கின்றன. Claude Code-இன் `/v1/messages` ரூட், Claude-லிருந்து OpenAI-க்கு மொழிபெயர்க்கப்படுவதற்கு **முன்னால்** பகிரப்பட்ட `handleChat` ப்ரீ-கால் காவல் கட்டமைப்புச் சங்கிலியில் நுழைகிறது; கூடு கட்டப்பட்ட (nested) `Read` டூல்-ரிசல்ட் படங்களை, அந்த மொழிபெயர்ப்பு அவற்றை OpenAI `image_url` உள்ளடக்கமாக மாற்றுவதற்கு முன்பு விவரிக்க வேண்டும் அல்லது கையாள வேண்டும் (#17069).

**விஷன் அல்லாத மாதிரிகளை** (non-vision models) இலக்காகக் கொண்ட படங்களைக் கொண்ட கோரிக்கைகளை இடைமறித்து, முழு கோரிக்கையையும் பார்வைத் திறன் கொண்ட மாதிரிக்கு (vision-capable model) மாற்று ரூட் செய்கிறது அல்லது அப்ஸ்ட்ரீம் அழைப்புக்கு முன் கட்டமைக்கக்கூடிய விஷன் மாதிரியால் உருவாக்கப்பட்ட உரை விளக்கங்களுடன் படப் பகுதிகளை மாற்றுகிறது. இது உரை-மட்டும் (text-only) வழங்குநர்களை மல்டிமோடல் பேலோடுகளை வெளிப்படையாகக் கையாள அனுமதிக்கிறது.

செயல்முறை (Flow):

1. இலக்கு மாதிரி ஏற்கனவே பார்வையை (vision) ஆதரித்தால் தவிர்க்கவும் (`isVisionBridgeForcedModel` கட்டாய-பிரிட்ஜ் பட்டியலில் தோன்றினால் தவிர).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) வழியாக படப் பகுதிகளைப் பிரித்தெடுக்கவும். இது `open-sse/utils/mediaParts.ts`-ல் உள்ள **ஒருங்கிணைந்த மீடியா கண்டறிதல் கருவி** `detectMediaParts()`-க்கு delegator-ஆகச் செயல்படுகிறது — இது காம்போ இணக்கத்தன்மை வடிப்பானுடன் பகிரப்பட்ட ஒற்றை உண்மை மூலமாகும். `replaceImageParts` மீண்டும் இணைக்கக்கூடிய வடிவங்களுக்கு பிரித்தெடுத்தல் அனுமதிக்கப்பட்டுள்ளது (பிரித்தெடுத்தல் ↔ மாற்றுதல் ஒப்பந்தம்): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, மற்றும் Responses API `input_image`. Claude Code `tool_result.content` மற்றும் Responses டூல் வெளியீடுகளுக்குள் கூடுகட்டப்பட்ட (nested) பொருந்தும் படங்களும் பிரித்தெடுக்கப்பட்டு அவற்றின் அசல் பாதைகளில் மாற்றப்படுகின்றன; இன்டிகேட்டர்-மட்டும் வடிவங்கள் காம்போ-ஃபில்டர் மெட்டீரியல் ஆகும், மேலும் அவை பிரித்தெடுக்கப்படாது.
   எதுவும் கிடைக்கவில்லை என்றால் தவிர்க்கவும்.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) மூலம் இயக்க நேர உள்ளமைவைத் தீர்க்கவும்: புதிய `modalityBridge*` அமைப்புகளின் சாவிகள் (keys) வெற்றி பெறும்; பழைய `visionBridge*` சாவிகள் **ஒரு-சுழற்சி ஃபால்பேக்** (rollback window) ஆக இருக்கும். பிரிட்ஜ் முடக்கப்பட்டிருக்கும் போது எந்த மீடியா வழித்தடத்திற்கும் (traversal) முன்பு தவிர்க்கவும்.
4. பயன்முறைத் தேர்வாளர் (`modalityBridgeVisionMode`, கீழேயுள்ள அட்டவணையைப் பார்க்கவும்) மாற்று ரூட் செய்வதா அல்லது விவரிப்பதா என்பதை முடிவு செய்கிறது. மாற்று ரூட் என்பது `model` மட்டும் மாற்றப்பட்ட `modifiedPayload`-ஐ வழங்கும், அதனுடன் மெட்டா `{ rerouted, fromModel, toModel, imagesKept }` கிடைக்கும்.
5. விவரிப்புப் பாதை (Describe path): படங்களை `maxImages` வரம்பிற்குள் கட்டுப்படுத்துங்கள், பணி-விழிப்புணர்வு ப்ராம்ப்ட்டை (task-aware prompt) உருவாக்கவும், விவரிப்பு தற்காலிக சேமிப்பை (describe cache) பார்க்கவும், விஷன் மாதிரியை **இணையான முறையில்** (`Promise.allSettled`) அழைக்கவும், மற்றும் அவற்றின் இடத்தில் `[Image N]: <description>` உரை பகுதிகளைச் செருகவும். தோல்வியுற்ற விவரிப்பு `null`-ஐ வழங்கும்: அறியப்படாத/விஷன்-ஆதரிக்கும் இலக்குகளுக்கு மூலப் படம் பாதுகாக்கப்படுகிறது (#4012), ஆனால் **உறுதிப்படுத்தப்பட்ட உரை-மட்டும் நேரடி இலக்கு** அல்லது விஷன்-இல்லாத காம்போ, விவரிக்கப்படாத ஒவ்வொரு படத்திற்கும் வெளிப்படையான `(unavailable — no vision-capable provider connected)` உரை ஸ்டப்பைப் பெறுகிறது, பகுதி தோல்விகள் மற்றும் விவரிப்பு-அழைப்பு வரம்பைத் தாண்டிய படங்களும் இதில் அடங்கும் (#17069). ஏற்கனவே உள்ள அனைத்து-தோல்வியுற்ற காம்போ விவரிப்பு ஃபால்பேக் அப்படியே உள்ளது (#8430).
6. `modifiedPayload` + மெட்டா (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ஆகியவற்றைத் திரும்பப் பெறவும்.

| `auto`     | ✔          | மரபுவழி எகிரிஸ்டிக் (heuristic), மாற்றப்படவில்லை (#6640/#7204): காம்போ அல்லாத/`auto/` மாதிரிகள் சிறந்த பார்வை மாதிரிக்கு (vision model) மாற்றிவிடப்படும், அசல் மாதிரி ஏற்கனவே பயன்படுத்தக்கூடிய நற்சான்றிதறுகளை (credentials) கொண்டிருந்தால் தவிர (அப்போது விவரிக்கவும்); காம்போ இலக்குகள் எப்போதும் விவரிக்கும்.                           |

| `reroute`  |            | கட்டாய மாற்றுப்பாதை: நற்சான்றிதழ்-கொண்ட-மாதிரி பாதுகாப்பு புறக்கணிக்கப்படுகிறது. மாற்றுப்பாதை-**இலக்கு** நற்சான்றிதழ் பாதுகாப்பு தொடர்ந்து பொருந்தும் — பயன்படுத்தக்கூடிய பார்வை இலக்கு எதுவும் இல்லாதபோது, உரை-மட்டும் இலக்கிற்கு மூலப் படங்களை அனுப்புவதற்குப் பதிலாக அல்லது விவரிப்பதற்குப் பதிலாக பிரிட்ஜ் தெளிவான பிழையுடன் தடுக்கும். |

கட்டாயப்படுத்தப்பட்ட முறைகள் ஆட்டோ எகிரிஸ்டிக் இயங்குவதற்கு **முன்பே** குறுக்குவழியில் செல்லும் (`short-circuit`); `auto` இன் செயல்பாடு PR-1-க்கு முந்தைய கார்டுரெயிலுடன் (guardrail) பைட்-ஒத்ததாக (byte-identical) இருக்கும்.

#### API-விசை வரம்பு (`visionBridgeKeyScope.ts`)

அழைப்பாளரின் API விசை `allowedConnections`, கோட்டா குளங்கள் (`allowedQuotas`) அல்லது மாதிரிகளை (`allowedModels` / `blockedModels` / `modelAccessMode: "restricted"` / `disableNonPublicModels`) கட்டுப்படுத்தும்போது, விசை பயன்படுத்தக்கூடிய இணைப்புகளில், அந்த விசை பயன்படுத்தக்கூடிய மாற்றுப்பாதை மற்றும் விவரிப்பு மாதிரிகளை மட்டுமே பிரிட்ஜ் தேர்ந்தெடுக்கும். விவரிப்பு அழைப்பு எப்போதும் OmniRoute செல்ஃப்-லூப் (self-loop) வழியாக `x-omniroute-self-loop-key-id` தலைப்புடன் (header) செல்லும், எனவே பெறும் அரட்டை கோரிக்கை அந்த விசையின் இணைப்பு மற்றும் மாதிரி கொள்கையை மீண்டும் அமல்படுத்தும். `enforceApiKeyPolicy()` அந்தத் தலைப்பை செல்ஃப்-லூப் பியரருடன் (bearer) மட்டுமே மதிக்கிறது, எனவே இது அணுகலைக் குறைக்க மட்டுமே முடியும், மேலும் தீர்க்கப்படாத ஐடி (id) நிராகரிக்கப்படும்.

விசைக்கு பார்வை மாதிரி அனுமதிக்கப்படவில்லை எனில், திறன் இல்லாத அப்ஸ்ட்ரீமிற்கு பட பைட்டுகளை அனுப்புவதற்குப் பதிலாக, **உறுதிப்படுத்தப்பட்ட உரை-மட்டும் இலக்கு** தெளிவான HTTP 400 உடன் உள்ளூர் அளவில் படக் கோரிக்கையை நிராகரிக்கும் (#17069). அறியப்படாத அல்லது நேட்டிவ் பார்வைத் திறன் கொண்ட இலக்குகளுக்கு, விவரிப்புப் பாதை அதன் முந்தைய தோல்வி-திறந்த (fail-open) நடத்தையைத் தக்க வைத்துக் கொள்ளும் (meta `{ skipped: true, reason: "no_permitted_vision_model" }`). விசை இல்லாத கோரிக்கைகளும், இந்த வரம்புகள் இல்லாத விசைகளும் முன்பைப் போலவே செயல்படும்.

#### பணி-விழிப்புணர்வு விவரிப்பு ப்ராம்ப்ட் (`modalityBridgeVisionTaskAware`)

இயல்புநிலை **true**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **கடைசி பயனர் செய்தியின்** உரையை (500 எழுத்துகளுக்கு சுருக்கப்பட்டது) அடிப்படை விவரிப்பு ப்ராம்ப்ட்டுடன் இணைக்கிறது, இது பயனர் உண்மையில் கேட்டதை நோக்கி (codex-vision-proxy மாதிரி) விளக்கத்தை வழிநடத்துகிறது மற்றும் தெரியும் உரையை படியெடுக்க (transcribe) பார்வை மாதிரியைக் கேட்கிறது. கொடி (flag) அணைக்கப்பட்டிருந்தால் - அல்லது பயனர் உரை இல்லை என்றால் - அடிப்படை ப்ராம்ப்ட் மாற்றப்படாமல் பயன்படுத்தப்படும்.

விவரிப்பு செல்ஃப்-லூப்பின் சொந்த OpenAI-இணக்கமான கோரிக்கை (`visionBridgeHelpers.ts`-ல் உள்ள `callVisionModelSingle()`) எப்போதும் `image_url.detail: "high"` ஐக் கோருகிறது — நிபந்தனையின்றி, ஒவ்வொரு அழைப்பாளர்/வழங்குநருக்கும், எந்தவொரு கிளையன்ட் சிக்னலாலும் கட்டுப்படுத்தப்படாமல். குறைந்த விவர மாதிரி எடுப்பது (Low-detail sampling) இந்த ப்ராம்ப்ட் கேட்கும் உரை-படியெடுப்புப் பணிக்கான OCR துல்லியத்தைக் குறைக்கிறது, எனவே அசல் உள்வரும் கோரிக்கை எந்த விவர நிலையைப் பயன்படுத்தியது என்பதைப் பொருட்படுத்தாமல் விவரிப்பு அழைப்பு எப்போதும் அதிக விவரங்களைக் கோருகிறது. இது உள் விவரிப்பு கோரிக்கை உடலை (body) மட்டுமே பாதிக்கிறது; முதன்மை கோரிக்கையில் அழைப்பாளரின் சொந்த `image_url.detail` ஐ OmniRoute எவ்வாறு முன்னோக்கி அனுப்புகிறது என்பதை இது மாற்றாது - அந்த இயல்புநிலை தனியாகப் প্রয়োগப்படுத்தப்படுகிறது, மேலும் கண்டறியப்பட்ட OpenCode கிளையண்டுகளுக்கு மட்டுமே, `defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts` இல்). விவரிப்பு செல்ஃப்-லூப்பின் Anthropic வயர்-ஃபார்மேட் கிளைக்கு `detail` புலம் எதுவும் இல்லை மற்றும் எந்த இயல்புநிலைகளாலும் பாதிக்கப்படாது.

#### விவரிப்பு வெளியீட்டு வரம்பு (`modalityBridgeVisionMaxChars`)

| விசை (Key)                     | இயல்புநிலை | வரம்பு               |
| ------------------------------ | ---------- | -------------------- |
| `modalityBridgeVisionMaxChars` | `0`        | `0` அல்லது 100–50000 |

`0` (இயல்புநிலை) என்றால் **வரம்பு இல்லை** என்று அர்த்தம் — `callVisionModel()` வழங்கும் விளக்கம் மாற்றப்படாமல் அனுப்பப்படுகிறது, இது ஏற்கனவே உள்ள நடத்தையைப் பாதுகாக்கிறது. 100–50000 வரம்பில் உள்ள எந்தவொரு மதிப்பும், அது `[Image N]: <description>` (`src/lib/guardrails/visionBridge.ts` இல் உள்ள `VisionBridgeGuardrail.preCall()`) என மீண்டும் இணைக்கப்படுவதற்கு முன்பு `…` பின்னொட்டுடன் விளக்கத்தைச் சுருக்கும். டவுன்ஸ்ட்ரீம் மாதிரிக்கு முழு படியெடுப்பு தேவைப்படும் விரிவான OCR பணிகளுக்கு இதை உயர்த்தவும்; அரட்டைப் பார்வை மாதிரிகளில் டோக்கன் பயன்பாட்டைக் கட்டுப்படுத்த இதைக் குறைக்கவும். டேஷ்போர்டு புலம் விஷன் டேப்பின் அட்வான்ஸ்டு பலனில் (`ModalityBridgeVisionTab.tsx` இல் உள்ள `modality-bridge-max-chars`) உள்ளது மற்றும் 1 மற்றும் 99 க்கு இடையிலான எந்த மதிப்பையும் 100 தரைக்கு (floor) மேலே கிளாம்ப்ட் (clamps) செய்கிறது, அதே நேரத்தில் வெளிப்படையான `0` ஐத் தொடாமல் விட்டுவிடுகிறது — `0` என்பது அதன் சொந்த உரிமையில் செல்லுபடியாகும் Zod மதிப்பாகும் (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), "அமைக்கப்படாத" இயல்புநிலை மட்டுமல்ல.

#### விவரிப்பு கேச் (`modalityBridge/bridgeCache.ts`)

நினைவகத்தில் உள்ள LRU + TTL கேச் விவரிப்பு வெளியீடுகளுக்காக, செயல்முறை முழுவதும் பகிரப்படுகிறது. விசை = `sha256(imageRef + composedPrompt + configuredBridgeModel)` நீள-முன்னொட்டு ஃபிரேமிங்குடன் (length-prefix framing) (புல-எல்லை மோதல்கள் இல்லை). மாதிரி கூறு என்பது உண்மையில் பதிலளித்த மாதிரி அல்ல, **கட்டமைக்கப்பட்ட** பிரிட்ஜ் மாதிரி ஆகும் — `callVisionModel` உள்நாட்டில் ஃபால் பேக் (fallback) செய்யப்படலாம், மேலும் ஒவ்வொரு முயற்சிக்கும் விசை அமைப்பது கேச்சை துண்டாக்கும் (fragment). தோல்வியுற்ற விவரிப்புகள் எப்போதுமே கேச் செய்யப்படாது. அமைப்புகள்:

| விசை (Key)                      | இயல்புநிலை | வரம்பு  |
| ------------------------------- | ---------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`     | —       |
| `modalityBridgeCacheTtlMinutes` | `60`       | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`      | 10–5000 |

#### Remote image normalization (self-loop describe/base64 fetch)

பிரிட்ஜ் சொந்தமாக ஒரு **தொலைநிலை** (remote) படத்தைப் பெறும்போது — Anthropic வர்ணிப்பு சுய-அழைப்பு மற்றும் `claude-wire-format` `base64` மாற்றுதல் (`ensureBase64ImagesForClaudeWire`), இவை இரண்டும் `visionBridgeHelpers.ts`-ல் உள்ள `fetchRemoteImageAsDataUri()` வழியாக — இதன் விளைவாக கிடைக்கும் டேட்டா URI, விஷன்-மாடல் கோரிக்கையில் உட்பொதிக்கப்படுவதற்கு முன்பு `normalizeDataUri()` (`open-sse/utils/imageNormalize.ts`) வழியாக அனுப்பப்படுகிறது. அதிக அளவிலான படங்கள் **2048px நீண்ட விளிம்பிற்கு** (OpenAI/Anthropic ஏற்கனவே சர்வர் தரப்பில் 적용 செய்யும் அளவு மாற்றும் வரம்புடன் பொருந்துகிறது) குறைக்கப்படுகின்றன, இது விஷன் மாடல் பார்ப்பதை மாற்றாமல் பதிவேற்ற பைட்டுகள்/தாமதத்தைக் குறைக்கிறது. அளவு மாற்ற `sharp` பயன்படுத்தப்படுகிறது, இது டைனமிக் இம்போர்ட் மூலம் ஏற்றப்படுகிறது: அதன் சொந்த பைனரி ஏற்றத் தவறும் பிளாட்ஃபார்மில், `normalizeDataUri()` **எப்போதுமே பிழையை வீசுவதில்லை** — இது அசல் பைட்டுகளின் பாஸ்த்ரூவுக்குத் திரும்பிச் செல்கிறது, எனவே வர்ணிப்பு/base64-மாற்று பாதை எப்போதும் தொடர்ந்து செயல்படும். படம் அல்லாத பைட்டுகள் (டீகோட் செய்யக்கூடிய படத்தைத் தராத பெட்ச்) அப்படியே மாற்றப்படாமல் அனுப்பப்படுகின்றன. இந்த இயல்பாக்கம் பிரிட்ஜ் அதன் சொந்த சுய-அழைப்பிற்காக பெறும் படங்களுக்கு மட்டுமே வரையறுக்கப்பட்டுள்ளது — இது அழைப்பாளரின் மூல பாஸ்த்ரூ பேலோடில் எப்போதுமே பயன்படுத்தப்படுவதில்லை, இது ஆப்ட்-இன்-மட்டுமே மியூட்டேஷன் கொள்கையுடன் (கெடுப்பான விதி #20) ஒத்துப்போகிறது.

#### Transparency header + stats

வர்ணிப்பு மூலம் மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ஐக் கொண்டுள்ளன (`modalityBridge/bridgeStats.ts`-ல் உள்ள `buildModalityBridgeHeader()` மூலம் உருவாக்கப்பட்டது, `src/sse/handlers/chatHelpers.ts`-ல் உள்ள `withModalityBridgeHeader()` மூலம் முத்திரையிடப்பட்டது). மாற்றுப் பாதைக்கு மாற்றப்பட்ட கோரிக்கைகளுக்கு **ஹெடர் எதுவும் இருக்காது** — பேலோட் மாற்றப்படவில்லை மற்றும் மாடல் மாற்றம் ஏற்கனவே பதில் பாடியில் உள்ள `model` புலத்தில் தெரியும்.

`GET /api/modality-bridge/stats` (`GET /api/settings`-ன் அதே அடுக்குடைய மேலாண்மை அங்கீகாரம்) நினைவகத்தில் உள்ள மாடல் வாரியான கவுண்டர்களை வழங்குகிறது `{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs, latencySamples, averageLatencyMs, lastUsedAt }` — `vision`, `audio`, மற்றும் `video` க்காக. `averageLatencyMs` ஆனது அனைத்து முயற்சிகளையும் அல்லாமல், `latencySamples` ஐ அதன் வகுப்பாகப் பயன்படுத்துகிறது; நேரத்தைக் கொண்டிருக்காத ஒரு செயல்பாடு பூஜ்ஜிய-மில்லின்செகண்ட் மாதிரியை உருவாக்காது. `bridged` என்பது வெற்றிகரமான மாற்றங்களுக்கான பின்தங்கிய-இணக்கமான மாற்றுப்பெயராக உள்ளது; தோல்வியுற்ற முயற்சிகள் அதை அதிகரிக்காது. கவுண்டர்கள் வடிவமைப்புப்படி செயல்முறை மறுதொடக்கத்தில் மீட்டமைக்கப்படும் (டெலிமெட்ரி, கணக்கியல் அல்ல).

#### Dashboard configuration

பிரத்யேக டாஷ்போர்டு பக்கம் `/dashboard/settings/modality-bridge` ஆகும். அதன் URL-ல் அணுகக்கூடிய `Vision`, `Audio`, மற்றும் `Video` தாவல்கள் `tab` மதிப்பை மாற்றும் போது வினவல் அளவுமபுள்ளிகளைப் பாதுகாக்கின்றன. விஷன் தாவல் இயக்குதல், முறை, மாடல் தேர்வு (தானியங்கி இயல்புநிலை உட்பட), பணி-விழிப்புணர்வு தூண்டுதல், மேம்பட்ட காலஅவளவு/படம்/விளக்க-நீளம்/கேச் வரம்புகள், இயக்க நேர கவுண்டர்கள் மற்றும் பாதுகாக்கப்பட்ட மாதிரி கோரிக்கையை வெளிப்படுத்துகிறது. ஆடியோ தாவலும் நேரலையில் உள்ளது: இது இயக்குதல், ஆட்டோவுடன் கூடிய STT-மட்டுமேயான மாடல் பிக்கர், காலஅவளவு/அதிகபட்ச-கிளிப் வரம்புகள், ஆடியோ கவுண்டர்கள் மற்றும் `input_audio` மாதிரி சோதனையை வெளிப்படுத்துகிறது. வீடியோ தாவல் செயல்படுகிறது: இது FFmpeg/ffprobe இயக்க நேர நிலையலைப் புகாரளிக்கிறது — நான்கு வெளிப்படையான UI நிலைகளில் ஒன்று (`unknown` ஆய்வு செயல்பாட்டில் இருக்கும்போது அல்லது முடிக்க முடியாதபோது, `restricted` ஆய்வு கிளையண்ட் தரப்பில் தவிர்க்கப்படும் லூப்பேக் அல்லாத டாஷ்போர்டு ஹோஸ்டில், `unavailable` ஆய்வு செய்யப்பட்டு காணாமல் போனது உறுதிசெய்யப்பட்டவுடன், அல்லது `available` FFmpeg/ffprobe பதிப்புகளுடன்) — இயக்கு/மாடல்/பிரேம்/வீடியோ/காலஅவளவு வரம்புகளை நிலைநிறுத்துகிறது, மாடல் பிக்கரை விஷன்-திறன் கொண்ட மாடல்களாக வடிகட்டுகிறது, மற்றும் வீடியோ கவுண்டர்களை வெளிப்படுத்துகிறது.

AI அமைப்புகளின் கீழ் உள்ள முந்தைய விஷன் பிரிட்ஜ் கார்டு புதிய பக்கத்திற்கான இணக்கத்தன்மை இணைப்பாகும்; இது இனி படிவத்தின் இரண்டாவது நகலைக் கொண்டிருக்காது. மீடியா வழங்குநர்களும் இருக்கும் ஸ்பீச்-டூ-டெக்ஸ்ட் பிளேகிரவுண்டை அகற்றாமல் இமேஜ்-டூ-டெக்ஸ்ட் மற்றும் ஸ்பீச்-டூ-டெக்ஸ்ட் ஒர்க்ஃப்ளோக்களை தொடர்புடைய மாடாலிட்டி பிரிட்ஜ் தாவல்களுடன் இணைக்கின்றனர்.

**சுய-லூப் அட்மிஷன் பைபாஸ்:** வர்ணிப்பு அழைப்பு OmniRoute இன் சொந்த `/v1` சுய-லூப் வழியாகச் செல்லும்போது, உப-கோரிக்கை `x-omniroute-admission-bypass: internal` ஐ அனுப்புகிறது மற்றும் தீர்க்கப்பட்ட சுய-லூப் நற்சான்றிதழுடன் அங்கீகரிக்கப்படுகிறது — உள்ளூர் பயன்முறையில் உள்ளூர் `sk_omniroute` சென்டினல், அல்லது ஆபரேட்டரால் கட்டமைக்கப்பட்ட `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env விசை (#1350) இதனால் `REQUIRE_API_KEY=true` டிப்ளாய்மென்ட்கள் இன்னும் வர்ணிப்பு அழைப்பை இயக்க முடியும். பைபாஸ் அந்தத் துல்லியமான நற்சான்றிதழ்களுக்கு மட்டுமே மதிக்கப்படுகிறது, எனவே வெளிப்புற கிளைண்டுகள் அட்மிஷனைத் தவிர்க்க ஹெடரைப் பயன்படுத்த முடியாது.

லெகசி இயல்புநிலைகள் `src/shared/constants/visionBridgeDefaults.ts`-ல் உள்ளன; புதிய முறை/பணி-விழிப்புணர்வு/கேச் இயல்புநிலைகள் மற்றும் அமைப்புகள் ரிசல்வர் `src/shared/constants/modalityBridgeDefaults.ts`-ல் உள்ளன. கார்ட்ரெயில் ஒரு `deps` கன்ஸ்ட்ரக்டர் விருப்பத்தை வெளிப்படுத்துகிறது, இதனால் சோதனைகள் போலி `getSettings` மற்றும் `callVisionModel` செயலாக்கங்களை ஊட்ட முடியும்.

### Audio Bridge (`audioBridge.ts`) — Modality Bridge PR-3

ஆடியோ உள்ளீட்டை ஏற்கும் என அறியப்படாத இலக்கை அடைவதற்கு முன்பு ஆடியோவைக் கொண்ட அரட்டை கோரிக்கைகளை இடைமறிக்கிறது. இது அரட்டை கோரிக்கையை எப்போதுமே மாற்றுப் பாதைக்கு மாற்றுவதில்லை: ஆடியோ பகுதிகள் ஏற்கனவே உள்ள OpenAI-இணக்கமான மல்டிபார்ட் எண்ட் பாயிண்ட் மூலம் படியெடுக்கப்படுகின்றன மற்றும் தேர்ந்தெடுக்கப்பட்ட அரட்டை மாடல் டெக்ஸ்ட் டிரான்ஸ்கிரிப்ட்களுடன் தொடர்கிறது.

ஓட்டம்:

1. `getResolvedModelCapabilities()` மூலம் `supportsAudio` தீர்மானிக்கப்படுகிறது. வெளிப்படையான provider-registry மெட்டாடேட்டா வெற்றி பெறும், அதைத் தொடர்ந்து நிலையான மாடல் மெட்டாடேட்டா, பின்னர் ஒத்திசைக்கப்பட்ட `modalities_input`. `audio` இல்லாத அறிவிக்கப்பட்ட உள்ளீட்டு பட்டியல் `false` ஆகும்; திறன் சான்று எதுவும் கிடைக்கவில்லை என்றால் அது `null` ஆகும். `false` மற்றும் `null` இரண்டும் பழமைவாத பிரிட்ஜை இயக்குகின்றன, அதே நேரத்தில் `true` அதைத் தவிர்க்கிறது.
2. `modalityBridgeAudio*` அமைப்புகளைத் தீர்மானித்து, பகிரப்பட்ட `detectMediaParts()` டிடெக்டர் மூலம் ஒவ்வொரு செய்தியிலிருந்தும் இணைக்கக்கூடிய டாப்-லெவல் ஆடியோ பகுதிகளைப் பிரித்தெடுக்கவும். ஆதரிக்கப்படும் வயர் வடிவங்கள் OpenAI `input_audio`, `audio_url`, மற்றும் `source.media_type: "audio/*"` ஆகும். கூடு கட்டப்பட்ட ஆடியோ ரூட்டிங்கிற்காக கண்டறியப்படுகிறது ஆனால் ஸ்பிளைஸ் பாதையால் அகற்றப்படுவதில்லை. பணி `modalityBridgeAudioMaxClips` மூலம் வரம்பிடப்பட்டுள்ளது; பிந்தைய பகுதிகள் மாறாமல் இருக்கும்.
3. கட்டமைக்கப்பட்ட `provider/model`-ஐ மதிக்கவும், அல்லது `selectAudioBridgeModel()` நிலையான கேடலாக் வரிசையில் `AUDIO_TRANSCRIPTION_PROVIDERS` வழியாகச் சென்று, பயன்படுத்தக்கூடிய செயலில் உள்ள வழங்குநர் நற்சான்றிதழுடன் முதல் மாடலைத் தேர்ந்தெடுக்க அனுமதிக்கவும்.
4. `callAudioTranscription()` ஆனது base64/data-URI ஆடியோவை மல்டிபார்ட் `file` ஆக மாற்றுகிறது, அல்லது DNS பின்னிங் மற்றும் 25 MB வரம்புடன் கூடிய பப்ளிக்-ஒன்லி அவுட்பவுண்ட் கார்டு வழியாக ரிமோட் `audio_url`-ஐப் பதிவிறக்குகிறது. பின்னர் அது கோப்பையும் தேர்ந்தெடுக்கப்பட்ட மாடலையும் உள்ளூர் `/v1/audio/transcriptions` செல்ஃப்-லூப்பிற்கு POST செய்கிறது, இது `resolveSelfLoopBearer()` உடன் அங்கீகரிக்கப்படுகிறது. ஏற்கனவே உள்ள டிரான்ஸ்கிரிப்ஷன் ரூட் சாதாரண நற்சான்றிதழ் தேடல், கூல்டவுன்/ரேட்-லிமிட் கையாளுதல் மற்றும் வழங்குநர் அனுப்பல் ஆகியவற்றைச் செய்கிறது.
5. வெற்றிகரமான அழைப்புகள் அவற்றின் பகுதிகளை `[Audio N]: <transcript>` கொண்டு மாற்றுகின்றன. அழைப்புகள் `Promise.allSettled` உடன் இயங்குகின்றன: தனிப்பட்ட தோல்வி அந்த அசல் ஆடியோ பகுதியைப் பாதுகாக்கிறது (#4012 ஒப்பந்தம்). ஒவ்வொரு அழைப்பும் தோல்வியடைந்து, இலக்கு `supportsAudio === false` என நிரூபிக்கப்பட்டால், அந்தப் பகுதிகள் `[Audio N]: (unavailable — no STT provider connected)` என மாறும் (#8430 ஒப்பந்தம்). அறியப்படாத இலக்குக்கு (`null`), அனைத்து தோல்வி முடிவும் மாறாமல் இருக்கும். பயன்படுத்தக்கூடிய STT நற்சான்றிதழ் இல்லாத நிரூபிக்கப்பட்ட டெக்ஸ்ட்-ஒன்லி இலக்கு, நெட்வொர்க் அழைப்பை வெளியிடாமல் அதே வெளிப்படையான ஸ்டப்பைப் பெறுகிறது.

வெற்றிகரமான டிரான்ஸ்கிரிப்டுகள் செயல்முறை-பரந்த Modality Bridge LRU/TTL கேச்-ஐப் பயன்படுத்துகின்றன. முக்கியமானது ஆடியோ குறிப்பு, நிலையான `audio-transcription` செயல்பாட்டு லேபிள் மற்றும் தேர்ந்தெடுக்கப்பட்ட STT மாடல் ஆகியவற்றை இணைக்கிறது; தோல்விகள் ஒருபோதும் கேச் செய்யப்படுவதில்லை. ஆடியோ முயற்சிகள் பகிரப்பட்ட `bridged`, `cacheHits`, `failures`, மற்றும் `lastUsedAt` கவுண்டர்களைப் புதுப்பிக்கின்றன. மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ஐக் கொண்டுள்ளன; தொடப்படாத கோரிக்கைகள் ஆடியோ பிரிட்ஜ் பிரிவைப் பெறுவதில்லை.

இயக்க நேர அமைப்புகள் DB-ஆதரிக்கப்பட்டவை மற்றும் Zod-சரிபார்க்கப்பட்டவை ஆகும்:

| Key                           | Default | Range              |
| ----------------------------- | ------- | ------------------ |
| `modalityBridgeAudioEnabled`  | `true`  | —                  |
| `modalityBridgeAudioModel`    | `""`    | Auto அல்லது STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000        |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10               |

பகிரப்பட்ட கேச் தொடர்ந்து `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, மற்றும் `modalityBridgeCacheMaxEntries` ஆகியவற்றால் கட்டுப்படுத்தப்படுகிறது.

### வீடியோ பிரிட்ஜ் (`videoBridge.ts`, `videoBridgePipeline.ts`)

அறியப்பட்ட நேட்டிவ் வீடியோ ஆதரவு இல்லாத இலக்கு அழைக்கப்படுவதற்கு முன்பு, சேட் கம்ப்ளீஷன்ஸ் `messages` மற்றும் ரெஸ்பான்ஸ் ஏபிஐ `input` ஆகியவற்றில் உள்ள டாப்-லெவல் வீடியோ பகுதிகளை இது இடைமறிக்கிறது. ஆதரிக்கப்படும் வடிவங்கள் `input_video`, `video_url`, `video_source`, HTTPS URLகள் மற்றும் `data:video/*;base64,...` டேட்டா URIகள் ஆகும். உரையில் உள்ள எளிய கோப்பு பெயர்கள் வீடியோவாகக் கருதப்படுவதில்லை.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) கோரிக்கை உலாவுதல், திறன்/கொள்கை சரிபார்ப்பு, கோரிக்கை வாரியான திரட்டல் மற்றும் பதில் பேலோட் ஆகியவற்றை நிர்வகிக்கிறது. வீடியோ வாரியான வேலை - கையகப்படுத்தல், முழு-முடிவு கேச், பிரேம் வரிசையை விவரிப்பது (இது எந்தவொரு அழைப்பாளர்-அறிவிக்கப்பட்ட ஆடியோ டிரான்ஸ்கிரிப்டையும் இணைக்கிறது), மற்றும் முயற்சி வாரியான மெட்ரிக்ஸ்/அபார்ட்/க்ளீன்அப் - ஆகியவை `videoBridgePipeline.ts` இல் உள்ள `processVideoPart` பின்னால் மறைக்கப்பட்டுள்ளது, இது `preCall`-இன் லூப்பில் உள்ள ஒவ்வொரு வீடியோ பகுதிக்கும் ஒருமுறை அழைக்கப்படுகிறது. அந்தத் தொகுதி வெளிப்படையான போர்ட் எல்லைகளையும் வரையறுக்கிறது: `VideoMediaBrokerPort` (பைட்டுகளைப் பெறுதல் மற்றும் மாதிரி பிரேம்களைப் பிரித்தெடுத்தல்), `VideoAudioTranscriptionPort` (அழைப்பாளர்-அறிவிக்கப்பட்ட ஆடியோ டிரான்ஸ்கிரிப்டை மாதிரி தலைப்புகளுடன் இணைத்தல்), மற்றும் `VideoDrilldownPort` (பிரேம் ட்ரில்-டவுன் நிலைத்தன்மை எல்லை; இன்னும் `processVideoPart`-ல் இணைக்கப்படவில்லை - தனித்தனி `/api/modality-bridge/video/drilldown` ரூட் மட்டுமே இன்று ட்ரில்-டவுன் உள்ளீடுகளை எழுதுகிறது).

பப்ளிக் `/v1` கோரிக்கை பாதை ஒருபோதும் சப்-ப்ராசஸை இறக்குமதி செய்யாது அல்லது அழைக்காது. ரிமோட் வீடியோக்கள் 50 MiB வரம்பிற்குள் பதிவிறக்கப்படுகின்றன; இன்லைன் base64 வீடியோக்கள் வீடியோவிற்கு 36 MiB டிகோட் செய்யப்பட்ட வரம்பைக் கொண்டுள்ளன, இதனால் மாடல்/செய்திகள்/பிரேமிங் என்வலப் ஆனது 50 MiB இன் பப்ளிக் JSON கோரிக்கை அனுமதி வரம்பிற்குள் இருக்க முடியும். ஒதுக்கீட்டிற்கு முன் இன்லைன் நீளம் மற்றும் டிகோட் செய்யப்பட்ட-அளவு மதிப்பீடுகள் சரிபார்க்கப்படுகின்றன. ஆரம்ப ரிமோட் URL மற்றும் ஒவ்வொரு ரீடைரக்ட்டிலும் HTTPS தேவைப்படுகிறது, DNS பின்னிங்குடன் இருக்கும் பப்ளிக்-ஒன்லி அவுட்பவுண்ட் கார்டு பயன்படுத்தப்படுகிறது. பைட்டுகள் துல்லியமான உள் `POST /api/modality-bridge/video/extract` ப்ரோக்கர் எல்லையைக் கடக்கின்றன. அந்த ரூட் `LOCAL_ONLY` மற்றும் `SPAWN_CAPABLE` இரண்டும் ஆகும், செயல்முறை வாரியாக அங்கீகரிக்கப்பட்ட, நம்பகமான-லூப்பேக் கோரிக்கையை மட்டுமே ஏற்றுக்கொள்கிறது, மேலும் URL, கோப்பு முறைமை பாதை, இயங்கக்கூடிய கோப்பு அல்லது வாதப் பட்டியலை ஒருபோதும் ஏற்றுக்கொள்வதில்லை. ஏபிஐ பாடி-சைஸ் பைப்லைன் மற்றும் ஹேண்ட்லரின் இன்கிரிமெண்டல் பாடி ரீடர் ஆகியவை சுயாதீனமாக 50 MiB ப்ரோக்கர் உள்ளீட்டு வரம்பைச் செயல்படுத்துகின்றன. அதன் வரையறுக்கப்பட்ட வரிசை ஒரு நேரத்தில் ஒரு எக்ஸ்ட்ராக்ஷனை இயக்குகிறது, நான்கு நிலுவையில் உள்ள வேலைகளை அனுமதிக்கிறது, மேலும் நிலுவையில் உள்ள உள்ளீட்டை 100 MiB ஆக வரம்புக்குட்படுத்துகிறது.

ப்ரோக்கருக்கு உள்ளே, `ffprobe` ஒரு தனிப்பட்ட உள்ளூர் கோப்பைப் படிக்கிறது; நிலையான வடிவ அனுமதிப்பட்டியல் (format allowlist) பிளேலிஸ்ட் மற்றும் மேனிஃபெஸ்ட் வடிவங்களை விலக்குகிறது. அனுமதிக்கப்பட்ட MOV-குடும்ப கொள்கலன்களுக்கு, வெளிப்புற MOV தரவு குறிப்புகள் இயல்பாகவே முடக்கப்பட்டிருக்கும், மேலும் நிலையான கட்டளை அவற்றைத் தேர்ந்தெடுக்காது. `ffprobe` மற்றும் `ffmpeg` இரண்டும் `file`-மட்டுமான நெறிமுறை அனுமதிப்பட்டியல், ஒரு இழை, நிலையான வாத அணிகள், ஷெல் இல்லை, மற்றும் `PATH`-லிருந்து தீர்க்கப்படும் இயக்கக்கூடிய கோப்புகளைப் பயன்படுத்துகின்றன. இணைக்கப்பட்ட-பட கவர் ஸ்ட்ரீம்கள் இயக்கக்கூடிய வேட்பாளர்கள் அல்ல. இயங்கக்கூடிய அனைத்து ஸ்ட்ரீம்களும் வரம்புகளைப் பூர்த்தி செய்ய வேண்டும், மேலும் உறுதியான குறைந்தபட்ச-குறியீட்டு ஃபால்பேக்கிற்கு முன்னதாக வெளிப்படையான இயல்புநிலை ஸ்ட்ரீம் விரும்பப்படுகிறது. வீடியோக்கள் 600 வினாடிகள், ஒரு பரிமாணத்திற்கு 8,192 பிக்சல்கள் மற்றும் 33,554,432 மூல பிக்சல்கள் வரை மட்டுமே வரையறுக்கப்பட்டுள்ளன. FFmpeg 1–16 நடுப்புள்ளி JPEG ஃபிரேம்களை மாதிரியாக எடுத்துக்கொள்கிறது, சிறிய உள்ளீடுகளை பெரிதாக்காமல் நீண்ட விளிம்பை அதிகபட்சம் 1,024 பிக்சல்களாகக் குறைக்கிறது, மேலும் ஒருபோதும் URL-ஐப் பெறுவதில்லை. மாதிரி எடுப்பது இயல்பாகவே `uniform` ஆகும். விருப்பத்திற்குரிய `scene_aware` மற்றும் சோதனை முறை `segment_aware` கொள்கைகள் ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் ஸ்ட்ரீம் மீது கூடுதலாக ஒரு நிலையான FFmpeg பாஸைச் செய்கின்றன, வரையறுக்கப்பட்ட `showinfo` காட்சி நேர முத்திரைகளைத் தேர்ந்தெடுக்கின்றன, மேலும் டிடெக்டர் தோல்வி, காலாவதி, தவறான வடிவிலான வெளியீடு அல்லது வெற்று வேட்பாளர் தொகுப்பு ஆகியவற்றின் போது அதே சீரான நடுப்புள்ளிகளுக்கு உறுதியாகத் திரும்புகின்றன. செக்மென்ட்-அவேர் பயன்முறையானது சரிபார்க்கப்பட்ட காட்சி இடைவெளிகளுக்கு விகிதாசாரமாக நடுப்புள்ளி மாதிரிகளை ஒதுக்கீடு செய்கிறது; செக்மென்ட்-அவேர் சான்றுகள் மற்றும் ஃபால்பேக் நடத்தை கீழே விவரிக்கப்பட்டுள்ளன. ஒவ்வொரு கொள்கையிலும் தேர்வு செய்யப்பட்ட பிறகு கடுமையான 16-ஃபிரேம் வரம்பு প্রয়োগ செய்யப்படுகிறது. சீன்-அவேர் கோரிக்கையானது ஒரே ஒரு ஃபிரேம் வரவு-செலவுத் திட்டத்தைக் கொண்டிருக்கும் போது, அது செயலில் உள்ள முழு-வீடியோ அல்லது ஃபோகஸ் சாளரத்தின் சீரான நடுப்புள்ளியைப் பயன்படுத்தி `policyEffective: uniform` என அறிக்கை செய்கிறது: தேர்ந்தெடுக்கப்பட்ட ஒரு ஒற்றை காட்சி ஃபிரேம் இரு தற்காலிக முனைகளையும் பாதுகாக்க முடியாது. அழைப்பாளர் விருப்பமாக வரையறுக்கப்பட்ட ஃபோகஸ் சாளரத்தை (`start`/`end` வினாடிகள்) வழங்கலாம்; எல்லைகள் மீடியா காலத்திற்கு உட்படுத்தப்படுகின்றன, தலைகீழான அல்லது வரையறுக்கப்படாத சாளரங்கள் நிராகரிக்கப்படுகின்றன, மேலும் அனைத்து மாதிரி எடுக்கும் கொள்கைகளும் இயல்பாக்கப்பட்ட இடைவெளிக்குள் மட்டுமே செய்யப்படுகின்றன. இதன் விளைவாக வரும் சாளரம் மாதிரி எடுக்கும் மெட்டாடேட்டாவிலும், நம்பத்தகாத விளக்க முன்னொட்டிலும் சேர்க்கப்படுகிறது, இதனால் கீழ்நிலை மாதிரிகள் முழு காலவரிசையிலிருந்து ஃபோகஸ் செய்யப்பட்ட பகுதியை வேறுபடுத்தி அறிய முடியும்.

செமேன்டிக் கேப்ஷன் ஃபோகஸ் என்பது தனித்த, வெளிப்படையான அமைப்பாகும். இயல்புநிலை `full` பகுப்பாய்வு பயன்முறையானது ஏற்கனவே உள்ள ஃபிரேம் ப்ராம்ப்ட்டைப் பாதுகாக்கிறது மற்றும் கோரிக்கை உரையை ஒருபோதும் கேப்ஷன் மாதிரிக்கு அனுப்பாது. `focused` பயன்முறையில், பிரிட்ஜ் அதே அரட்டை அல்லது பதில்கள் கொள்கலனிலிருந்து சமீபத்திய காலியாக இல்லாத பயனர் எழுதிய `text`/`input_text`-ஐ மட்டுமே படிக்கிறது, அதை NFC-க்கு இயல்பாக்குகிறது, கட்டுப்பாட்டு எழுத்துக்கள் மற்றும் வெற்று இடங்களைச் சுருக்குகிறது, மேலும் அதை 500 யூனிகோட் குறியீட்டு புள்ளிகளுடன் வரம்புக்குட்படுத்துகிறது. வெற்று முடிவு, துல்லியமான `full` ப்ராம்ப்ட்டுக்குத் திரும்பும். பயன்படுத்தக்கூடிய குறிப்பு, அர்ப்பணிக்கப்பட்ட நம்பத்தகாத-பயனர்-சூழல் தொகுப்பில் JSON-ஆக சீரியல் செய்யப்படுகிறது மற்றும் கவனிக்கக்கூடிய விவரங்களுக்கு மட்டுமே முன்னுரிமை அளிக்கலாம்; ஊடகத்தில் தெரியும் அல்லது கேட்கக்கூடிய வழிமுறைகளைப் பின்பற்றுவதற்கு எதிரான தனி எச்சரிக்கையை அது மீற முடியாது. உரை சார்ந்த ஃபோகஸ் ஒருபோதும் `start`/`end`-ஐ ஊகிப்பதில்லை அல்லது தற்காலிக மாதிரியை மாற்றுவதில்லை.

#### FU-07 கட்டமைப்புப் பகுதி சான்றுகள்

ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் வீடியோ ஸ்ட்ரீம் மீது `segment_aware` வரம்பிற்குட்பட்ட ஒரு முன்-பகுப்பாய்வு பாஸைப் பயன்படுத்துகிறது. நிலையான ஃபில்டர் செயின் முதலில் அதிகபட்சம் 320 பிக்சல்கள் அகலத்திற்கு அளவிடுகிறது, காட்சி மாற்றங்கள் மற்றும் உறைந்த இடைவெளிகளை கண்டறிகிறது, பின்னர் மங்கள், சராசரி லூமா மற்றும் இடஞ்சார்ந்த/காலநிலை தகவல்களுக்காக வினாடிக்கு 1 ஃபிரேம் வீதம் மாதிரிகளை எடுக்கிறது. இந்த பாஸ் 600 கட்டமைப்பு மாதிரிகள், ஒரு FFmpeg/ஃபில்டர் இழை, அதே `file`-மட்டுமான நெறிமுறை மற்றும் கொள்கலன் அனுமதிப்பட்டியல்கள், 1 MiB செயல்முறை-வெளியீட்டு வரம்பு மற்றும் ப்ரோக்கரின் பகிரப்பட்ட ரத்துசெய்தல்/கெடுவிற்குள் அதிகபட்சம் 30 வினாடிகளுக்கு மட்டுமே வரம்பிடப்பட்டுள்ளது. இது கோரிக்கையிலிருந்து கட்டளை, ஃபில்டர், பாதை அல்லது URL-ஐ ஒருபோதும் ஏற்றுக்கொள்வதில்லை. கட்டமைப்பு மதிப்புகள் உறுதியான மாதிரி எடுக்கும் சான்றுகள்தாம், செமேன்டிக் வீடியோ புரிதல் அல்ல. அவை பொருள், செயல்கள், தலைப்புகள், பேச்சு அல்லது பயனர் நோக்கத்தை ஊகிப்பதில்லை. காட்சிக் காட்சிகள் மற்றும் உறைபனி எல்லைகள் பகுதிகளை உருவாக்குகின்றன; உறைபனி கவரேஜ், மங்கள், வெளிப்பாடு, இடஞ்சார்ந்த விவரம் மற்றும் கால மாற்றம் ஆகியவை ஏற்கனவே உள்ள 1–16 ஃபிரேம் பட்ஜெட் எவ்வாறு ஒதுக்கீடு செய்யப்படுகிறது என்பதை மட்டுமே பாதிக்கின்றன. முழுமையாக உறைந்த பகுதி ஒரு ஃபிரேமாகக் கட்டுப்படுத்தப்படுகிறது, அதே நேரத்தில் உறைந்திராத பகுதிகள் மீதமுள்ள பட்ஜெட்டுக்குப் போட்டியிடுகின்றன. எல்லைகள் ஃபிரேம்களை விட அதிகமாக இருக்கும் போது, சீரான காலவரிசைக் கவரேஜ் தக்கவைக்கப்படுகிறது, இதனால் விரைவான ஆரம்ப வெட்டுக்கள் நீண்ட பின்தொடரும் பகுதியை மறைக்க முடியாது. உறைபனி எல்லையின் 1-வினாடி பகுப்பாய்வு தீர்மானத்திற்குள் உள்ள காட்சி எல்லைகள் ஒன்றிணைக்கப்படுகின்றன. விடுபட்ட ஃபில்டர்கள், தவறான/வெற்று சான்றுகள், டிடெக்டர் பிழை அல்லது வரம்பிற்குட்பட்ட முன்-பகுப்பாய்வு காலாவதி ஆகியவை துல்லியமான சீரான நடுப்புட்டுக் கொள்கைக்கு திறந்த நிலையில் தோல்வியடைகின்றன. அழைப்பாளர் ரத்துசெய்தல் அல்லது ப்ரோக்கர் கெடு திறந்த நிலையில் தோல்வியடையாது: அது இயக்கத்தில் உள்ள துணைச் செயல்முறையை நிறுத்துகிறது, பிந்தைய ஃபிரேம் பிரித்தெடுத்தலைத் தடுக்கிறது, மேலும் தனிப்பட்ட தற்காலிக மரம் `finally`-ல் அகற்றப்படுகிறது.

`scripts/perf/video-bridge-fu07-eval.ts` ஆனது போஸ்ட்-டெட் அப் கேப்ஷன்-கால் சேமிப்புகள், அடர்ந்த-இயக்க பட்ஜெட் ஒதுக்கீடு, மங்கள்/வெளிப்பாடு/SI-TI சான்றுகள், நீண்ட வாலுடன் கூடிய விரைவான வெட்டுக்கள் மற்றும் படிப்படியான-மங்கல் தவறான நேர்மறைகளுக்கான உறுதியான உண்மையான FFmpeg சாதனங்களை உருவாக்குகிறது. இது முன்-பகுப்பாய்வு சுவர் நேரத்தையும், `/usr/bin/time` கிடைக்கும் இடங்களில், சাইল்ட் CPU மற்றும் உச்ச RSS-ையும் பதிவு செய்கிறது. இதன் தர சோதனைகள் கட்டமைப்பு ஓரக்கிள்கள் மட்டுமே. இந்த சேணம் அங்கீகரிக்கப்பட்ட முனைப்புள்ளி அல்லது உறைந்த நடுவரைக் கொண்டிருக்காததால், உண்மையான கேப்ஷன்-மாடல் தரம் `HOLD` என உள்ளது. `--caption-cost-per-call-usd` வெளிப்படையான நேர்மறையான ஒரு அழைப்புக்கான மதிப்பீட்டை வழங்காவிட்டால் பணச் சேமிப்பும் `HOLD` என்றே இருக்கும்; ஸ்கிரிப்ட் எந்த முடிவையும் ஒருபோதும் போலியாக உருவாக்காது.

ஒவ்வொரு பிரேமும் 4 MiB ஆகவும், அனைத்து ரா பிரேம்களும் சேர்த்து 23 MiB ஆகவும், சீரியலைஸ் செய்யப்பட்ட ப்ரோக்கர் பதில் 32 MiB ஆகவும் வரம்பிடப்பட்டுள்ளது. ஒரு பிரைவேட் தற்காலிக அடைவு `finally`-ல் அகற்றப்படும். OmniRoute ஆனது FFmpeg-ஐ பண்டில் செய்யாது மற்றும் விருப்பத்திற்கேற்ப இயங்கக்கூடிய பாதையை ஏற்காது. கேப்ஷனிங் செய்வதற்கு முன், பிரிட்ஜ் ஒரு கன்சர்வேடிவ் விஷுவல் நகல் நீக்க பாஸைப் பயன்படுத்துகிறது: ஒவ்வொரு JPEG-ம் 16×16 கிரேஸ்கேல் பஃபராகக் குறைக்கப்பட்டு, தக்கவைக்கப்பட்ட கடைசி பிரேமுடன் மட்டுமே ஒப்பிடப்படுகிறது. ஒரு பிரேமிற்கு மேற்பட்ட கோரப்பட்ட கேப்ஷன் பட்ஜெட்டுக்கு, எக்ஸ்ட்ராக்ஷன் அந்த பட்ஜெட்டைப் போல இரண்டு மடங்கு வரை மற்றும் 16 பிரேம்களுக்கு மிகாமல் வரம்பிற்குட்பட்ட வேட்பாளர் தொகுப்பை வழங்குகிறது. கோரப்பட்ட வரம்பு நகல் நீக்கத்திற்குப் பின்னரே பயன்படுத்தப்படுகிறது, பட்ஜெட் குறைந்தது இரண்டாக இருக்கும்போது இறுதிச் சுருக்கத்தின் போது முதல் மற்றும் இறுதி தேர்ந்தெடுக்கப்பட்ட வேட்பாளர்கள் பாதுகாக்கப்படுகிறார்கள். பதிப்பு செய்யப்பட்ட `grayscale-16x16-mean-cells-v2` பாலிசியானது, சராசரி லுமா டெல்டா மற்றும் இயல்பாக்கப்பட்ட டெல்டா குறைந்தது 0.05 உள்ள தம்ப்நேல் செல்களின் விகிதம் ஆகிய இரண்டில் பெரியதைப் பயன்படுத்துகிறது. நகல் வரம்பு என்பது நிலையான 0.04 ஆகும், இது ரன்டைம் அமைப்பாக வெளிப்படுத்தப்படுவதை விட யூகிக்கக்கூடிய தன்மைக்காக தேர்ந்தெடுக்கப்பட்டது. இந்த இரண்டாம் நிலை உயர்-மாறுபட்ட சமிக்ஞை சிறிய இயக்கம் மற்றும் புலப்படும் உரை மாற்றங்களைப் பாதுகாக்கிறது, அவற்றை சராசரி-மட்டும் ஒப்பீடு மறைத்துவிடக்கூடும். ஒப்பீட்டாளர் அல்லது டிகோடர் பிழைகள் திறந்த நிலையில் தோல்வியடைகின்றன மற்றும் கவரேஜைத் தக்கவைத்துக்கொள்கின்றன. வெளியீட்டு மெட்டாடேட்டா பிரித்தெடுக்கப்பட்ட வேட்பாளர்கள், வெற்றிகரமாகப் பயன்படுத்தப்பட்ட பிரேம்கள் மற்றும் கைவிடப்பட்ட காட்சி நகல்களைப் பிரிக்கிறது.

வெளிப்படையாகக் குறிக்கப்பட்ட வீடியோ பகுதி டைம்ஸ்டாம்ப் செய்யப்பட்ட காண்டாக்ட் ஷீட்டைக் கோரலாம். பிரிட்ஜ் அதிகபட்சமாக 4-காலம், 16-பிரேம் JPEG கட்டத்தை உருவாக்குகிறது. ஒவ்வொரு 512-பிக்சல் செல்லும் அதன் மூல டைம்ஸ்டாம்பை உயர்-மாறுபட்ட கீழ்ப்பகுதியில் பதிக்கிறது, அதே நேரத்தில் அதே டைம்ஸ்டாம்கள் கீழ்நிலை தொடர்பு மற்றும் தணிக்கைக்காக உரை மெட்டாடேட்டாவில் இருக்கும். முழுமையான JPEG 32 MiB ஆக வரம்பிடப்பட்டுள்ளது. `sharp`-ஆல் கட்டத்தை டிகோட் செய்ய அல்லது உருவாக்க முடியாவிட்டால், பிரிட்ஜ் தனிப்பட்ட JPEG பிரேம்களுக்குத் திரும்பும்; கிளையண்ட் அபார்ட் ஷீட் செயல்பாடு வழியாக இன்னும் பரவுகிறது.

புரோமோஷன் சான்றுகள் செயற்கை கலவை மைக்ரோபெஞ்ச்மார்க்கிலிருந்து வேண்டுமென்றே தனித்தனியாக வைக்கப்பட்டுள்ளன. `scripts/perf/video-bridge-contact-sheet-eval.ts` உண்மையான OpenAI-இணக்கமான விஷன் மாடல்களுக்காக ஸ்கீமா-பதிப்பு செய்யப்பட்ட A/B ஹார்னஸை வரையறுக்கிறது. இது வழங்குநர்-அறிவிக்கப்பட்ட டோக்கன்கள், எண்ட்-டு-எண்ட் வால் லேடன்சி (ஷீட் கம்போசிஷன் உட்பட), மாடல்-கால் எண்ணிக்கை மற்றும் மேனிஃபெஸ்ட்-வரையறுக்கப்பட்ட உண்மைத் தக்கவைப்பு ஆகியவற்றை அளவிடுகிறது. ரா மாடல் பதில்கள் அறிக்கையில் எழுதப்படுவதில்லை; SHA-256 டைஜெஸ்ட்கள் மற்றும் பொருத்தப்பட்ட உண்மை ஐடிக்கள் மட்டுமே தக்கவைக்கப்படுகின்றன. `--execute-real` அனுப்பப்பட்டு மற்றும் `--model`, `OMNIROUTE_BASE_URL`, மற்றும் `OMNIROUTE_API_KEY` கட்டமைக்கப்பட்டிருந்தால் ஒழிய, ஹார்னஸ் எந்த நெட்வொர்க் அல்லது கட்டண மாதிரி அழைப்பையும் செய்யாது. அந்த வெளிப்படையான உண்மையான இயக்கம் இல்லாமல், அதன் இயந்திரத்தால் படிக்கக்கூடிய தீர்ப்பு `HOLD` என்றே இருக்கும்; செயற்கை பேலோடு/கால்-எண்ணிக்கை அளவீடுகள் மட்டுமே புரோமோஷன் சான்றுகள் அல்ல.

அழைப்பாளர்கள் தங்களிடம் ஏற்கனவே இணைக்கப்பட்ட உரை இருக்கும்போது, ஆதரிக்கப்படும் வீடியோ பகுதியுடன் விருப்பமான `transcript.cues` வரிசையை இணைக்கலாம். ஒவ்வொரு கியூவும் `text`, ஆய்வு செய்யப்பட்ட காலத்திற்குள் வரையறுக்கப்பட்ட `start`/`end` இடைவெளி, மற்றும் அனுமதிக்கப்பட்ட `source` (`client`, `embedded`, அல்லது `audio-bridge`) ஆகியவற்றைக் கொண்டிருக்க வேண்டும்; `confidence` இயல்புநிலையாக `1` என இருக்கும் மற்றும் `0`-க்கும் `1`-க்கும் இடையில் இருக்க வேண்டும். சரியான நகல் கியூக்கள் சுருக்கப்படுகின்றன. OmniRoute இந்த மெட்டாடேட்டாவிலிருந்து ஒருபோதும் டிரான்ஸ்கிரிப்ஷனைத் தொடங்குவதில்லை: சரிபார்க்கப்பட்ட கியூக்கள் மூல, நம்பிக்கை மற்றும் இடைவெளியுடன் விவரிக்கப்பட்ட முடிவில் நகலெடுக்கப்படுகின்றன, மேலும் பிரேம்களுடன் நம்பகத்தன்மையற்ற அவதானிப்புகளாக ரெண்டர் செய்யப்படுகின்றன. தவறான, வரம்பிற்கு அப்பாற்பட்ட அல்லது தோற்றம் இல்லாத உரை கேப்ஷன்ஸ்ட்ரீமில் கலக்கப்படுவதற்கு பதிலாக நிராகரிக்கப்படுகிறது. இரண்டு கோரிக்கை-பாடி டிரான்ஸ்கிரிப்ட் சேனல்களும் வழங்கப்பட்ட தோற்றத்தை `client` என இயல்புநிலைக்குக் கொண்டுவருகின்றன, இதில் சுயமாகக் கோரப்பட்ட `embedded` அல்லது `audio-bridge` லேபிள்களும் அடங்கும். கோடு-மட்டும் `trustedSource` ஆர்கியுமண்ட் மூலம் மட்டுமே சேவையகத்திற்குச் சொந்தமான அடாப்டர் அந்த நம்பகமான லேபிள்களை ஒதுக்க முடியும்; ஒரு கோரிக்கை JSON புலத்தால் அந்த ஆர்கியுமண்டை அடைய முடியாது. டிரான்ஸ்கிரிப்ட் உரை அதன் தோற்றத்தைப் பொருட்படுத்தாமல் நம்பகத்தன்மையற்ற மீடியா-பெறப்பட்ட உள்ளடக்கமாகவே இருக்கும், மேலும் அது ஒருபோதும் அங்கீகாரத்தைத் தீர்மானிக்கக்கூடாது.

ஒரு மேம்பட்ட அழைப்பாளர் அதே வீடியோவிற்கான `audioTranscript` டிராக்கை வழங்கலாம்; இது சேவையக டிரான்ஸ்கிரிப்ஷனுக்கான சான்று அல்லாமல், கிளையண்டால் வழங்கப்பட்ட உரையாகக் கருதப்படும். ஃபியூஷன் சீம் காட்சி மற்றும் ஆடியோ அவதானிப்புகளை ஒரே டெட்லைன் மற்றும் அபார்ட் சிக்னலின் கீழ் இயக்குகிறது, அவற்றை ஒரு பொதுவான காலவரிசையில் வரிசைப்படுத்துகிறது, சரியான நகல்களைச் சுருக்குகிறது, மற்றும் ஒரு பக்கம் மட்டுமே வெற்றிபெறும் போது பகுதி முடிவைப் புகாரளிக்கிறது. தவறான `audioTranscript` அந்த பகுதி முடிவாகக் குறைக்கப்படுகிறது — முழு வீடியோவையும் தோல்வியடையச் செய்வதற்குப் பதிலாக, காட்சி விளக்கம் வைக்கப்பட்டு ஆடியோ கிளை சுத்திகரிக்கப்பட்ட தோல்விக் குறியீட்டைப் பதிவு செய்கிறது. கிளை வாரியான கிடைக்கும் தன்மை, பகுதி கொடி, மற்றும் சுத்திகரிக்கப்பட்ட தோல்விக் குறியீடுகள் விவரிக்கப்பட்ட முடிவிலும், கார்ட்ரெயில் மெட்டாடேட்டாவிலும் (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), முடிவு-கேச் மெட்டாடேட்டாவிலும், மற்றும் பிரிட்ஜ் ஃபியூஷன் கவுண்டர்களிலும் பாதுகாக்கப்படுகின்றன. இயல்புநிலை வீடியோ பிரிட்ஜ் பாதை பேச்சு-க்கு-உரை அல்லது இரண்டாவது மீடியா நகலைப் பதிவிறக்குவதை அழைக்காது; அந்த வெளிப்படையான டிராக் இல்லாமல், அது வீடியோ-மட்டுமாகவே இருக்கும்.

**டிரான்ஸ்கிரிப்ட் தக்கவைப்பு (#12150 P1).** வீடியோ பிரிட்ஜ் (இது இயல்பாகவே ஆப்ட்-இன் ஆகும்) எப்போது டிரான்ஸ்கிரிப்ட் கியூவை ரெண்டர் செய்கிறதோ, அப்போது இது தானாகவே பொருந்தும் — தனித்த தக்கவைப்பு கொடி (flag) எதுவும் இல்லை. ஒரு கோரிக்கை ஏதேனும் டிரான்ஸ்கிரிப்ட் கியூவை ரெண்டர் செய்யும் போது (அழைப்பாளர் அறிவித்த `transcript` அல்லது இணைக்கப்பட்ட `audioTranscript`), கார்ட்ரெயில் அதை `videoBridgeObserved` எனக் குறிக்கிறது மற்றும் வீடியோ விளக்கத்தின் திருத்தப்பட்ட நிழல் பிரதியை உருவாக்குகிறது — இது ஒரு ஒத்த ரெண்டரிங் ஆகும், இதில் ஒவ்வொரு கியூவின் ஃப்ரீ-டெக்ஸ்ட் பாடியும் `[redacted-video-transcript]` மூலம் மாற்றப்படுகிறது, இது சரம் ஒன்று சேர்க்கப்படுவதற்கு முன்பு கட்டமைக்கப்பட்ட கியூ புலத்தை மாற்றுவதன் மூலம் உருவாக்கப்படுகிறது (தட்டையாக்கப்பட்ட உரையைப் பகுப்பாய்வு செய்வதன் மூலம் அல்ல, எனவே எந்தவொரு கியூ உள்ளடக்கமும் — எதிரிடையான அல்லது சாதாரணமானது, `]` ஐக் கொண்ட உடல்கள் உட்பட, எ.கா. `[inaudible]`/`[music]` — தப்பிக்க முடியாது). நிலைநிறுத்தப்பட்ட கால்-லாக் கோரிக்கை பாடியானது, ஒவ்வொரு வீடியோவிலிருந்து பெறப்பட்ட உரை பகுதியையும் அந்தத் திருத்தப்பட்ட நிழல் பிரதியுடன் உள்ளடக்க சமத்துவத்தின் மூலம் மாற்றுகிறது; `fullText` ஆங்கர் முடிக்கப்பட்ட ப்ரீ-கால் கார்ட்ரெயில் பேலோடிலிருந்து மீண்டும் படிக்கப்படுகிறது, எனவே பிந்தைய செயின் கார்ட்ரெயில்கள் (PII மற்றும் சான்றச் முகமூடிகள், முன்னுரிமைகள் 10/95) விளக்க உரையை இருக்கையிலேயே திருத்திய பிறகும், சிஸ்டம்-ப்ராம்ட்/ஹேண்ட்ஆஃப்/மெமரி இன்ஜெக்ஷன் செய்தி வரிசையை மாற்றியமைத்த பிறகும் பொருத்தம் தொடர்ந்து வெற்றிகரமாக இருக்கும். மாடலுக்கு மேலே அனுப்பப்பட்ட பாடி மாறாமல் உள்ளது. கண்காணிக்கப்பட்ட கோரிக்கை எந்தவொரு நீடித்த மெமரியையும் நிரப்புவதில்லை (கோரிக்கை மற்றும் பதில்-பெறப்பட்ட பிரித்தெடுத்தல் இரண்டும் தவிர்க்கப்படுகின்றன), எனவே மாடலின் சொந்தப் பதிலால் டிரான்ஸ்கிரிப்ட் உரையை மெமரிக்குள் எதிரொலிக்க முடியாது.

**ரா வீடியோ புலங்கள் (#12430).** பிரிட்ஜ் இயக்கப்பட்டு, நேட்டிவ் வீடியோ ஆதரவு தெரியவில்லை அல்லது இல்லாதபோது, வரையறுக்கப்பட்ட `transcript`/`audioTranscript` புலங்களும் `videoBridgeObserved`-ஐச் செயல்படுத்துகின்றன, விளக்கத் தோல்விக்குப் பிறகும் அல்லது `maxVideos` வரம்பிற்குப் பிறகும் கூட. `null` மற்றும் வெற்றுச் சரங்கள் கணக்கிடப்படுகின்றன; இல்லாத புலங்கள் மற்றும் வீடியோ அல்லாத மெட்டாடேட்டா கணக்கிடப்படாது. தக்கவைக்கப்பட்ட நகல்கள் இந்தப் புலங்களைத் திருத்துகின்றன அல்லது கோரிக்கையைத் தவிர்த்துவிடுகின்றன, மேலும் கேச்/மெமரி புறக்கணிக்கப்படுகின்றன.

அந்த ஃபால்பேக் பாதைகளில், செல்லுபடியாகும் அழைப்பாளர் கியூக்கள் தரமற்ற வழங்குநர் புலங்களைக் காட்டிலும் ஆதரிக்கப்படும் `text`/`input_text` பகுதிகளாக மாறுகின்றன. கோரிக்கையால் வழங்கப்பட்ட இரண்டு டிராக்களும் நம்பத்தகாத `client` அவதானிப்புகளாகவே இருக்கின்றன, வீடியோ விவரிக்கப்படவில்லை மற்றும் மீடியாவுக்கு எதிராக டைம்ஸ்டாம்புகள் சரிபார்க்கப்படவில்லை என்ற வெளிப்படையான எச்சரிக்கையுடன். ஏற்கனவே உள்ள 256-கியூ/64-KiB மொத்த மற்றும் ஒரு கியூவிற்கான வரவு-செலவுத் திட்டங்கள் இரண்டு டிராக்களுக்கும் சேர்த்துப் பொருந்தும்; டைம்ஸ்டாம்புகள் புரோக்கரின் 600-வினாடி உச்ச வரம்பு மற்றும் வழங்கப்பட்ட எந்தவொரு ஃபோகஸ் விண்டோவிற்கும் பொருந்துமாறு இருக்க வேண்டும். செல்லுபடியற்ற டிராக்குகள் நிராகரிக்கப்படுகின்றன, தன்னிச்சையான உரையாக முன்னோக்கி அனுப்பப்படுவதில்லை; அவற்றின் ஒருங்கிணைக்கப்பட்ட வரவு-செலவுத் திட்டம் மீறப்படாவிட்டால், செல்லுபடியாகும் மற்றொரு டிராக் இன்னும் பயன்படுத்தப்படலாம். `null`/வெற்றுப் புலங்கள் எந்த உரையையும் சேர்க்காது. இந்த ஃபால்பேக் மூலம் மீடியா ஃபெட்ச் அல்லது டிரான்ஸ்கிரிப்ஷன் எதுவும் சேர்க்கப்படவில்லை. டிரான்ஸ்கிரிப்ட் நீட்டிப்பு புலங்கள் ஃபால்பேக் வீடியோ கேரியர் மற்றும் அதன் `video_url`/`source` ஆப்ஜெக்ட்களிலிருந்து அகற்றப்படுகின்றன. OpenAI வயர் அலவ்பிஸ்ட் கறாராகவே உள்ளது; அறியப்படாத-நேட்டிவ் வீடியோ கேரியர்கள் கிடைக்கின்றன மற்றும் அறியப்பட்ட உரை-மட்டும் இலக்குகள் பாதுகாப்பான குறிப்பான்களை வைத்திருக்கின்றன. கட்டமைக்கப்பட்ட திருத்த நிழல் பிரதிகள் இணைக்கப்பட்ட டிரான்ஸ்கிரிப்ட் உரையைப் பாதுகாக்கின்றன, அதே நேரத்தில் அசல் அழைப்பாளருக்குச் சொந்தமான கோரிக்கை மாறாமல் உள்ளது. நேட்டிவ்-ஆதரிக்கப்படும் இலக்குகள் மற்றும் முடக்கப்பட்ட பிரிட்ஜ்கள் அவற்றின் ஏற்கனவே உள்ள பைபாஸ் நடத்தையைத் தக்கவைத்துக்கொள்கின்றன.

கூடுதல் தக்கவைக்கப்பட்ட நகல்கள் அதே கவனிக்கப்பட்ட-கோரிக்கை சமிக்ஞையைப் பயன்படுத்துகின்றன. ரா ப்ரீ-கார்ட்ரெயில் கிளைன்ட்-கோரிக்கை ஸ்னாப்ஷாட், இன்-மெமரி நிலுவையில் உள்ள கோரிக்கை மற்றும் முன்கூட்டியே நிராகரிக்கப்பட்ட-கோரிக்கை பதிவு ஆகியவை வீடியோ பாகங்களில் உள்ள டிரான்ஸ்கிரிப்ட் புலங்களை கட்டமைப்பு ரீதியாக மாற்றுகின்றன; பைப்லைன் நிலைகள் மற்றும் கன்டெக்ஸ்ட் ஹேண்ட்ஆஃப் மூலம் ஒருங்கிணைக்கப்பட்ட சரம் ப்ராம்ட்டுகள் நிலைநிறுத்தப்பட்ட-கோரிக்கை-பாடி சிங்கில் திருத்தப்படுகின்றன. நிலைநிறுத்தப்பட்ட `video_content_removed` குறிப்பான், வேண்டுமென்றே நிராகரிக்கப்பட்ட உரையை மீண்டும் உருவாக்குவதற்குப் பதிலாக `previous_response_id` தொடர்ச்சியைத் தோல்வியடையச் செய்கிறது. கண்காணிக்கப்பட்ட கோரிக்கையானது லாக்கிங் செய்வதற்கு முன் அதன் ஒரு பகுதி திருத்த நிழல் பிரதியை இழந்தாலோ, அல்லது பிந்தைய கோரிக்கை மாற்றங்களுக்குப் பிறகு பல வீடியோ நிழல்களில் ஒன்று கூட பொருந்தாமல் போனாலோ, பகுதியளவு திருத்தப்பட்ட டிரான்ஸ்கிரிப்ட்டைத் தக்கவைத்துக்கொள்வதற்குப் பதிலாக தக்கவைக்கப்பட்ட கோரிக்கை பாடி முழுமையாக தவிர்க்கப்படுகிறது.

கண்காணிக்கப்பட்ட கோரிக்கைக்கு, மாடல் பதிலானது கட்டமைக்கப்பட்ட கியூ எல்லை இல்லாமல் டிரான்ஸ்கிரிப்ட்டின் எந்தப் பகுதியையும் மேற்கோள் காட்டலாம். எனவே அதன் நிலைநிறுத்தப்பட்ட கால்-லாக் `responseBody` ஒரு விடுபட்ட குறிப்பானால் மாற்றப்படுகிறது; விரிவான பைப்லைன் ஆர்டிஃபேக்ட் (இது அப்ஸ்ட்ரீம்/கிளைன்ட் பாடிக்கள் மற்றும் ஸ்ட்ரீம் சன்க்களை உள்ளடக்கியிருக்கலாம்) தக்கவைக்கப்படாது. செமண்டிக், ஐடெம்பொட்டென்சி மற்றும் ரீசனிங்-ரீப்ளே கேச்சுகள் அந்த கோரிக்கைக்கான வாசிப்புகள் மற்றும் எழுத்துக்களைத் தவிர்க்கின்றன. வழங்குநர் கோரிக்கை மற்றும் கிளைன்ட்-புலப்படும் பதில் ஆகியவை மாறாமல் இருக்கும். விரிவான ஆர்டிஃபேக்ட் தவிர்க்கப்படும்போது ஆரம்ப கீப்அலைவ் பைட்டுகள் தற்காலிக பஃபரிலிருந்து வடிகட்டப்படுகின்றன. Kiro-வின் தவறான EventStream எச்சரிக்கையானது பேலோட் பைட் எண்ணிக்கையை மட்டுமே புகாரளிக்கிறது, அதன் உள்ளடக்கங்களെയோ அல்லது JSON பார்சரின் ரா பிழையையோ எப்போதுமே தெரிவிக்காது. தொடர்புடைய தகுதியற்ற ஒவ்வொரு வழங்குநர்/பிளக்கின் கண்டறிதலும் தணிக்கை செய்யப்பட்டுள்ளது என்று இது கூறவில்லை; பரந்த தக்கவைக்கப்பட்ட-சினிங் ஸ்வீப் #11658 இல் கண்காணிக்கப்படுகிறது.

உள்ளமை `/api/modality-bridge/video/drilldown` லைஃப்செயில் என்பது ஒரு தனித்துவமான, லூப்பேக்/டோக்கன்-அங்கீகரிக்கப்பட்ட கேச் சப்ஸ்ட்ரேட் ஆகும். ஒவ்வொரு செயல்பாட்டிற்கும் ஒரு கனோனிகல் ஒளிபுகா பிரின்சிபல் ஐடியும் தேவைப்படுகிறது. ஒரு உற்பத்தி அழைப்பாளர் இயக்கப்படுவதற்கு முன்பு, அது அங்கீகரிக்கப்பட்ட டெனன்டிலிருந்து அந்த ஐடியைப் பெற வேண்டும் மற்றும் கிளைன்ட்-தேர்ந்தெடுக்கப்பட்ட மதிப்பை ஒருபோதும் முன்னோக்கி அனுப்பக்கூடாது. கேச் விசைகள் அந்த பிரின்சிபாலை கனோனிகல் செஷன் மற்றும் வீடியோ-குறிப்பு ஐடிகளுடன் பிணைக்கின்றன, அவற்றின் SHA-256-பெறப்பட்ட விசைகளை மட்டுமே சேமிக்கின்றன, மேலும் வாசிப்புகள் மற்றும் நீக்குதல் இரண்டையும் அதே பிரின்சிபாலுக்கு வரம்புக்குட்படுத்துகின்றன. கேச் ஒரு உள்ளீட்டிற்கு அதிகபட்சமாக 16 பெறப்பட்ட JPEG பிரேம்களைச் சேமிக்கிறது, பத்து நிமிடங்களுக்குப் பிறகு அவற்றை காலாவதியாக்குகிறது, மேலும் வரம்பிற்குட்பட்ட `start`/`end` வாசிப்புகள் அல்லது வெளிப்படையான செஷன் நீக்கத்தை ஆதரிக்கிறது.

ஒவ்வொரு பிரின்சிபலும் 16 உள்ளீடுகள் மற்றும் 64 MiB கனோனிகல் JPEG தரவுகளுக்கு மட்டுமே வரம்பிடப்பட்டுள்ளது. அந்த வரம்புகள் உலகளாவிய 64-உள்ளீடு/256 MiB உச்ச வரம்பிலிருந்து சுயாதீனமானவை: பிரின்சிபல் கோட்டா அழுத்தம் உலகளாவிய LRU வெளியேற்றம் பரிசீலிக்கப்படுவதற்கு முன்பு அந்த பிரின்சிபலின் குறைந்தபட்சம்-சமீபத்தில்-பயன்படுத்தப்பட்ட உள்ளீடுகளை மட்டுமே வெளியேற்றுகிறது. கேச் செயல்பாட்டின் போது காலாவதியான உள்ளீடுகள் பிரின்சிபல் மற்றும் குளோபல் கணக்கியல் இரண்டிலிருந்தும் துடைக்கப்படுகின்றன, அதே நேரத்தில் ரத்துசெய்தல் மற்றும் சரிபார்ப்புத் தோல்வி ஆகியவை பகுதியளவு மாற்றீட்டை உறுதிப்படுத்தாது.

நியமமற்ற (non-canonical) Base64, அதிகப்படியான பேடிங், JPEG அல்லாத ஊடகங்கள், முறையற்ற அல்லது துண்டிக்கப்பட்ட JPEG-கள், மற்றும் வரையறுக்கப்பட்ட முழுப் பட `sharp` டிகோடிங்கின் போது எச்சரிக்கையை உருவாக்கும் JPEG-களை கேச் நிராகரிக்கிறது. ஏற்றுக்கொள்ளப்பட்ட ஒவ்வொரு படத்தையும் நியமமான (canonical) JPEG-ஆக அது மறு-என்கோடு செய்கிறது, அழைப்பாளர் புலங்களை நம்புவதற்குப் பதிலாக டிகோட் செய்யப்பட்ட பைட்டுகளிலிருந்து அகலம் மற்றும் உயரத்தைப் பெறுகிறது, மேலும் தொடர்ச்சியான பாலிவிகிள்ட் பைட்டுகளைத் தக்கவைத்துக்கொள்வதை விட அவற்றை நிராகரிக்கிறது. வரம்பிற்குட்பட்ட நியம சுருக்கப்பட்ட பஃபர் மட்டுமே இரண்டு கோட்டாக்களுக்கும் வசூலிக்கப்படுகிறது. 32 MiB டிகோட் செய்யப்பட்ட-உள்ளீட்டு வரம்பிற்கான Base64 மேல்நிலையை JSON வயர் வரம்பு கொண்டுள்ளது. சேமிக்கப்பட்ட ஒவ்வொரு வழித்தோன்றலும் அதன் சரிபார்க்கப்பட்ட JPEG வடிவம்/தெளிவுத்திறன், மாதிரி எடுக்கும் கொள்கை, வழித்தோன்றல் பதிப்பு, உருவாக்கப்பட்ட நேரம், சேவையகத்தால் கணக்கிடப்பட்ட உள்ளடக்க ஹாஷ், மற்றும் ஹேஷ் செய்யப்பட்ட பெற்றோர் குறிப்புடன் நம்பகமான அழைப்பாளரின் பெற்றோர்-உள்ளடக்க ஹாஷைப் பதிவு செய்கிறது. அணுக்க கேச் சமர்ப்பிப்புக்கு முன்பு ஒத்திசைவற்ற டிகோட்/ஹாஷ் நிலைகளுக்கு இடையில் ரத்துசெய்தல் சரிபார்க்கப்படுகிறது.

இந்தப் பகுதி இன்னும் உற்பத்தி தயாரிப்பாளரை ரூட்டுடன் இணைக்கவில்லை மற்றும் பல-தெளிவுத்திறன் மாறுபாடு தேர்வை வழங்கவில்லை. இதனால் வெளிப்படையான வீடியோ பிரிட்ஜ் (Video Bridge) கோரிக்கை பாதை கூடுதல் வேலையை ஏற்படுத்தாது, அதே நேரத்தில் வாடகைப்பத்-சார்ந்த பிரதான வழித்தோன்றல் மற்றும் முழு FU-08 பல-தெளிவுத்திறன் வாழ்க்கை சுழற்சி ஆகியவை முழுமையான நடத்தையாக ஆவணப்படுத்தப்படுவதற்குப் பதிலாக வெளிப்படையான பின்தொடர்தல் வேலையாகவே இருக்கும்.

கட்டமைக்கப்பட்ட வீடியோ மாதிரியைப் பயன்படுத்தி பிரேம்களுக்கு வரிசையாக தலைப்புகள் இடப்படுகின்றன. காலியான வீடியோ மேலெழுதல் விஷன் அமைப்பைப் பெறுகிறது; இரண்டும் காலியாக இருந்தால், விஷன் ஆட்டோ-ரூட்டர் பயனுள்ள விஷன்-திறன் கொண்ட மாதிரியைத் தேர்ந்தெடுக்கிறது. வெற்றிகரமான தலைப்புகள் அசல் பகுதியை ஒரு நிலையான `[Video description:` முன்னொட்டுடன் மாற்றுகின்றன, இது உரையை நம்பத்தகாத ஊடக-பெறப்பட்ட அவதானிப்பு எனக் குறிக்கிறது மற்றும் மீடியாவில் காணப்படும் வழிமுறைகளைப் பின்பற்றுமாறு கீழ்நிலை மாதிரிகளுக்குக் கூறுகிறது. பிரேம்-தலைப்பு கேச் விசைகளில் JPEG பைட்டுகள், ப்ராம்ப்ட், நேர முத்திரை மற்றும் பயனுள்ள மாதிரி ஆகியவை அடங்கும்; வெற்றிகரமான தலைப்புகள் மட்டுமே கேச் செய்யப்படுகின்றன. கேச் உள்ளீடுகள் ஃபால்பேக் மாதிரி உட்பட உண்மையான வெற்றிகரமான தயாரிப்பாளர் மாதிரியைத் தக்கவைத்துக்கொள்கின்றன; வெவ்வேறு பிரேம்கள் வெவ்வேறு மாதிரிகளால் உருவாக்கப்படும் போது பிரிட்ஜ் `mixed` எனத் தெரிவிக்கிறது. கேச் ஹிட் என்பது கோரப்பட்ட ரூட்டிங் திட்டமாக மறுபெயரிடுவதற்குப் பதிலாக அந்தத் தயாரிப்பாளர் அடையாளத்தை மீண்டும் பயன்படுத்துகிறது. முழு-வீடியோ முடிவு கேச், வெளியீட்டை மாற்றும் ஒவ்வொரு உள்ளீட்டிலும் விசையிடப்பட்டுள்ளது — ப்ராம்ப்ட், பயனுள்ள மாதிரி, மாதிரி எடுக்கும் கொள்கை, பிரேம் எண்ணிக்கை, சொற்பொருள் பகுப்பாய்வு முறை, இயல்பாக்கப்பட்ட ஃபோகஸ் குறிப்பின் SHA-256 கைரேகை, ஃபோகஸ் விண்டோ, `transcript`, `audioTranscript`, மற்றும் தொடர்புத் தாள் கொடி — எனவே அந்த பரிமாணங்களில் எதை மாற்றினாலும் அது கேச் மிஸ் ஆகும், ஒருபோதும் பழமையான மறுபயன்பாடாக இருக்காது. காட்சி டெடப் கொள்கை பதிப்பு, வரம்பு மற்றும் வரம்பிற்குட்பட்ட வேட்பாளர்-பிரேம் எண்ணிக்கை ஆகியவை முடிவு-கேச் விசை மற்றும் மெட்டாடேட்டாவில் வெளிப்படையாக உள்ளன; எனவே கொள்கை மாற்றம் பழமையான முழு-வீடியோ விளக்கத்தை மீண்டும் பயன்படுத்த முடியாது. முடிவு-கேச் v4 மெட்டாடேட்டா பயன்முறை மற்றும் கைரேகையை வைத்திருக்கிறது, மூல பயனர் பணியை ஒருபோதும் வைக்காது. காவல்துறை மெட்டாடேட்டா கோரப்பட்ட மற்றும் பயனுள்ள பகுப்பாய்வு முறைகள் இரண்டையும் புகாரளிக்கிறது; பயன்படுத்தக்கூடிய பயனர் உரை இல்லாத கோரப்பட்ட `focused` முறை திறம்பட `full` எனப் புகாரளிக்கப்படுகிறது.

காவல்துறை ஆதரிக்கப்படும் ஒவ்வொரு வீடியோ பகுதியையும் வெளியேற்றுகிறது, ஆனால் `modalityBridgeVideoMaxVideos`-க்கு மேல் விவரிக்கவில்லை. `supportsVideo === false` என நிரூபிக்கப்பட்ட இலக்கிற்கு, தோல்வியடைந்த மற்றும் அதிக வரம்பு கொண்ட வீடியோக்கள் வெளிப்படையான பாதுகாப்பான உரை குறிப்பான்களாக மாறும், இதனால் மூல வீடியோ எதுவும் எஞ்சியிருக்காது. திறன் அறியப்படாதபோது, அந்தப் பகுதிகள் அவற்றின் வீடியோ கேரியரைத் தக்கவைத்துக்கொள்கின்றன; எந்தவொரு ஃபால்பேக் டிரான்ஸ்கிரிப்ட்டும் மேலே உள்ள வரம்பிற்குட்பட்ட உரை மாற்றத்தைப் பின்பற்றும். `supportsVideo === true` கொண்ட இலக்குகள் பிரிட்ஜைத் தவிர்க்கின்றன. கிளையன்ட் கோரிக்கை ரத்து சமிக்ஞை பதிவிறக்கம், ப்ரோக்கர் வரிசை, துணை செயல்முறைகள் மற்றும் தலைப்பு அழைப்புகள் வழியாகப் பரவுகிறது; ரத்துசெய்தல்கள் வீடியோக்களுக்கு இடையில் நின்றுவிடும் மற்றும் மூல ஊடகத்திற்கு எப்போதுமே திறந்த நிலையில் தோல்வியடையாது.

| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` பொதுவான தலைப்புகளைப் பாதுகாக்கிறது; `focused` வரம்பிற்குட்பட்ட, நம்பத்தகாத சமீபத்திய-பயனர் சூழலைப் பயன்படுத்துகிறது |
| `modalityBridgeVideoModel`          | `""`        | விஷன் பிரிட்ஜ் மாதிரியைப் பெறுகிறது                                                                                        |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                                       |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, அல்லது விகிதாசார `segment_aware`; கண்டறிதல் தோல்வியுற்றால் `uniform`-க்குத் திரும்பும்           |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                                        |

120 விநாடிகளுக்கு மேல் உள்ள பழைய நிலைப்படுத்தப்பட்ட வீடியோ டைம்அவுட் மதிப்புகள் ப்ரோக்கர் காலக்கெடுவிற்கு மாற்றப்படுகின்றன; அந்த வரம்பிற்கு மேல் புதிய அமைப்புகளின் எழுத்துகள் நிராகரிக்கப்படுகின்றன. `GET /api/modality-bridge/video/runtime`-க்கு அங்கீகாரம் அல்லது இயக்க நேர ஆய்வு செய்வதற்கு முன் நம்பகமான ஸ்டாம்ப் செய்யப்பட்ட லூப்ேக் இருப்பிடம் தேவைப்படுகிறது, பின்னர் மேலாண்மை அங்கீகாரம் தேவைப்படுகிறது. இது `available`, சுத்திகரிக்கப்பட்ட FFmpeg/ffprobe பதிப்புகள் மற்றும் இயக்க நேரம் கிடைக்காதபோது ஒரு நிலையான காரணத்தை மட்டுமே வழங்கும். உள் பிரித்தெடுத்தல் இறுதிப் புள்ளி பொது பதிவேற்ற API அல்ல: வரிசை செறிவூட்டல் `503`-ஐயும் `Retry-After`-ஐயும் வழங்கும், அழைப்பாளர் துண்டிப்பு `499`-ஐ வழங்கும், மற்றும் நிலையான ப்ரோக்கர் காலக்கெடு `504`-ஐ வழங்கும். மாற்றப்பட்ட பதில்கள் விஷன் அல்லது ஆடியோ பிரிவுகளை அகற்றாமல் மத்திய `x-omniroute-modality-bridge` தலைப்பில் `video->text;model=<visionModel>;parts=<videos>` ஐச் சேர்க்கின்றன.

### PII Masker (`piiMasker.ts`)

**இரண்டு** நிலைகளிலும் இயங்குகிறது.

- **`preCall`** என்பது பேலோடை (payload) நகலெடுக்கிறது, `system`, `messages`, `input`, மற்றும் `prompt` (வெறும் சரம் உருப்படிகள் உட்பட) ஆகியவற்றை ஆராய்கிறது, மேலும் சரம் `content`/`text` புலங்களுக்கு `processPII()`-ஐ (`@/shared/utils/inputSanitizer`-லிருந்து)ப் பயன்படுத்துகிறது. `PII_REDACTION_ENABLED=true` ஆக இருக்கும்போது, கண்டறியப்பட்ட PII வெளிச்செல்லும் பேலோடில் திருத்தப்படுகிறது (redact செய்யப்படுகிறது). இது `INPUT_SANITIZER_MODE`-இலிருந்து (இது பிராம்ட்-இன்ஜெக்ஷன் கொள்கையை மட்டுமே கட்டுப்படுத்துகிறது) தனித்து இயங்குகிறது. திருத்தம் (redaction) முடக்கப்பட்டிருக்கும் போது, இந்த அழைப்பு உள்ளடக்கத்தை மாற்றாமல் கண்டறிதல் எண்ணிக்கைகளைப் பதிவு செய்கிறது.
- **`postCall`** என்பது பதிலை ஆழமாக நகலெடுக்கிறது (`deep-clones`), `sanitizePIIResponse()` மற்றும் Responses-API-வடிவ மாஸ்கர் (`maskResponsesOutput` — இது `output_text` மற்றும் `output[].content[].text` ஆகியவற்றை உள்ளடக்கியது) ஆகியவற்றை இயக்குகிறது. ஏதேனும் திருத்தம் நிகழ்ந்தால், மாற்றியமைக்கப்பட்ட பதில் அசல் பதிலுக்கு மாற்றாக அமையும்.

காவல் அரண் (guardrail) எதையும் தடை செய்யாது; இது குறிப்புகளை மட்டுமே அளிக்கும் (`meta.detections`, `meta.redacted`) அல்லது மீண்டும் எழுதும்.

#### வகை வாரியான தேர்வு, தனிப்பயன் வடிவங்கள் மற்றும் கண்டறிதல் கவுண்டர்கள்

**Dashboard → Settings → Security → PII masking** என்பது _எது_ மறைக்கப்பட வேண்டும் என்பதைத் தேர்ந்தெடுக்கிறது. இது மறைத்தலை ஆன் செய்யாது: அது இன்னும் `PII_REDACTION_ENABLED` (கோரிக்கை) மற்றும் `PII_RESPONSE_SANITIZATION` (பதில் + SSE) மூலமாகவே உள்ளது, இவை இரண்டும் இயல்பாகவே முடக்கப்பட்டிருக்கும்.

- **வகை வாரியான தேர்வு (Per-type selection)** — உள்ளமைக்கப்பட்ட ஐடிக்கள் `src/shared/constants/piiTypes.ts` (`PII_BUILTIN_TYPES`) கோப்பில் பட்டியலிடப்பட்டுள்ளன. அமைக்கப்படாவிட்டால் அனைத்து வகைகளும் என்று பொருள்படும் (இந்த அமைப்பு வருவதற்கு முந்தைய நடத்தை). கோரிக்கை இயந்திரத்தின் `ssn_us` வடிவம் `ssn` உடன் ஒப்பிடப்படுகிறது. டெம்ப்ளேட்டுகள் (Minimal, Standard, Financial, Brazilian, USA, Full) UI-ல் உள்ள செக்பாக்ஸ்களை மட்டுமே நிரப்புகின்றன.
- **தனிப்பயன் வடிவங்கள் (Custom patterns)** — 20 ரெஜெக்ஸ் அல்லது வைல்ட்கார்ட் வடிவங்கள் வரை (`*` = 64 வெவெளியிடப்படாத எழுத்துகள் வரை, `?` = ஒன்று). பொருத்தமானவை `[CUSTOM_REDACTED]` ஆக மாறும். ஒவ்வொரு வடிவமும் `compilePiiCustomPattern()` (`src/shared/utils/piiCustomPatterns.ts`) வழியாகச் செல்கிறது: அதிகபட்சம் 500 எழுத்துகள், `g i m s u` க்கு மட்டுப்படுத்தப்பட்ட கொடிகள் (flags), கம்பைல் ஆக வேண்டும், `safe-regex` (பேரழிவுப் பின்னடைவு) தேர்வில் வெற்றி பெற வேண்டும், மேலும் வெற்றுச் சரம் அல்லது திருத்த இடதாரியுடன் பொருந்தக்கூடாது. தோல்வியடையும் வடிவம் சேமிக்கப்படும்போதும் சோதிக்கப்படும்போதும் நிராகரிக்கப்படும், மேலும் தோல்வியடையும் சேமிக்கப்பட்ட வரி இயக்க நேரத்தில் கம்பைல் செய்யப்படுவதற்குப் பதிலாகத் தவிர்க்கப்படும். மறைத்தல் இயக்கத்தில் இருக்கும்போது மட்டுமே தனிப்பயன் வடிவங்கள் இயங்கும்.
- **கண்டறிதல் கவுண்டர்கள் (Detection counters)** — வகை வாரியான எண்ணிக்கைகள் (பொருத்தப்பட்ட மதிப்புகள் அல்ல), நினைவகத்தில் வைக்கப்பட்டு மறுதொடக்கம் செய்யும்போது மீட்டமைக்கப்படும் (`src/lib/pii/piiDetectionStats.ts`). மறைத்தல் இயக்கத்தில் இருக்கும்போது மட்டுமே இவை அதிகரிக்கும்.

அமைப்புகள் `key_value` அட்டவணையில் (`pii_settings` நேம்ஸ்பேஸ், `src/lib/db/piiSettings.ts`) சேமிக்கப்பட்டு 1 விநாடி தற்காலிக நினைவகம் மூலம் படிக்கப்படுகின்றன. API:

| Method | Path                     | Purpose                                                                                       |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------- |
| `GET`  | `/api/settings/pii`      | கொடி நிலை, `enabledTypes`, `customPatterns`, கண்டறிதல் கவுண்டர்கள்                            |
| `PUT`  | `/api/settings/pii`      | `enabledTypes` (`null` = அனைத்தும்) மற்றும்/அல்லது `customPatterns`-ஐ மாற்றவும்               |
| `POST` | `/api/settings/pii/test` | அதிகபட்சம் 8 KB மாதிரிக்காக ஒரு வடிவத்தை உலர்-ரன் (dry-run) செய்யவும்; எதுவும் சேமிக்கப்படாது |

இவை மூன்றும் மேலாண்மை அங்கீகாரம் தேவைப்படுத்துகின்றன மற்றும் Zod (`src/shared/validation/schemas/piiSettings.ts`) ஐப் பயன்படுத்தி உடலை (body) சரிபார்க்கின்றன.

### பிராம்ட் இன்ஜெக்ஷன் (`promptInjection.ts`)

பயனர் வழங்கிய உள்ளடக்கத்தில் உள்ள விரோத கட்டமைப்புகளைக் கண்டறிந்து, கட்டமைக்கப்பட்ட கொள்கையை அமல்படுத்துகிறது. இதன் செயல்பாடு சூழல் மாறிகள் மற்றும் கன்ஸ்ட்ரக்டர் விருப்பங்களால் இயக்கப்படுகிறது:

| Setting                          | Env var                                                                                               | Default | Effect                                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| இயக்கப்பட்டது (Enabled)          | `INPUT_SANITIZER_ENABLED`                                                                             | `true`  | `false` எனும்போது, காவல் அரண் குறுக்கு-சுற்று செய்யும்.                                                                                                                                                                             |
| முறை (Mode)                      | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                       | `warn`  | இன்ஜெக்ஷன் கொள்கை: `block`, `warn`, அல்லது `log`. (`redact` பின்னோக்கி-இணக்கத்தன்மைக்காக ஏற்றுக்கொள்ளப்படுகிறது ஆனால் இன்ஜெக்ஷன் உரையை **நீக்காது**; கோரிக்கை PII திருத்தம் `PII_REDACTION_ENABLED` மூலம் கட்டுப்படுத்தப்படுகிறது.) |
| தடுப்பு வரம்பு (Block threshold) | `blockThreshold` option / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`  | தடுக்கத் தேவையான குறைந்தபட்ச தீவிரம். நடுத்தரம் இயல்பாகவே கவனிப்பதற்கு மட்டுமே (observe-only).                                                                                                                                      |

**முறை முன்னுரிமை** (`getMode`): அழைப்பாளர் `options.mode` → `INJECTION_GUARD_MODE` **DB அம்ச-கொடி மேலெழுதல்** (Dashboard → Settings → Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env → `warn`. எனவே டாஷ்போர்டு மேலெழுதல் சூழல் மாறிகளை விட முன்னுரிமை பெறுகிறது, இதனால் அம்சக் கொடிகள் UI இயக்கப்படும் காவல் அரணை நேரலையாகக் கட்டுப்படுத்துகிறது (மறுதொடக்கம் தேவையில்லை). DB வாசிப்பு தோல்வி-பாதுகாப்பானது: அது பிழையை ஏற்படுத்தினால், காவல் அரண் சூழல் சார்ந்த நடத்தல்தத்திற்குக் கீழே விழும் (falls back), மேலும் மேலெழுதல் எதுவும் அமைக்கப்படாதபோது செயல்பாடு சூழல்-மட்டுமே தீர்வு முறைக்கு ஒத்ததாக இருக்கும்.

கண்டறிதல் மூலங்கள்:

1. `@/shared/utils/inputSanitizer`-லிருந்து பெறப்பட்ட `sanitizeRequest()` (பைப்லைனில் வேறு இடங்களில் பயன்படுத்தப்படும் பகிரப்பட்ட கண்டறிதல் தொகுப்பு).
2. உள்ளமைக்கப்பட்ட `DEFAULT_GUARD_PATTERNS` (தற்போது `system_override_inline` மற்றும் `markdown_system_block`, இரண்டும் `high` தீவிரம் கொண்டவை).
3. கன்ஸ்ட்ரக்டர் விருப்பங்கள் வழியாக அனுப்பப்படும் விருப்பத்தேர்வு `customPatterns` (சரங்கள், ரெஜெக்ஸ் அல்லது `{ name, pattern, severity }` பதிவுகள்).

`mode === "block"` ஆக இருக்கும்போது **மற்றும்** குறைந்தது ஒரு கண்டறிதலாவது தீவிர வரம்பை (severity threshold) பூர்த்தி செய்யும்போது, `preCall` ஆனது `{ block: true, message: "Request rejected: suspicious content detected" }` ஐத் தரும். `warn`/`log` முறைகளில், கார்ட்ரெயில் பதிவுகளை உருவாக்குகிறது ஆனால் அழைப்பை அனுமதிக்கிறது. பதிவேகம் (registry) வழியாகச் செல்லாமல் ப்ராம்ப்ட்டுகளை மதிப்பீடு செய்ய வேண்டிய அழைப்பாளர்களுக்காகப் பகிரப்பட்ட உதவியாளர் `evaluatePromptInjection()` என்பதும் ஏற்றுமதி செய்யப்படுகிறது.

**ஸ்கேன் வரம்பு (v3.8.20):** டிடெக்டர் இணைக்கப்பட்ட ப்ராம்ப்ட் உரையின் **முதல் 16 KB** ஐ மட்டுமே ஆய்வு செய்கிறது — இது `src/shared/utils/inputSanitizer.ts` இல் உள்ள `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 பைட்டுகள்) ஆகும். `detectInjection()` மற்றும் `evaluatePromptInjection()` இரண்டும் பேட்டர்ன் லூப்பை இயக்குவதற்கு முன்பு `slice(0, MAX_INJECTION_SCAN_BYTES)` ஐப் பயன்படுத்துகின்றன. ஊடுருவல் வழிகாட்டுதல்கள் (Injection directives) உள்ளீட்டின் மேல் பகுதிக்கு அருகில் இருப்பதால், இது கண்டறிதலைப் பலவீனப்படுத்தாமல் பல நூறு KB பேலோடுகளில் ரெஜெட்ஸ் CPU/GC ஐக் கட்டுப்படுத்துகிறது (ஒப்பிடுக: #3932, #4041).

### கிரெடென்ஷியல் மாஸ்கர் (`credentialMasker.ts`)

**இரண்டு** கட்டங்களிலும் இயங்கும், இயல்புநிலை சங்கிலியில் கடைசியாக (முன்னுரிமை `95`). வெளிச்செல்லும் பேலோடிலிருந்து (செய்தி உள்ளடக்கம், டூல்-கால் வாதங்கள், டூல் முடிவுகள்) **மற்றும்** வழங்குநர் பதிலிலிருந்து நன்கு அறியப்பட்ட API விசை / ரகசிய-டோக்கன் வடிவங்களை இது மறைக்கிறது (`redacts`), இதனால் ஒரு ப்ராம்ப்ட்டில் ஒட்டப்பட்ட சான்றளிப்பு (credential) (அல்லது டூல் முடிவால் மீண்டும் எதிரொலிக்கப்பட்டது) அப்ஸ்ட்ரீம் வழங்குநருக்கோ அல்லது கிளைண்டிற்கோ கசிவதில்லை.

- **ஆப்ட்-இன் மட்டும் (Opt-in only)**, PII நீக்கத்தின் அதே மரபு (Hard Rule #20-ஐ ஒட்டியது): `settings.credentialRedactionEnabled === true` **அல்லது** `CREDENTIAL_REDACTION_ENABLED=true` என இருந்தால் ஒழிய முடக்கப்படும். இது ஆஃப் செய்யப்பட்டிருக்கும்போது, கார்ட்ரெயில் ஒரு நோ-ஆப் (no-op) ஆகும் — இது எதையும் தடுப்பதில்லை மற்றும் எதையும் மீண்டும் எழுதுவதில்லை.
- `redactCredentials()` முழு பேலோட்/பதில் மரத்தையும் (`walkValue()`, புரோட்டோடைப்-பொல்யூஷன்-சேஃப், `WeakSet` வழியாக சைக்கிள்-சேஃப்) வலம் வந்து, உண்மையில் மாறிய கிளைகளை மட்டும் குளோன் செய்து, பொருத்தங்களை `[REDACTED:<type>]` பிளேஸ்ஹோல்டரைக் கொண்டு மாற்றுகிறது.
- `CREDENTIAL_PATTERNS` எல்எல்எம் வழங்குநர் விசைகள் (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), விசிஎஸ்/சாஸ் டோக்கன்கள் (GitHub, Slack, Linear, Notion, npm, Postman, Discord), கட்டண விசைகள் (Stripe, Square), கிளவுட் விசைகள் (AWS access key, Twilio, SendGrid, Mailgun), தனிப்பட்ட விசைகள் / JWTகள், சான்றளிப்பு கொண்ட இணைப்புச் சரங்கள் (`mongodb://user:pass@...`, போன்றவை), மற்றும் ஒரு பொதுவான `Authorization`/`x-api-key`/`api-key`/`apikey` தலைப்பு-மதிப்பு வடிவத்தை உள்ளடக்கியது. தலைப்பு வடிவ விசைகள் (`authorization`, `x-api-key`, `api-key`, `apikey`) பொதுவான உரை ரெஜெட்ஸ் மூலம் இல்லாமல், கட்டமைப்பு ரீதியாக மறைக்கப்படுகின்றன (மதிப்பு மட்டும், `Bearer `/`Basic ` போன்ற ஸ்கீம் முன்னொட்டு பாதுகாக்கப்படுகிறது).
- கார்ட்ரெயில் எதையும் தடுக்காது; இது மீண்டும் எழுதுவது (`modifiedPayload` / `modifiedResponse`) மற்றும் குறிப்புகளைச் சேர்ப்பது (`meta.credentialsRedacted`, `meta.count`) மட்டுமே செய்யும்.

ரிகிரஷன் கார்ட்: `tests/unit/credential-masker-guardrail.test.ts`.

## அடிப்படையான ஒப்பந்தம் (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true சங்கிலியை உடனடியாக குறுக்கிடுகிறது
  message?: string; // தடுக்கும்போது வெளிப்படும்
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // கோரிக்கையை மாற்றியமைக்க preCall ஆல் திருப்பி அனுப்பப்படுகிறது
  modifiedResponse?: TValue; // பதிலை மாற்றியமைக்க postCall ஆல் திருப்பி அனுப்பப்படுகிறது
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ஒரு கார்டுரெயில் (guardrail) `void`, `{}`, அல்லது `{ block: false }` ஆகியவற்றில் ஒன்றைத் திருப்பித் தருவதன் மூலம் "மாற்றம் இல்லை" என்பதைக் குறிக்கிறது. ஒரு `modifiedPayload`/`modifiedResponse`-ஐத் திருப்பித் தருவது, கீழ்நிலை கார்டுரெயில்களுக்காகச் சங்கிலி வழியாகப் பாயும் மதிப்பை மாற்றுகிறது. `signal?: AbortSignal` அழைப்பாளரின் வாழ்க்கைச் சுழற்சியைக் கார்டுரெயில்களுக்குக் கொண்டு செல்கிறது. கோரிக்கை இரத்துசெய்தல் என்பது வேண்டுமென்றே செய்யப்படும் தோல்வி-திறந்த (fail-open) விதிவிலக்காகும்: ஆதரிக்காது என அறியப்பட்ட இலக்குக்கு மூல ஊடகத்தை (raw media) மீட்டெடுக்காமல் ஊடகப் பாலங்கள் வேலையை நிறுத்திவிட்டு சுத்தம் செய்யும்.

## பதிவகம் (`registry.ts`)

ஒற்றைநிலை (singleton) `guardrailRegistry` பின்வருவனவற்றை வெளிப்படுத்துகிறது:

- `register(guardrail)` — ஒரு கார்டுரெயிலைச் சேர்க்கிறது (அல்லது இயல்பாக்கப்பட்ட பெயரால் மாற்றுகிறது) மற்றும் ஏறுவரிசை `priority` அடிப்படையில் மீண்டும் வரிசைப்படுத்துகிறது.
- `clear()` / `list()` — நிர்வாக உதவிகள்.
- `runPreCallHooks(payload, context)` — செயலில் உள்ள கார்டுரெயில்கள் மீது ஊடுருவுகிறது, `modifiedPayload` மூலம் பேலோடைச் செலுத்துகிறது, மற்றும் முதல் `block: true` வந்ததும் நிறுத்துகிறது.
- `runPostCallHooks(response, context)` — பதில் பக்கத்தில் இதே போன்ற ஓட்டம்.
- `resetGuardrailsForTests({ registerDefaults })` — நிலையை அழிக்கிறது மற்றும் சுத்தமான சோதனை தனிமைப்படுத்தலுக்காக விருப்பமாக இயல்புநிலைகளை மீண்டும் பதிவு செய்கிறது.

இரண்டு ரன்னர்களும் `{ blocked, payload|response, results, guardrail?, message? }` என்பதைத் திருப்பித் தருகின்றன, இங்கு `results` என்பது ஒவ்வொரு கார்டுரெயிலுக்கான `blocked`, `skipped`, `modified`, `error`, மற்றும் `meta` புலங்களை உள்ளடக்கிய `GuardrailExecutionResult` பதிவுகளின் வரிசையாகும், இது டிரேசிங்கிற்குப் பயனுள்ளதாக இருக்கும்.

### ஒவ்வொரு கோரிக்கைக்கும் கார்டுரெயில்களை முடக்குதல்

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` தற்போதைய கோரிக்கைக்குத் தவிர்க்கப்பட வேண்டிய கார்டுரெயில் பெயர்களின் நகல்-நீக்கப்பட்ட பட்டியலைத் தொகுக்கிறது. ஐந்து சேனல்கள் உள்ளன, இந்த வரிசையில் படிக்கப்பட்டு ஒரே பட்டியலாக இணைக்கப்படுகின்றன (நகல் நீக்கும்போது முதல் நிகழ்வு வெல்கிறது):

1. `apiKeyInfo.disabledGuardrails`
2. கோரிக்கை உடல் `disabledGuardrails` (மேல் மட்டம்)
3. கோரிக்கை உடல் `metadata.disabledGuardrails` (`metadata` ஒரு பொருளாக இருக்கும்போது மட்டும்)
4. தலைப்பு `x-omniroute-disabled-guardrails`
5. மரபுவழித் தலைப்பு `x-disabled-guardrails`

ஐந்து சேனல்களும் இணைக்கப்பட்டுள்ளன, இதில் இரண்டு தலைப்புகளும் அடங்கும்: `x-omniroute-disabled-guardrails` மற்றும் `x-disabled-guardrails` இரண்டையும் அனுப்புவது அவற்றின் பட்டியல்களின் கூட்டணியைத் தவிர்க்கிறது, மேலும் வெற்று நவீன தலைப்பு இனி மரபுவழித் தலைப்பை மறைக்காது ([#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412), [#16805](https://github.com/diegosouzapw/OmniRoute/pull/16805) இல் சரிசெய்யப்பட்டது).

மதிப்புகள் சரம் வரிசைகளாக அல்லது காற்புள்ளியால் பிரிக்கப்பட்ட சரமாக இருக்கலாம்; பெயர்கள் டிரிம் செய்யப்பட்டு, சிறிய எழுத்து கெபாப்-கேஸுக்கு (`pii_masker` → `pii-masker`) இயல்பாக்கப்படுகின்றன, மேலும் வெற்று உள்ளீடுகள் கைவிடப்படுகின்றன. இதன் முடிவு `context.disabledGuardrails` வழியாகப் பதிவகத்திற்கு அனுப்பப்படுகிறது, இது பொருந்தும் கார்டுரெயில்களைத் தவிர்க்கிறது (`results`-ல் `skipped: true`).

இந்த முடக்கல் பட்டியல் **பதிவகத்தை** மட்டுமே பாதிக்கிறது. ப்ராம்ட்-இன்ஜெக்ஷன் `block` முறை ஒரு கட்டாய எல்லையாகும்: இன்ஜெக்ஷன்-கார்ட் மிடில்வேர் (`src/middleware/promptInjectionGuard.ts`) அழைப்பாளர்-கட்டுப்படுத்தப்பட்ட முடக்கல் பட்டியல் எதுவும் இல்லாமல் `evaluatePromptInjection()` ஐ அழைக்கின்றது (இது முன்பு செய்த செயலற்ற `resolveDisabledGuardrails({ body })` அழைப்பு [#16934](https://github.com/diegosouzapw/OmniRoute/pull/16934) இல் அகற்றப்பட்டது), எனவே `prompt-injection`-ஐ முடக்கும் கோரிக்கை கூட `block` முறையில் நிராகரிக்கப்படும். இது திட்டமிட்டே செய்யப்பட்டுள்ளது. முடக்கல் சேனல்கள் அழைப்பாளரால் கட்டுப்படுத்தப்படுகின்றன (கோரிக்கை உடல், மெட்டாடேட்டா, தலைப்புகள்), மேலும் ஆபரேட்டர் அமைத்த பாதுகாப்புக் கட்டுப்பாட்டை அழைப்பாளர் அணைக்க முடியாது ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). [#16412](https://github.com/diegosouzapw/OmniRoute/issues/16412) இலிருந்து பெறப்பட்ட தலைப்பு ஒன்றியம், எந்தப் பதிவக கார்டுரெயில்கள் தவிர்க்கப்படுகின்றன என்பதை மட்டுமே மாற்றுகிறது; இது ஒரு கிளையன்ட் மிடில்வேரைத் தவிர்க்க அனுமதிக்காது. கட்டாய திறவுகோல் மற்றும் குழு வாரியான கார்டுரெயில் கொள்கைகள் v4 RFC [#16417](https://github.com/diegosouzapw/OmniRoute/issues/16417) இல் கண்காணிக்கப்படுகின்றன. [Coverage and limits](#coverage-and-limits) ஐப் பார்க்கவும்.

## செயல்பாட்டு வரிசை

`src/sse/handlers/chat.ts` மற்றும் `open-sse/handlers/chatCore.ts` வழியாகச் செல்லும் ஒவ்வொரு கோரிக்கைக்கும் ([அளவும் வரம்புகளும்](#coverage-and-limits) பகுதியில் பட்டியலிடப்பட்டுள்ள அரட்டை-குடும்ப வழிகள்):

1. `resolveDisabledGuardrails(...)` ஆனது ஏபிஐ விசை, பாடி மற்றும் ஹெடர்கள் ஆகியவற்றிலிருந்து தவிர்ப்புப் பட்டியலை உருவாக்குகிறது.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ஆனது பாதுகாப்பு வரம்புகளை ஏறுவரிசை முன்னுரிமையில் இயக்குகிறது:
   - முடக்கப்பட்ட பாதுகாப்பு வரம்புகள் `skipped` எனப் பதிவு செய்யப்படுகின்றன.
   - ஒவ்வொரு பாதுகாப்பு வரம்பின் `preCall` ஆனது `modifiedPayload` வழியாக பேலோடை மீண்டும் எழுதலாம்.
   - முதல் `block: true` ஆனது தொடரை குறுக்கிட்டு, ஹேண்ட்லர் பாதுகாப்பு வரம்பு நிராகரிப்புப் பதிலை வழங்கும்.
3. (மீண்டும் எழுதப்பட்டிருக்கக்கூடிய) பேலோடு காம்போ ரூட்டிங் மற்றும் அப்ஸ்ட்ரீம் டிஸ்பாட்ச் ஆகியவற்றுக்குள் பாய்கிறது.
4. **ஸ்ட்ரீமிங் அல்லாதவை மட்டும்:** பதில் தொகுக்கப்பட்ட பிறகு, `guardrailRegistry.runPostCallHooks(...)` அதே தொடரை பதிலில் இயக்குகிறது. இங்குள்ள `block: true` ஆனது அப்ஸ்ட்ரீம் பதிலை நீக்கிவிட்டு HTTP 400 ஐத் திருப்புகிறது. ஸ்ட்ரீம் செய்யப்பட்ட பதில்கள் இந்தப் படியை முழுமையாகத் தவிர்க்கின்றன.

பிழையை ஏற்படுத்தும் பாதுகாப்பு வரம்புகள் `error: <message>` எனப் பதிவு செய்யப்பட்டு `logger.warn` வழியாக பதிவு செய்யப்படுகின்றன, ஆனால் தொடர் தொடர்கிறது — வடிவமைப்பின்படி தோல்வி-திறந்த (fail-open) முறையில் இயங்குகிறது.

### மூடப்படாதவை

- **மீடியா, எம்பிக்கிங்ஸ் மற்றும் தரவு வழிகள்** (`/v1/images/*`, `/v1/embeddings`, `/v1/audio/*`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/rerank`, `/v1/search`, `/v1/moderations`) பதிவு மையத்தை எப்போதுமே அடைவதில்லை. PII மாஸ்கிங், நற்சான்றிதழ் மாஸ்கிங் அல்லது மோடாலிட்டி பிரிட்ஜ் அங்கு இயங்குவதில்லை. பழைய ஊடுருவல்-பாதுகாப்பு மிடில்வேர் மட்டுமே அவற்றின் ஒரே சோதனையாகும்.
- **ஸ்ட்ரீம் செய்யப்பட்ட பதில்களுக்கு** கால்-க்குப் பிந்தைய பாதுகாப்பு வரம்புகள் எதுவும் கிடைக்காது: கால்-க்குப் பிறகு `pii-masker` அல்லது `credential-masker` இல்லை, மேலும் கால்-க்குப் பிந்தைய பிளாக் இல்லை. ஸ்ட்ரீமிங் PII டிரான்ஸ்ஃபார்ம் மட்டுமே பொருந்தும் (`PII_RESPONSE_SANITIZATION` இயக்கத்தில் இருக்கும்போது). ஸ்ட்ரீம் செய்யப்பட்ட பதிலில் மீண்டும் எதிரொலிக்கும் நற்சான்றிதழ் மறைக்கப்படாது.
- **சேனல்களை முடக்குதல் vs. மிடில்வேர் (வடிவமைப்புப்படி):** மிடில்வேர் ஆனது அழைப்பாளர்-கட்டுப்பாட்டு முடக்கல் பட்டியலை எதையும் அனுப்பாமல், `evaluatePromptInjection()`க்கான சொந்த அழைப்பின் மூலம் ப்ராம்ட் ஊடுருவலை மதிப்பிடுகிறது. `block` பயன்முறையானது அழைப்பாளர்-கட்டுப்பாட்டு முடக்கங்களால் தவிர்க்க முடியாத ஒரு கட்டாய எல்லையாகும், அரட்டை-குடும்ப வழிகள் உட்பட ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)). `prompt-injection` ஐ முடக்குவது பதிவு மைய பாதுகாப்பு வரம்பைத் மட்டுமே தவிர்க்கும்.

### கால்-க்குப் செல்வதற்கு முன் பதிலைக் காண்பது எது

ஸ்ட்ரீமிங் அல்லாத பாதையில் வரிசை: நினைவகப் பிரித்தெடுத்தல் → உள்ளமைக்கப்பட்ட கருவி இயக்கம் → கால்-க்குப் பிந்தைய பாதுகாப்பு வரம்புகள் → கால்-க்குப் பிந்தைய பிளாக் வெளியேற்றம் → செமண்டிக்-கேச் சேமிப்பகம்.

- **நினைவகப் பிரித்தெடுத்தல்** மற்றும் **கருவி இயக்கம்** ஆகியவை, அழைப்புக்குப் பிந்தைய பாதுகாப்புக் காவல்கள் அதை மாற்றுவதற்கு அல்லது தடுப்பதற்கு முன்பே பதிலைக் காண்கின்றன. [#16401](https://github.com/diegosouzapw/OmniRoute/pull/16401) முதல், `PII_RESPONSE_SANITIZATION` இயக்கத்தில் இருக்கும்போது (ஸ்ட்ரீமிங் மற்றும் ஸ்ட்ரீமிங் அல்லாத முறைகள் இரண்டிலும்) நினைவகப் பிரித்தெடுத்தலானது பிரிக்கப்பட்ட உரையை `sanitizePII` வழியாக இயக்குகிறது, எனினும் அழைப்புக்குப் பிறகு பின்னர் தடுக்கப்படும் ஒரு பதிலும் கூட நினைவகத்திற்கும் கருவிகளுக்கும் வழங்கப்பட்டிருக்கும்.
- **Semantic cache** ஆனது அழைப்புக்குப் பிறகு பதிலைச் சேமிக்கிறது, எனவே இது மாற்றப்பட்ட பதிலைச் சேமிக்கிறது, மேலும் தடுக்கப்பட்ட பதில் எப்போதுமே கேச் செய்யப்படுவதில்லை. கேச் உள்ளீடுகள் ஒவ்வொரு API விசைக்கும் (API key) தனித்தனியாகக் குறிக்கப்படுகின்றன.

Modality Bridge பாதுகாப்புத் தடுப்புகள் சூழல் மாறிகளிலிருந்து அல்லாமல், தரவுத்தள ஆதரவு கொண்ட அமைப்புகளின் சேமிப்பகத்திலிருந்து (`getSettings()`) இயக்க நேர (runtime) உள்ளமைவைப் படிக்கின்றன. Vision-ன் முதன்மைச் சாவிகள் (primary keys) `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, மற்றும் `modalityBridgeCacheMaxEntries` ஆகும். பழைய `visionBridge*` சாவிகள் ஆவணப்படுத்தப்பட்ட ஒரு-சுழற்சி (one-cycle) வாசிப்பு ஃபால்பேக்காக மட்டுமே ஏற்றுக்கொள்ளப்படும்; டாஷ்போர்டு எழுத்துகள் (writes) முதன்மைச் சாவிகளைப் பயன்படுத்துகின்றன. இயல்புநிலைகள் மற்றும் ஃபால்பேக் ரிசால்வர் `src/shared/constants/modalityBridgeDefaults.ts`-ல் உள்ளன, அதே நேரத்தில் பழைய மாறிலிகள் `src/shared/constants/visionBridgeDefaults.ts`-ல் தக்கவைக்கப்பட்டுள்ளன.

ஆடியோவானது `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, மற்றும் `modalityBridgeAudioMaxClips` ஆகியவற்றைப் பயன்படுத்துகிறது, அதனுடன் பகிரப்பட்ட `modalityBridgeCache*` அமைப்புகளையும் பயன்படுத்துகிறது. Modality Bridge ஸ்கீமாவுடன் இந்தச் சாவிகள் அறிமுகப்படுத்தப்பட்டதால், ஆடியோவிற்கு பழைய-சாவி ஃபால்பேக் கிடையாது.

வீடியோவானது `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, மற்றும் `modalityBridgeVideoTimeout` ஆகியவற்றைப் பயன்படுத்துகிறது, அதனுடன் பகிரப்பட்ட `modalityBridgeCache*` அமைப்புகளையும் பயன்படுத்துகிறது. FFmpeg/ffprobe விருப்பத்தேர்வு சார்ந்த செயல்பாட்டுச் சார்புநிலைகளாக (operational dependencies) இருப்பதாலும், ஃபிரேம் தலைப்பிடுதல் தாமதத்தையும் மாதிரிச் செலவையும் கூட்டுவதாலும் இது இயல்பாகவே முடக்கப்பட்டுள்ளது.

## Custom Guardrails

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

படிகள்:

1. `BaseGuardrail`-ஐ நீட்டிக்கும் `src/lib/guardrails/myGuardrail.ts` கோப்பை உருவாக்கவும்.
2. `preCall` மற்றும்/அல்லது `postCall`-ஐச் செயல்படுத்தவும்.
3. இறக்குமதி செய்யும் நேரத்தில் பதிவு செய்யவும் (`registerDefaultGuardrails`-இலிருந்து புஷ் செய்யவும்) அல்லது இயக்க நேரத்தில் `guardrailRegistry.register(...)` ஐ அழைக்கவும் — ஒரே இயல்பாக்கப்பட்ட பெயரைக் கொண்ட முந்தைய கார்டிரெயிலை இந்த ரெஜிஸ்ட்ரி மாற்றிவிடும்.
4. `tests/unit/` இன் கீழ் சோதனைகளைச் சேர்க்கவும் (தற்போதைய எடுத்துக்காட்டுகள்:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## சோதனை செய்தல்

அறியப்பட்ட நிலையிலிருந்து தொடங்க சோதனைகளுக்கு இடையில் `resetGuardrailsForTests()` ஐப் பயன்படுத்தவும்.
வெற்று ரெஜிஸ்ட்ரியுடன் தொடங்கி, சோதனை செய்யப்பட வேண்டிய கார்டிரெயில்களை மட்டும் பதிவு செய்ய `{ registerDefaults: false }` ஐ அனுப்பவும். Vision Bridge சார்பு ஊசிக்கு (`dependency injection`) இடமளிக்கிறது (`deps.getSettings`, `deps.callVisionModel`); Audio Bridge ஆனது அமைப்புகள், திறன்கள், STT மாதிரித் தேர்வு, நற்சான்றிதழ் சோதனைகள் மற்றும் டிரான்ஸ்கிரிப்ஷன் ஆகியவற்றுக்கான சமமான சீம்களை வெளிப்படுத்துகிறது. எனவே சோதனைகள் தரவுத்தளம் அல்லது பிணைய அணுகல் இல்லாமல் இரண்டு ஓட்டங்களையும் செயல்படுத்த முடியும்.

## இன்ஜெக்ஷன்-கார்ட் ரூட் கவரேஜ் & ரெட்-டீம் (கட்டம் 8 · தொகுதி D)

இன்ஜெக்ஷன்-கார்ட் (`createInjectionGuard` / `withInjectionGuard`) பயனர் பிராம்ட்களை ஏற்றுக்கொள்ளும் அனைத்து ரூட்டுகளையும் உள்ளடக்கியது. இது `INJECTION_GUARD_MODE` ஐப் பின்பற்றுகிறது (இயல்புநிலை `warn` = பதிவு மட்டும்; `block` = HTTP 400 `SECURITY_001` ஐ வழங்கும்).

| வகை                     | ரூட்டுகள்                                                                                                                                            | இயல்புநிலை முறை |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| உரை (Text)              | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | `warn`          |
| உருவாக்கம் (Generative) | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | `warn`          |
| தரவு (Data)             | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | `warn`          |

உரை பிரித்தெடுத்தல் (`extractMessageContents`) ஆனது `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஆகியவற்றை உள்ளடக்கியது.

**ரெட்-டீம் (இரவுநேர சோதனை, `nightly-llm-security.yml`):** ஒவ்வொரு ரூட்டும் `INJECTION_GUARD_MODE=block` இல் OWASP-LLM கார்ப்பஸைத் தடுக்கிறதா என்பதை promptfoo உறுதிப்படுத்துகிறது; garak சோதனைகளை இயக்குகிறது (ரகசிய விசை இல்லாமல் தவிர்க்கப்படும்). நிலைத்தன்மைக்காக `moderations` சேர்க்கப்பட்டுள்ளது. பிளாக் பயன்முறை என்பது கட்டாய வரம்பாகும்: மிடில்வேர் அனுப்பும் கோரிக்கை வாரியான முடக்கல் பட்டியலை `evaluatePromptInjection()` புறக்கணிக்கிறது, எனவே `disabledGuardrails` ஆனது ஒரு ரூட்டை இதிலிருந்து விலக்கு அளிக்க **ாது** ([#16413](https://github.com/diegosouzapw/OmniRoute/issues/16413)).

இரவுநேர பணிப்பாய்வு (`.github/workflows/nightly-llm-security.yml`, cron + மேனுவல் டிஸ்பாட்ச்) இரண்டு வேலைகளைக் கொண்டுள்ளது:

- **`promptfoo-guard` (தடுக்கும் தன்மை கொண்டது)** — `INJECTION_GUARD_MODE=block` உடன் `promptfoo eval -c promptfooconfig.yaml` ஐ இயக்குகிறது. ஒவ்வொரு எதிரணி நிகழ்வும் (எ.கா. "முந்தைய அனைத்து வழிமுறைகளையும் புறக்கணி...", DAN-பாணி ஜெயில்பிரேக்குகள்) பதில் `error.code === "SECURITY_001"` ஐக் கொண்டுள்ளது என்பதை உறுதிப்படுத்துகிறது, அதாவது கார்ட் உண்மையில் கோரிக்கையை நிராகரித்துள்ளது.
- **`garak` (ஆலோசனை வழிகாட்டி)** — உள்ளூர் OmniRoute நிகழ்வுக்கு எதிராக (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` ஐ இயக்குகிறது. வழங்குநர் ரகசியத்தால் (`PROMPTFOO_PROVIDER_KEY`) கட்டுப்படுத்தப்படுகிறது; தடையின்றி தவிர்க்கப்பட்டு `|| true` பின்னொட்டுடன் இயக்கப்படுகிறது, எனவே இது CI தோல்வியடையாமல் அறிக்கையளிக்கிறது.

கார்ட் உதவியாளரின் கவரேஜ் (`createInjectionGuard` / `withInjectionGuard`) ஒவ்வொரு பிராம்ட்டைக் கொண்ட `/v1` ரூட்டையும் உள்ளடக்கியது; பிராம்ட் உரை `src/shared/utils/inputSanitizer.ts` இல் உள்ள `extractMessageContents()` மூலம் `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` இலிருந்து பெறப்படுகிறது.
